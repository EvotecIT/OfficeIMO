# Legacy Visio XML fixture evidence

`clickhouse-replication.vdx` is an unmodified drawing from the ClickHouse presentation sources, covered by their [Apache 2.0 license](LICENSE.txt). The [manifest](producer-manifest.json) pins the upstream revision and SHA-256 hash. It contains one page with 19 top-level drawing elements and nested group content. The editable model exposes 11 shapes and seven connected connectors; one connector with only one attached endpoint stays preserved in native XML with a diagnostic.

`angularjs-simple-scope.vdx` is an unmodified documentation drawing from AngularJS, covered by its [MIT license](angularjs-LICENSE.txt). The manifest pins its revision and hash. Its bitmap shape embeds a 113 × 155 pixel BMP with a zero file-size header. `VisioForeignImageRenderingTests` checks every decoded pixel, preserves the original payload after shape edits and VDX/VSDX round trips, and exercises cropping, group rotation/mirroring, master inheritance, and unsupported-object diagnostics with generated cases.

`nxbre-ie3.vsx` is an unmodified NxBRE rule-design stencil with 12 masters, including nested groups, under its [MIT license](nxbre-MIT-LICENSE.txt). `pronom-visio2002.vsx` and `pronom-visio2002.vtx` are unmodified Visio 2002 samples from the PRONOM research corpus, supplied under [CC0](pronom-NOTICE.txt). Each contains a floor-plan space master with scaled geometry, named rows, fields, and a legacy font table. The manifest pins all three sources and hashes.

`clickhouse-distributed-insert.vdx` is an unmodified Apache-2.0 drawing from the same ClickHouse presentation repository. Its two pages contain green “INSERT INTO ” runs followed by black table names, and a stored switch from Yandex Sans Text to Monaco. `nxbre-chocolatebox.vdx` is an unmodified MIT NxBRE drawing that records Visio 11.0/build 3216. Its Rules page has a connector callout alternating regular and bold Arial text around a binder name and filename. The manifest pins both sources and hashes; ClickHouse does not identify its producer in the XML.

`VisioRichTextRenderingTests` checks these color, font and emphasis runs after direct loading, XML reopening and package reopening. Generated controls check nonzero row indices, source-section edits, palette colors, transparency, decorations, superscript, shaping, font diagnostics and plain-label replacement. Rendering leaves native markers, cells and formulas unchanged; copying a page retains independent formatting rows. libvisio 0.1.11 independently confirms the producer color and emphasis changes. It uses Yandex Sans Text for both lines of the stored ClickHouse font switch, so that switch is qualified against XML and OfficeIMO SVG rather than independent rendering equivalence. Neither fixture supplies varied paragraph formatting, and this evidence does not qualify full typography or native Microsoft Visio save-back.

`VisioLegacyProducerTests` checks their master counts, page settings, catalog attributes, named rows, text whitespace, and edits through XML and Open XML round trips. Generated cases separately check changed versus untouched formulas, nested child insertion/removal, new master fonts, unused template masters, input rejection, and registered-master creation with the page's default unit. Export uses the Visio 2003 namespace for older input; it does not regenerate a Visio 2002 document.

`VisioLegacyXmlTests` imports the ClickHouse drawing, edits a shape, and checks untouched text and nested content after export. Separate generated cases exercise drawing, stencil, and template families, connectors, named ShapeSheet rows, palette colors, XML budgets, and save failure behavior.

Generated image-bearing master cases check untouched transform and Connection-row formulas while editing text and dimensions, retain implicit and explicit local pins, and remove orphaned payloads after child deletion. A controlled stencil/template built from the AngularJS bitmap passes the Microsoft schema before and after edits and package reopening; libvisio reads the edited labels and embedded image. This uses independent source content in a generated master, not an independently produced stencil or native Visio acceptance.

Independent validation during implementation used the Microsoft Visio 2003 DatadiagramML schema for generated VDX, VSX, VTX and re-exported fixture XML. libvisio 0.1.11 read all three generated families, rendered the generated VDX rectangle and text, and extracted identical text from the original fixture and its unedited re-export. These tools are validation-only and are not product dependencies. Schema validity and libvisio interoperability do not establish acceptance by native Microsoft Visio; native application acceptance remains open.

For the AngularJS bitmap, libvisio 0.1.11 and OfficeIMO produce the same image bounds after unit conversion. LibreOffice renders both exported SVGs with the embedded screenshot in that location; the OfficeIMO PNG shows the same content. This comparison qualifies the image placement, not whole-diagram fidelity: text/styles and partially attached connectors differ. The bundled LibreOffice build rejects direct VDX import, and this evidence does not establish Microsoft Visio acceptance.

The three stencil/template inputs and their edited exports pass the Microsoft Visio 2003 schema after normalization. libvisio 0.1.11 renders the 12 NxBRE masters identically before and after unedited export, and reads the changed master label after editing. The two PRONOM inputs retain their page bounds and path geometry. Their typography differs because the legacy font table now resolves to named fonts; the template also exposes unqualified inherited-style differences. LibreOffice rendering of the extracted SVGs confirms the master artwork and edited labels, but the small PRONOM stencil preview clips long labels even in the independent source rendering. This is preservation and edit evidence, not full text-layout or native Visio acceptance.

`VisioTextStylePreservationTests` checks native Character/Paragraph row identities, text markers, untouched formulas, clearing formatting, independent master instances and local-reference remapping. Repeated package round trips retain inherited labels and formatting without materializing local overrides. `VisioShapeSheetSectionPreservationTests` checks section replacement, removal and addition on shapes and connectors, plus master font overrides in all three independent stencil/template inputs. `VisioLegacyCellMetadataTests` retains all 35 NxBRE null-string markers and checks literal caches, units, standard and producer-specific errors in both accepted legacy namespaces. User, Shape Data and source-section formula edits clear obsolete errors while untouched errors remain preserved.

`VisioDuplicationFormulaTests` checks local formula references after page and selection duplication, including nested shapes, attached connectors, custom API IDs and subsequent insertion or reordering. Both XML and Open XML paths use the copied native IDs while preserving original formulas, quoted text, explicit cross-page references and targets outside the copied graph.

A controlled single-row workflow for each XML family and font edits in the three producer inputs pass 24 Microsoft schema checks across source, unedited export, edited export and package reopening. libvisio 0.1.11 reads unchanged text and observes the edited font sizes: 15 points in the selected NxBRE master and 18 points in both PRONOM masters. Stencil/template validation uses `VisioDocument::parseStencils`; the ordinary drawing command-line readers do not exercise their masters. Twelve extracted SVGs were rendered to PDF for inspection, alongside the OfficeIMO drawing PNG before and after reopening. The controlled text changes retain row indices 7 and 4 and produce red 18-point text. OfficeIMO's reopened drawing has the same painted SVG, but the independent renderer differs in font resolution and alignment. This qualifies the recorded formatting and preservation operations, not mixed-run typography, inherited-style equivalence or native Microsoft Visio acceptance.

`VisioMasterInstancesTests` creates scaled editable NxBRE instances directly from XML and after stencil-package import. It checks independent child edits, positions and zero local pins, text clearing, User cells, master links, and connected topology through VDX and VSDX. Generated cases cover nested child trees, remapped local formulas, colliding destination font IDs, and unsupported resizing without partial insertion. Text-size cases cover native inch values with and without unit metadata and authored large point sizes.

A rendered instance workflow creates all 12 NxBRE masters, with 17 immediate children and 29 master links, edits one child, moves its group, and connects two groups. The OfficeIMO SVG is identical before and after package reopening. Both XML exports pass the Microsoft schema and libvisio reads the edited text. After converting view-box units, libvisio and OfficeIMO agree on the resized rectangle coordinates. Rendered comparison still exposes differences in font alignment, inherited fills, line weights, semantic artwork, and connector display. This qualifies the recorded instance-editing and geometry contracts, not complete rendering equivalence or native Microsoft Visio behavior.

`VisioNativeCellMetadataCloningTests` checks guarded null/error metadata after master instantiation, repeated selection and page copying, edits before or after copying, external master registration and stencil import. It covers nested shapes, connectors, PageSheets, newly imported styles, stable copied formula targets and font-ID collisions. Removing the last marker from a single-shape blueprint retains adjacent native cells. Mechanical formula/font rebinding retains producer errors; caller edits invalidate obsolete metadata.

A public NxBRE workflow creates the Atom master instance, copies the selection and duplicates the page through same-document, external-registration and stencil-package routes. All 18 direct/package-reopened exports retain the exact three source markers per Atom tree, with the six style markers retained where styles are imported. The failing baseline and corrected exports pass 36 Microsoft schema checks. libvisio 0.1.11 produces identical painted SVG and extracted text for each before/after pair. Six representative populated-page SVGs were rendered to PDF and inspected. These checks qualify the recorded copying/import operations and appearance retention; invisible null semantics are verified against the source cells, and native Microsoft Visio save-back acceptance remains open.

`VisioNativeCellMetadataImportMergingTests` checks destination-cell retention and new-cell/row additions in generated and additional stylesheets, plus external transfer of additional master roots and their nested native cells. It also checks omitted deletion and header attributes against incoming attributes, with new-entry controls retaining the source values. A multi-root page-copy control retains both modeled shapes and connector state. Controlled public workflows pass 24 strict Microsoft schema checks and independent libvisio reads after direct export and package reopening; their exact cells retain the expected null conditions, formulas, units and producer errors.

`VisioNativeCellMetadataStyleIdentityTests` checks numeric stylesheet aliases in both directions and named rows at different source indices. Repeated import and package reopening retain the destination row, attributes and guarded cells, rebase newly added cell metadata, and retain new styles and rows with their source attributes.

`angularjs-concepts.vdx` is an unmodified AngularJS documentation drawing under the same [MIT license](angularjs-LICENSE.txt), pinned in the manifest. On the `runtime` page, shape `22` uses two paragraph rows: left-aligned `Event Queue`, an empty centered paragraph, and centered `(wait)`. `VisioRichTextParagraphTests` checks placement, the empty line, XML/package reopening and unchanged native cells. Generated shape/connector cases cover nonzero row indices, first-line and hanging indents, spacing, source-section edits, copies, plain-label replacement, fitting and cancellation. No varied indent/spacing producer fixture was found; those cells have constructed contract evidence.

libvisio 0.1.11 reader callbacks retain left/center/center alignment, 120% line spacing and both paragraph breaks in the AngularJS label. Its SVG writer collapses that label into spans without independent paragraph positions, so the callback evidence does not establish visual equivalence with its SVG. The source has no producer version or document-property metadata; Microsoft Visio production and native open/edit/save acceptance remain unqualified. Paragraph markers and spacing follow the [Visio paragraph-run contract](https://learn.microsoft.com/en-us/previous-versions/office/developer/office-2003/bb421669(v=office.11)) and [native line-spacing values](https://learn.microsoft.com/en-us/office/client-developer/visio/spline-cell-paragraph-section).

`shorewall-netfilter.vdx` is an unmodified documentation drawing from Shorewall, under [GFDL 1.2 or later](shorewall-GFDL-1.2.txt), with no invariant or cover sections. Its [notice](shorewall-NOTICE.txt), [original documentation declaration](shorewall-NetfilterOverview.xml) and [same-revision license](shorewall-GnuCopyright.xml) accompany the fixture. The manifest pins its revision and hash. The file records Visio version 12.0/build 6556 and Tom Eastep as its creator.

Page 0, shape 32 contains `Raw`, `Mangle` and `Nat` paragraphs with `Bullet=1`, `BulletFont=0`, `BulletFontSize=-1`, zero `TextPosAfterBullet`, and a quarter-inch hanging indent. `VisioRichTextBulletTests` checks three round markers, first-text positions, equal label/body sizes, unchanged native cells/text, and XML/Open XML reopening. Generated controls cover custom labels, font IDs, absolute and relative size overrides, wrapping, fitting, direct master labels, copies, source-section edits, plain-label replacement, shaping, font diagnostics and bounded fallback.

libvisio 0.1.11 emits three list-element callbacks with round markers at 100% size and a quarter-inch minimum label width. Its SVG omits those markers, so the callback evidence qualifies native list semantics rather than independent rendering equivalence. The fixture's Arial 8-point text is qualified by the [cached stylesheet-chain and native font-name profiles](../../../OfficeIMO.Visio/README.md#cached-text-style-inheritance). Microsoft documents the other marker kinds; its diamond icon differs from libvisio's hollow-circle mapping. Those kinds use the documented Unicode equivalents, with generated rendering checks. Exact marker glyph metrics, broader independently produced bullet styles and native Microsoft Visio open/edit/save acceptance remain unqualified.

`VisioLegacyLayerTests` compares page layer indices, source cells and shape memberships from `angularjs-concepts.vdx` and `nxbre-chocolatebox.vdx` through direct XML export and Open XML reopening. Generated controls cover sparse row indices, new-row collisions, repeated page duplication with remapped layer formulas, layer reordering, nested shape and connector membership, clearing membership, and explicit value assignments that replace formula/null/error state while retaining units. Repeated saves of the same model retain the replacement even when original membership is restored. Master PageSheets remain covered by the stencil/template preservation checks above.

`vdxtosvg-basicshapes.vdx` is Jon Breen's unmodified Visio 2002 sample from the VDXtoSVG corpus stored in GNOME Dia. The fixture-specific [MIT notice](vdxtosvg-NOTICE.txt) and manifest pin its source and hash. Its integrity declaration records Visio 10.0/build 525. Page 0, shape 13 contains hyperlink `Row_21`, numeric ID 1, the VDXtoSVG home-page address, U+E000 cached sub-address and extra information, and `Frame F="No Formula"`. `VisioLegacyHyperlinkProducerTests` checks every stored hyperlink cell and row identity through XML/Open XML reopening, page copying, an address edit and an explicit same-value frame assignment without changing the source row. Export normalizes the legacy namespace to Visio 2003 and adds default `Invisible` and `SortKey` cells; it does not reproduce the original bytes.

`VisioLegacyHyperlinkTests` checks all nine typed hyperlink values, numeric/localized identities, unchanged formulas and native cell state, same-value and changed-value assignments, repeated page copies, and imported master editing without source mutation. `VisioHyperlinkRowNameTests` covers unused default names, explicit and inherited root/child names, native null/error retention when new rows are inserted, numeric-only rows, copying and newly registered masters. `VisioHyperlinkEffectiveMasterTests` covers registered masters selected by default lookup, dynamic connector masters retained from loaded XML, page and selection copying, explicit overrides and assignment-state preservation. Drawing, stencil and template cases use controlled Visio 2002/2003 XML and repeated reopening. The independent sample supplies one named shape row; multiple-row, inherited master and dynamic-formula producer coverage and Microsoft Visio hyperlink interaction remain unqualified.

`pronom-visio2002.vtx`, page `Page-1`, shape `1`, stores local text-frame cells marked `F="Inh"`: its width and height caches are half those in master `0`. The loader retains the local caches through XML/Open XML reopening. On the independent NxBRE drawing's `Rules` page, shape `13` omits its local frame and inherits the `&` master label and frame. These inputs qualify cached frame inheritance; neither supplies rotated or asymmetric-margin 2D text evidence.

`VisioTextFramePlacementTests` covers rotated local pins, nested parent rotations, asymmetric margins, plain and rich labels, scaled master instances, authored single-shape masters, copies, reopening and render nonmutation. SVG coordinates, decoded PNG bounds and libvisio callbacks agree on the controlled frames. Failing baselines cover the eight cases, including frames smaller than the renderer fitting minimum. Independent-reader and rendered evidence qualify the recorded operations, not arbitrary text formulas or native Microsoft Visio appearance.

`VisioMasterTextStyleSerializationTests` checks styling across all 16 generated 2D master names and aliases with unnamed and named blueprints, through both master-instance APIs. Geometry and registered identities survive XML/Open XML reopening. Dynamic connector masters retain their 1D endpoints, routing cells and text-position controls while storing the requested text style. Generated controls also check the 10-point default for unassigned font size, unique text-frame cells, independent instance styles and unchanged blueprints. Default and partially specified frames retain their effective dimensions and local pins when creating resized instances before and after reopening, including labels supplied for blank blueprints. These are serialized-definition checks; native Microsoft Visio rerouting remains unqualified.

`VisioDrawingScaleRenderingTests` checks reduced, enlarged, mixed-unit and 1:1 page projection, physical fonts, margins, paragraph metrics and stroke thickness, grouped text, connector labels and collision search, stencil artwork, copying, XML/Open XML reopening, export metadata and raster budgets. A scaled crop/mirror case compares the complete rendered image against an equivalent physical-size drawing. Rendering retains the native drawing-unit values.

The PRONOM template stores 1728-by-1152 drawing-inch bounds with a 1:48 scale. libvisio reports a 36-by-24-inch page, a text-frame center at (18, 10.875) physical inches, 12-point text and physical margins of 1/18 inch. OfficeIMO exports its page at 1728 by 1152 pixels at 48 pixels per inch through direct loading and both reopening routes. Controlled page and text-frame callbacks agree with the projected SVG coordinates; generated legacy output passes the Microsoft schema. LibreOffice rendering of OfficeIMO SVG checks visible placement independently. These remain one producer's scaled input plus generated controls, not broader native application acceptance.

libvisio 0.1.11 scales the controlled files' line weights with geometry, whereas Microsoft's [drawing-scale contract](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-vsdx/1a60ffcb-969c-48f1-aa02-ff2228718043) explicitly excludes line weights from scaling. OfficeIMO retains physical line weight and does not claim agreement with that reader's stroke widths. Microsoft Visio appearance, arbitrary formulas and exact typography remain unqualified.

`VisioGeometrySectionContractTests` checks generated builtin shape/master and connector geometry, unique one-based path-row identities and section-level settings. Controlled shape cases cover `NoShow`, `NoFill` and `NoLine` through direct rendering, page copying and XML/Open XML reopening, including hidden master geometry. Curved native connector cases retain their route for label anchoring and inspection while hiding suppressed lines, arrowheads and collision obstacles. A unique outlined route stays selected when auxiliary geometry is hidden or has no outline. Older OfficeIMO geometry headers remain readable; section-level settings take precedence. Source flags, formulas and sparse row indices stay preserved.

Independent libvisio callbacks distinguish hidden, stroke-only, fill-only and fully painted controlled shapes and connectors. Generated Open XML geometry now supplies row identities, so the reader draws the builtin outlines that were absent in the failing baseline. Generated legacy copies pass the Microsoft schema. OfficeIMO SVG/PNG and independently generated SVG are rendered for visible flag and outline inspection. These controls qualify the shared serializer and preview behavior; they do not expand independent-producer coverage or establish native Microsoft Visio acceptance.

`VisioArcGeometryContractTests` checks the signed circular `ArcTo` bow for shapes and connectors, reversed and diagonal chords, minor and major sweeps, SVG/PNG previews, labels placed with `PlaceLabel`, arriving arrow direction and unchanged native geometry through reopening and page copying. Eight one-shape controls agree with libvisio 0.1.11 and Aspose.Diagram 26.9.0 evaluation rendering. The evaluation engine remains an isolated evidence tool, with its markings intact; it is not a product dependency. These controls establish bow direction, not independent-producer breadth, arbitrary stored connector text-frame placement or exact native arrow appearance. The [V2 backlog](../../../Docs/ROADMAP.md#legacy-visio-xml-depth) retains those qualifications.

`VisioArcMasterScalingTests` checks unequal positive width/height scaling through both master-instance APIs, page copying and reopening. Circular arcs become editable elliptical rows; rotated absolute and Open XML relative elliptical arcs retain their transformed curves. Controls cover signed, reversed, diagonal and major arcs, zero bow, deleted rows, formula-only coordinates, source-master preservation and atomic rejection of invalid or excessive axis profiles. Resized instances retain only formulas that reproduce the intended coordinates at their final placement, including unchanged absolute axes and normalized move, line and arc fractions. Legacy XML has no relative-row mapping; those controls qualify Open XML.

Independent public-API consumers qualify generated circular and rotated elliptical masters, including relative Open XML controls, and the NxBRE warning-sign master converted from VSX to VSSX and imported into a fresh drawing. Generated VDX output passes the Microsoft schema. libvisio 0.1.11 reports ellipse radii within 0.0001 inch of the analytic affine transform. Evaluation rendering retains endpoints within 0.00001 inch; its different cubic subdivision produces a measured maximum curve-distance difference of 0.028 inch. LibreOffice-rendered SVG comparisons show the transformed curves and warning-sign outline. This qualifies curve placement, not exact stroke, theme or text appearance.

The generated independent-render controls use consecutive native row indices. The evaluation engine leaves otherwise equivalent sparse-index master controls blank; libvisio renders them, and OfficeIMO retains their source row identities. Sparse controls have OfficeIMO and libvisio evidence rather than evaluation-render agreement. Native Microsoft Visio open/edit/save, formula-dependent edits after creation and broader independent-producer curves remain unqualified.

`VisioShapeResizeTests` checks resizing existing edited NxBRE Atom instances, nested frames, connection-point identity and attached endpoints, free endpoints and waypoints, every source-master part, inherited absolute/relative arc geometry, orthogonal child/text rotations, units and atomic rejection. `VisioForeignImageRenderingTests` checks saved image placement, unchanged payload and crop fractions, and identical pixels after explicit resizing and XML/Open XML reopening. LibreOffice-rendered SVG comparisons show the changed producer-group outlines and circular-arc geometry. libvisio retains the producer's edited 12-point label and agrees with the native image rectangle. Its SVG export uses the default raster aspect ratio, producing different cropped-image pixels; independent crop-pixel parity and exact text appearance remain unqualified. These controls do not establish native Microsoft Visio acceptance, arbitrary formula recalculation or sheared frame support.

`VisioPackageMetadataContractTests` checks generated and legacy-converted drawing, template and stencil packages for parseable XML metadata, valid page-window identities and absence of an advertised empty thumbnail. Empty property parts and numeric window types failed independent opening in the baseline; valid property roots and the documented `Drawing` window type removed those failures. This proves generated package readability for the recorded controls, not preservation of arbitrary imported package metadata or Microsoft Visio open/edit/save acceptance.

`VisioConnectorTextFrameTests` checks the NxBRE Rules-page callout's cached pin, dimensions, local pin and angle during endpoint translation, rotation and uniform scaling. It covers explicit page and path overrides, page-angle edits, copies, fitting after scaling, successful and unsuccessful overlap cleanup, and repeated VDX/VSDX reopening. `VisioRasterRotationTests` checks the painted rotation direction of plain/rich shape and connector boxes, ellipse axes, stencil artwork and package previews. The prior raster adapter inverted an already converted native angle; its failing controls paint every tested rotation in the opposite direction.

Independent libvisio controls use the unchanged NxBRE callout and direct edits to its cached native frame cells. VDX and VSDX exports agree with the reader's text origin and rotation for translation, 90-degree rotation and 1.5-times scaling with a minus-30-degree rotation. Legacy exports pass the Microsoft schema. Public consumers exercise native and API anchor edits on .NET 8 and .NET 10 through source and packed assemblies. Managed and independently rendered SVG/PDF previews show the recorded frame changes; line wrapping and typography differ, and some edited labels extend beyond the original page. These controls qualify cached placement and editing, not whole-page rendering equivalence, arbitrary ShapeSheet recalculation, reflected or sheared frames, or native Microsoft Visio acceptance.
