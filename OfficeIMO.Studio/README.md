# OfficeIMO Studio

OfficeIMO Studio is a cross-platform desktop and mobile application for OfficeIMO's document engines. The application presents the existing PDF, conversion, workflow, security, and OCR capabilities where the platform supports them; reusable document behavior remains in the owning OfficeIMO packages.

## Current workspace

- In Tools, **File origin and text integrity** assesses local files through their registered format owners. Review structural carriers, exact Unicode findings, check coverage and source hashes, then select Content Credentials, external references or AI source declarations to remove from a separate copy. The workflow rejects a changed source, respects live document ownership, blocks signed-package invalidation, re-inspects the copy, and exports the shared JSON report to a local folder. Visible watermarks and unrelated metadata remain unchanged. Provider locations and cryptographic/detection provider configuration are outside this workbench; absent providers are explicit in the result.

- Open **Tools → Invoices**, or search for **Invoices**, to inspect CII/UBL XML, validate it, convert to a supported specification, create a presentation or hybrid PDF, or replace selected source headers. The result keeps source mapping, model checks, schema checks, and business rules separate. Standards checks require an explicit release, pinned rules and Java/Saxon; requested checks must pass before output is published. Header editing retains supported source XML content and changes only supplied fields. Local outputs use numbered copies when a filename already exists. Provider inputs are supported; provider output folders require direct-write confirmation and keep a verified recovery copy if publication is uncertain. PDF options include languages, an embedded font, line-item columns, unit/payment labels, compact details, and continuation-page identity.
- Open several PDFs in document tabs and use single-page, continuous, two-page, or grid reading modes. Hidden tabs release page images and rendering caches while retaining document edits and undo history; documents displayed in independent panes keep their presentation active.
- In View, choose **Independent panes** to view the current document twice or select another open document in either pane. Each pane keeps its own page, zoom and reading layout. Click or focus a pane, or press F6, to make it the target of editing, undo and save. Two views of one document share its edits and undo history. Narrow windows show the active viewport with **Switch active pane** available; both navigation states are retained. **Close pane** returns to one viewport and keeps the document tabs open. Synchronized comparison temporarily replaces the pane display and restores it when closed.
- Opening a file through a symlink or hard link reuses its existing tab and pending edits. Conversion, document-health output, assembly, page export, Save As, extraction, splitting, and protected/decrypted copies check live tab ownership before publishing their final destination. Numbered-copy mode skips owned paths; replacement reports a failure instead of replacing an open document. Assembly adds each physical source once, and comparison rejects an alias of the current document.
- Local-file saves check that the source still has the physical identity and contents Studio opened. If another application changes, replaces, or removes it, Studio keeps the pending edits and refuses to overwrite the external version; use **Save As** to choose a different file. The shared commit path also checks the displaced source during atomic replacement. Saving a source opened through a symlink updates its target and preserves the link.
- Open and compare PDFs through desktop storage-provider streams, including sources without local paths. Available provider bookmarks are retained with recent and restart references. In a macOS sandbox, selected local files retain an app-scoped native bookmark, and read/write streams hold its resolved permission until disposal. A changed location or unavailable permission requires selecting the file again. PDF input and serialized provider output are limited to 512 MiB. A provider save checks the opened contents before writing and verifies the result after closing the write stream, but cannot guarantee atomic replacement or rollback. Studio explains this before saving and keeps edits and enabled recovery snapshots when publication fails.
- Choose comfortable or compact controls in Settings. With document history enabled, Studio remembers page, zoom, reading layout, bounded pane widths, and pane choices for up to 64 documents, using path hashes in the view-preference file.
- On macOS, Studio uses the system title bar, native File/Edit/View/Window menus, Settings with Command+comma, and a collapsible labelled sidebar. Document tabs sit below the system title bar on macOS and in the title bar on other desktop platforms; an unsaved tab shows a dot, middle-click closes a tab, and Ctrl+Shift+T (Command+Shift+T on macOS) reopens the most recently closed document. One command row holds the document task (View, Annotate, Edit, Pages, Forms, Protect), that task's tools, undo and redo, find, save a copy, save, focus reading, and the pane toggles. Page navigation and zoom float over the page, and a status line shows the position, document facts, unsaved changes, and what the active tool expects.
- Press F9 for focus reading and Escape or F9 to restore document controls. At narrow widths, bottom navigation replaces the sidebar, a document picker replaces the tab strip, and the task tools move onto their own row. Search and properties open over the page so the document retains its width. The separate iOS host uses a touch workspace over the same document state and PDF engine.
- Custom zoom stays in place through editing, undo, redo, recovery, and saving. Fit width and Fit page remain explicit choices; on wide windows Fit width stops at a comfortable reading size instead of filling the screen.
- Home leads with a drop target, quick tasks, and recent documents shown with first-page previews rendered in memory for local PDFs. Continue a previous session from the banner on Home, or review each document first. Unchanged sources reopen with their reading positions; changed or missing sources offer individual choices, including recovering verified pending edits into a new file. Recovering to a local file requires a new path; provider destinations use the explicit direct-write confirmation. Session memory can be disabled in Settings and keeps up to 32 document references locally; entries expire after 30 days of inactivity.
- If Studio cannot save or clear the restart record, a notice stays visible with a Retry action. A successful retry clears that notice without dismissing unrelated recovery errors.
- Turn off document history in Settings to stop storing new recent-file entries and reading preferences. Existing records remain until cleared. Before working with private documents, also disable restart sessions and recovery storage, and close other running Studio instances. Confirmed history cleanup removes recent files, saved reading preferences, and restart records; it preserves open documents, unsaved edits, and recovery copies. Failed or partial cleanup is reported for retry.
- Recovery restores only snapshots written within the last 30 days and verifies their contents again when applying them. Each new snapshot stores its metadata and document bytes in one atomically replaced file, preserving the previous snapshot if publication fails. Existing recovery files remain readable and migrate on the next successful edit while storage is enabled. Recovery snapshots are limited to 512 MiB; with recovery storage enabled, an edit that would exceed this limit is rejected before changing the open document.
- Turn off recovery storage in Settings before editing private documents to prevent new edit snapshots. This waits for active writes and applies to the running Studio instance and future launches; close other running instances separately. Editing, undo, redo, and saving remain available, but new unsaved edits cannot be recovered after an unexpected exit. Existing copies remain available until explicitly cleared or expired. This switch does not disable recent documents, saved reading positions, restart sessions, or the recovery copy required for a direct provider workflow write. The workflow confirmation explains that requirement before writing.
- Studio cleans recognized expired recovery data at startup and removes abandoned temporary files older than one day. Automatic cleanup retains unknown future formats and unrelated files. Settings also offers confirmed cleanup of stored recovery files and reports any files it cannot remove. Cleanup preserves original documents and open unsaved edits; subsequent edits can create new recovery files while storage is enabled.
- On Unix, newly written recovery files allow read/write access only to their owner. Rewriting an older snapshot also applies these permissions. Windows recovery files use the access controls of the local application-data location.
- Search the Tools catalog or open command search with Ctrl+K or Ctrl+Shift+P (Command on macOS), or from the title bar. On iPad and iPhone, **Find a command** in the navigation sidebar opens the same search with touch controls and room for the software keyboard; an attached keyboard can use Command+K. Command search opens inside the window, highlights matching words, lists recently run and available commands first, and keeps unavailable commands at the end with their requirement. Commands use the same operations as the workspace controls and can be selected with the keyboard.
- Drop files anywhere in the window. PDFs open in tabs, and other supported inputs join the conversion queue; in Convert, every dropped file joins the queue. An overlay explains what the drop will do before you release.
- Startup accepts every supplied document. macOS file-open activation waits for startup and processes successive batches in order: PDFs open in tabs and supported conversion files join the queue with provider access retained. Unsupported or busy intake reports an error; a later successful intake clears that rejection. Finder **Open With** is verified on the local macOS ARM64 app for a Numbers ZIP document delivered to an already-running Studio instance: it opens Convert and queues the document as Numbers → XLSX. This check does not qualify cold-start activation, other file types, or sandbox bookmark recovery.
- Results, progress, and recovery choices appear as a notice at the bottom of the workspace, above the page controls, instead of moving it. Each result names the change that finished, and after a document change the notice offers Undo on the same row. Finished background jobs announce themselves with Open and View jobs actions. Search results stay in the search pane rather than appearing as a notice.
- When an in-place save is refused because the source file changed, the error bar offers **Save a copy…** so the edits can be kept in a new file.
- Find text with Ctrl+F (Command+F on macOS), then use Enter and Shift+Enter or Next and Previous to move through individual occurrences. The result count, selected result, and page highlights identify the same match. Escape clears search and returns keyboard focus to the reader. Changing the query or editing the document clears stale results. Phrases match across line breaks and end-of-line hyphenation, and each line of a wrapped match is highlighted. Search includes existing OCR text layers. When the current page is a scanned image without text, a banner explains that search, selection, and the assistant cannot read it yet and offers **Make searchable**, which starts OCR for the document.
- Follow bookmarks and links, navigate by keyboard, use page night mode, and compare two PDFs in synchronized panes. **Find differences** lists changed page appearance, changed dimensions, and pages present in only one document. Move through the list to select the corresponding pages and show pixel differences at the reader's zoom. Both documents get a header of the same height, so their pages start level, and the properties pane closes while comparing. Enter separate page selections to review ranges of a long PDF (up to 100 selected pages per document); blank selects all pages. Selected sequences pair in order, retaining original page numbers and unmatched selected pages. This rendered comparison does not identify semantic edits or moved pages. **Export report** saves a standalone HTML gallery and summary bound to both compared snapshots. Changed sources, edits or page selections invalidate export; neither source PDF is rewritten.
- Annotate with one active tool at a time: Select (V), Note (N), Text box (T), Highlight (H), Underline (U), Strikeout (S), Squiggly (Q), and a **Shapes** menu with Rectangle (R), Ellipse (E), Line (L), Polygon (P), Ink (I), and Stamp. Selection handles, hover outlines, and drawing previews use the Studio accent colour. Pick markup colors from swatches or enter a hex value. Selecting text while reading offers Copy, Highlight, Underline, and Strikeout next to the selection; right-click a page to copy, select all text, mark up the selection, or add a note at that point.
- Select existing text, images, and annotations with visible bounds and handles. Replace, move, resize, recolor, flatten, or remove supported objects through the canonical PDF editors.
- Click a word in Edit mode to type on the page. Choose a replacement font, size, and overflow policy, then compare the original and prepared result before applying. The review magnifies the selected area and can show the full page. Find-and-replace lists individual occurrences to include or exclude; selecting one reveals its page highlight. Draft changes invalidate the preview, and applying the reviewed result creates one undoable edit. New text uses a standard PDF font; substitution warnings identify fidelity limits.
- Drag a selected image or annotation to move it, or drag its handles to resize it. Images retain their proportions and rotation; alignment guides show nearby edges and centers. Image edits rewrite the placement above existing content by default, with an explicit background option; original paint order cannot be retained.
- In **Annotate**, Shift-click to add or remove annotations, or drag an empty area to select several. **Group** saves a standard PDF markup group; selecting one member selects the group after reopening. **Ungroup** separates its members. Move, duplicate, delete, raise, and lower the selected annotations together as one undoable edit. Groups stay on one page, preserve separate comment replies, and exclude links, redaction marks, and replies. Resize individual annotations; free-text callout transforms remain unsupported. Use arrows to browse annotations, Space to select, Shift+Space to toggle a group, and Ctrl+arrows to move (Ctrl+Shift+arrows moves ten points). Ctrl+A selects page annotations, Ctrl+G groups, Ctrl+Shift+G ungroups, Ctrl+D duplicates, Ctrl+] raises, Ctrl+[ lowers, and Delete removes the selection.
- Review comment threads in Comment mode, filter by author or completion state, and jump to the next unresolved thread. **Export summary** saves every thread as Markdown, grouped by page with its status and replies. Selecting a thread reveals its page annotation. Reply, resolve, or reopen through undoable PDF edits; saved replies and review states remain standard PDF metadata. Reply drafts stay with their thread during annotation edits, page reordering, undo, and redo, and survive cancelled operations. If an edit removes the original comment or cannot report its identity, the draft remains available to copy or restore to a chosen thread. Drafts are kept for the current session. Accepted, rejected, and other existing review states remain visible until explicitly changed.
- Add text, images, links to web addresses or to pages of the same document, notes, markup, shapes, ink, stamps, signature appearances, watermarks, and page numbers. The watermark preview updates as its settings change.
- Add headers and footers from the Edit properties pane: text for the left, centre, and right of each, with `{page}`, `{pages}`, `{date}`, `{file}`, and `{title}` placeholders, a font size, a starting number, and an optional page range.
- Insert or replace PNG and JPEG images through the file picker's stream access, including sources without a local path. Each selected image is limited to 64 MiB; access is released after reading, and failed reads preserve the current document.
- In Pages, the page grid fills the workspace. Organize pages by drag and drop; select pages with Ctrl or Shift and use the floating action bar to rotate, move, duplicate, extract, or delete them. Crop, resize to a paper size (fit, fill, or stretch the content), import, split, and insert blank pages from the command row and properties pane, with undo, redo, save, and recovery support. Deleting pages takes effect immediately and can be undone until you save. PDF imports accept provider streams and apply the selected batch as one undoable change, with a 512 MiB total input limit.
- Extract pages from the current document, including unsaved edits, after reviewing the output order. Ranges can reorder or repeat pages, up to 100,000 selected pages. Extraction saves a separate PDF, checks destination ownership again before publication, and leaves the reading position and undo history intact. The result opens the saved PDF or its local folder; Jobs retains verified recovery copies for interrupted provider writes.
- Split the current document, including unsaved edits, after reviewing each part's filename and source page range. Split every few pages or start a new file at each top-level bookmark, named after the bookmark. Local parts are saved together in a new `Split PDFs` folder, using a numbered folder if the name is occupied. Provider folders require replacement consent and retain verified parts if a later write fails. The result dialog opens individual PDFs; Jobs keeps the output and any recovery records. Splitting leaves the source and its pending edits intact.
- Review PDF imports before changing the document: choose each source's page ranges, omit sources, arrange their order, and choose the insertion page. Imports use the captured copies shown in the review, accept PDF passwords through the existing password prompt, and remain one undoable change. A batch accepts up to 1,000 PDFs, 512 MiB of input, and 100,000 selected pages. The reader stays on the same original page after insertion, and Jobs records the import attempt.
- Fill, flatten, and author supported AcroForm controls. In **Forms**, text, check boxes, drop-downs, radio groups, and list boxes are editable on the page. Repeated copies of a field share one draft, and drafts stay visible as you move between fields. Tab and Shift+Tab follow field order; arrow keys move between radio choices on the current page. Multi-select lists toggle each selection without requiring a modifier key. Radio widgets with ambiguous appearance states remain in the inspector. Import and export form data as XFDF from the Forms menu. Drafts are applied when you save.
- In **Forms**, choose **Recognize form values** to read visible text inside existing fields with the configured OCR engine and languages. Review the captured field region or full page, correct the proposal, and accept each value explicitly. A correction clears its acceptance. Read-only fields, unsupported script rules, invalid lengths, comb values and choices remain blocked; supported numeric rules use the [bounded review policy](../OfficeIMO.Pdf.Ocr/README.md#review-values-for-existing-form-fields). Resolve manual drafts before recognition or applying proposals. **Apply accepted values** creates one undoable edit; save or save a copy separately. Changed documents require a fresh recognition review.
- **Fill and sign** from the Forms command row: type, draw, or pick an image of your signature or initials, optionally keep them for next time on this computer, and place them with one click or by dragging a box. **Date** places today's date. Where a PDF only accepts annotations, as many forms do, drawn signatures are placed as ink and typed signatures and dates as text; picture signatures need a PDF that allows page content. These are visual signatures; use Protect for certificate signatures.
- Review password-protected and unencrypted copies before saving. Studio captures the current document and chosen protection settings, shows permission and destination consequences, and records verified output or interrupted provider-write recovery in Jobs. Open the result or reveal its local folder from the result dialog. PDFs with content-copy restrictions can be viewed with the document-open password; text search follows extraction permissions, while text selection and object inspection require content-copy permission or owner access.
- Review a certificate-signed copy with the selected certificate, captured document edits, and an appearance preview. Signing runs only after approval and preserves the open document. Apply or discard pending form edits before reviewing a signed, protected, extracted, or split copy; retained or conflicting drafts also need resolution. The result separates signature-math and digest checks from certificate-chain, revocation, and timestamp evidence, with output and recovery actions in Jobs. **Certify this document** makes the signature a certification signature and records which later changes (none, form filling, or form filling and comments) keep it valid; certification is available only on an unsigned document. The PDF engine currently rejects adding another signature to an already-signed document.
- Collect redaction marks across pages by drawing areas or searching for literal text and regular expressions. Search marks the complete matching line; review the highlighted area, include or exclude individual marks, and add reasons before applying. Changing the selection or sanitization choice requires another review. Editing the document clears stale marks.

The report contains fingerprints, page numbers, and counts; it excludes matched text, search terms, reasons, and file paths. Export refuses a saved PDF that has changed since verification. Documents blocked by active-content policy may require a sanitized copy before redaction planning.

The document-health workbench accepts provider-backed PDFs for inspection, repair planning, comparison, optimization, repair, and sanitization. Conversion, page-image export, and assembly accept provider-backed files through bounded private staging, retain their original references, and check provider contents again before publication. Assembly also accepts provider ZIPs. Print preview reads a provider once and uses the same bounded document snapshot for its plan and page images. Each job chooses automatic, editable, or embedded-preview representation. Partial editable recovery and incomplete preview coverage require explicit acceptance; Numbers worksheet-name normalization is a separate choice. - In the conversion queue, **Run pending** processes new entries and **Retry failed / cancelled** retries only those outcomes, using the current output settings. Completed entries keep their files and diagnostics. Aliases of a file are queued once per conversion route, while distinct files on case-sensitive volumes remain separate. If a runner stops without returning a result, **Check output** requires inspecting the destination before removing and re-adding that entry; it is excluded from automatic retries. To intentionally repeat a completed conversion, remove its queue entry and add the source again.
- Open **Jobs** to follow conversion, document-health, assembly, page-export, and searchable-PDF attempts across document tabs. These workflows share two execution slots; conversion files run sequentially within their batch. Cancel a waiting or running attempt from its card, or cancel its conversion batch. Completed PDF outputs open in Studio; other files and folders use the system association. The history holds up to 500 attempts, retaining active entries and recovery records while discarding the oldest other finished entries when full. **Clear finished** removes records without deleting output files or recovery copies. Cards show the output file name with its full location in a tooltip, a **Show in folder** action for local outputs, and a progress bar coloured by outcome. Ordinary history is kept for the current session. Workflow recovery records return after restarting Studio, but execution never resumes automatically. Open a verified recovery PDF and use Save As to keep it; other recovery formats use the system association. When an attempt has multiple copies, select the copy to open or discard. Discarding requires confirmation for that selected copy. These copies do not expire automatically and are separate from edit snapshots in Settings. Their store admits at most 100 records and defaults to a 1 GiB limit; a full store prevents further provider workflow writes until copies are discarded.
- Create searchable PDFs through `OfficeIMO.Workflows` and `OfficeIMO.Pdf.Ocr`. Choose pages and recognition languages, then use **Recognize and review** in the header to inspect word bounds, confidence, language, diagnostics, and native-text overlaps. Exclude individual eligible words or whole pages; selections survive page changes. Enlarge a selected word to inspect its source region. **Create searchable PDF** commits the reviewed selection; cancellation leaves the destination unchanged. Confidence and rendering controls sit under advanced settings. The workbench supports 28 typed language choices, checksum-verified language-data provisioning, and provider-backed inputs. Choose output selects a local file or provider destination; provider writes require confirmation and retain a verified recovery copy if publication is uncertain. The runner rechecks source contents and open-document ownership after review before publishing the validated PDF.
- In **OCR → Images and multiple files**, add PDFs or raster images and choose an output folder. The queue shows proposed filenames before recognition and adds numeric suffixes when selected files share a name. PDFs produce searchable copies; images produce UTF-8 text files whose text can be corrected alongside the source preview. Enlarge an image or select another image/page when the source container provides several. Review each file before saving. Completed outputs are available immediately in Jobs and from **Open output** in the session. Recognition uses one engine sequentially within the session and shares the application's workflow execution budget.
- Closing a tab or Studio while work is active offers **Wait and close**, **Cancel work and close**, and **Keep open**. Waiting or cancelling keeps the affected document alive until operations finish; cancelling one tab leaves other tabs' jobs running. Whole-window close also waits for session restoration. Cancelling restoration retains unopened entries for a later restart choice. Already saved outputs are preserved, and unsaved-edit choices follow once active work has stopped. An unexpected process exit does not resume workflow execution.

## Book publishing

Choose **Publish book** to create a reflowable book or open a DOCX, Markdown, HTML,
EPUB or `.oibook` project. The workspace edits title, language, creator, cover and
project CSS. The Chapters tab preserves drafts while changing selection and supports
insertion, removal, reordering, titles and XHTML body editing. Applying an invalid
draft retains the last validated book. One package edit can be undone or redone
within the current session.

The Preview tab renders the selected chapter through the existing EPUB image owner.
Reader applications can reflow it differently. Import review lists conversion losses;
acknowledge non-fatal findings only after inspecting them. Missing dependencies or
other failed imports require source repair and re-import. EPUB export runs the native
writer's validation and cannot bypass failed import findings.

**Save project** retains the EPUB and review state together in `.oibook`.
**Export EPUB** writes a separate reader-facing publication. Both routes verify their
stored output and protect opened sources, changed project files, recovery paths and
other open documents. Cancellation and publication failures retain the current book.
Local manuscript assets stay within the source's physical parent; provider imports
need embedded resources when their provider does not expose an authorized asset base.

The source editor is XHTML, and this workspace targets reflowable books. Fixed-page
layout, media-overlay timing, scripting, DRM rewriting, automatic accessibility
certification and crash recovery of unsaved book drafts remain outside its contract.

## Document assistant

Open **Assistant** to ask read-only questions about the current PDF. Choose **Connections and model** to open guided setup, choose a provider, connect, and select an available model. Choose **Use this connection** to return to the document. Starter prompts help you summarize, find action items, or review key facts; you can edit the question before sending it. The assistant uses the current workspace bytes, including applied unsaved edits. Apply form drafts before asking; PDFs that prohibit content extraction are unavailable to the assistant.

| Connection | Setup |
| --- | --- |
| ChatGPT | Sign in with your ChatGPT account, or explicitly choose **Use existing Codex login**. The native IX Codex transport needs no agent CLI. |
| OpenAI-compatible API | Enter an HTTPS API base URL and your API key, then refresh the model list. |
| GitHub Copilot | Supply a Copilot-authorized GitHub token, or enter your registered GitHub app client ID and use browser device sign-in. |
| LM Studio | Load a text model in LM Studio, start its local server, then connect. The preset uses `http://localhost:1234/v1/`. |
| Ollama | Start Ollama and download a text model, then connect. The preset uses `http://localhost:11434/v1/`. |
| Other local server | Set a loopback OpenAI-compatible endpoint under **Advanced connection options** and select a model. All local presets disable hosted fallback, redirects, and proxy use. |

Hosted connections require the document-text consent checkbox before each connection's questions are enabled. Model discovery and sign-in do not send document evidence. Supplied API keys and GitHub tokens remain in memory for the Studio session. Native login credentials use separate Studio-owned IX stores; the existing Codex login is read only when explicitly selected and its authentication file is not overwritten. When several accounts are saved, select the account to use. **Use this connection** saves the provider, model, base URL, and any GitHub application ID in Studio preferences. A new session restores those choices and requires a connection check; it does not restore API keys or document consent.

Choose the whole document or the current page, then **Prepare evidence**. Current-page mode extracts only the selected page and keeps its original page number for citations; the input-byte limit still applies to the full PDF. Preparation runs locally and reports the number of pages, text items, characters and pages without extractable text. Studio reuses that immutable snapshot for repeated questions until the source or page scope changes. Hiding the assistant releases the prepared evidence. Switching tabs also closes the inactive assistant; reopen it to prepare evidence for that tab again.

For scanned pages, choose **Review with OCR**. Save pending changes first. Studio checks that the saved file still matches the prepared source, opens the OCR workspace, and creates a separate searchable PDF after you review the recognized words. **Open output** returns to the assistant with evidence prepared from that output. Protected PDFs require a separately authorized unprotected copy for this OCR route.

Answers show checked source references and exact quotes; select a page reference to navigate to it. **Copy answer** and **Export answer** include the question, answer, source quotes, source and evidence hashes, provider/model identity, omissions and review limitations. Export creates a plain-text answer artifact. A quote match proves that the text occurs in the source, so review the interpretation yourself. The status shows incomplete or unsupported answers and omitted evidence. The assistant uses text evidence and bounded questions; cross-batch reasoning is limited by the [shared engine contract](../Docs/officeimo.document-assistant-design.md).

Connection failures provide the next action when the provider exposes a typed authentication, access, model, usage, availability or timeout error. Reconnect after updating a credential or endpoint. Studio does not retry a rejected request automatically or display raw provider error payloads. SDK failures without a public error category show a general recovery message.

Conversations remain in memory and include at most three prior exchanges as bounded context. Changing the document, page scope, model or connection clears the conversation. Closing a tab, hiding the assistant, switching tabs or cancelling discards pending answers. Cancellation stops waiting for a provider and rejects late results; stopping the provider's own computation depends on its cancellation support. The panel docks beside the document in wide windows and opens as a drawer at narrower widths. Questions and answer exports leave the source PDF unchanged.

## Runtime requirements

Studio performs its supported document conversions in process through OfficeIMO's
format and rendering engines. Installing an external office suite or document
converter is unnecessary. The packaged desktop editions include the .NET runtime.
OCR is a separate, optional Tesseract operation. Printer queue delivery uses the
platform printer service; preparing and saving print sheets works independently.
The Mac App Store edition provides print-PDF preparation and blocks external OCR
and printer command-line execution.

## Capability ownership

Studio does not contain a second document engine:

- `OfficeIMO.Pdf` owns PDF reading, rendering, interaction geometry, editing, forms, security, signatures, redaction, and output mutation.
- `OfficeIMO.Workflows` owns reusable conversion, inspection, repair, optimization, comparison, sanitization, image-export, print-planning, and mixed-source assembly workflows.
- `OfficeIMO.Epub` owns manuscript packaging and native EPUB validation; `OfficeIMO.Word.Html` and `OfficeIMO.Markdown` own their source projections. `OfficeIMO.Workflows.BookProject` owns book edits, project persistence and review state. Studio supplies editor state and permission-aware storage.
- `OfficeIMO.Pdf.Ocr` owns searchable text generation. `OfficeIMO.Workflows` owns source snapshots, output validation, publication, and ordered OCR sessions; Studio configures the optional Tesseract CLI provider. `OfficeIMO.Reader.Image` identifies image sources, and `OfficeIMO.Reader.Ocr` owns their recognition and normalized-document enrichment.
- Avalonia owns only the cross-platform windowing and control layer. Studio uses OfficeIMO's retained page scene with the canonical raster renderer for content that the Avalonia adapter cannot preserve, including transformed text and embedded-font metrics. Restricted viewing also uses the raster path. Studio does not use PDFium.

In the single-PDF OCR workspace, **Scan preparation** previews the source and prepared page before recognition. Draw one region for the selected page, adjust perspective corners, or enable cleanup for straightening, black and white levels, gamma, and color mode. Arrow keys move the focused region; Shift+arrow keys resize it. In corner mode, keys 1–4 select a corner clockwise from top left and arrow keys move it. Changed settings invalidate the reviewed preview. OCR uses the prepared pixels and maps recognized text back to the original visible PDF. **Save reviewed page as raster PDF** instead exports a separate pixel-only copy and omits native text and interactive content. The source digest is checked before saving.

For quick extraction, choose **Recognize text to copy**, review the selected page or region, exclude unwanted words, and choose **Use selected text**. The result remains selectable in the workspace; **Copy reviewed text** sends it to the clipboard without choosing an output file or creating a PDF. Confidence and native-text overlap rules still apply.

Tesseract is an explicit OCR runtime prerequisite. OfficeIMO discovers an installed executable and can provision checksum-pinned language data, but the application does not silently install or bundle a native OCR executable. Scan preparation and raster-copy export do not require it.

Use **Settings → Text recognition setup** to check the installed engine and its recognition languages. **Choose Tesseract executable** selects a local installation; **Check and save** verifies it before storing the choice. Searchable PDFs, scan-text extraction and multi-file OCR use that saved choice. **Use automatic discovery** returns to environment, PATH and known-installation discovery after a successful check. If no engine is found, Settings shows platform installation instructions; install it and check again. A failed check preserves the previous saved configuration. Recognition-language downloads remain a separate choice in each OCR workflow.

## Language, accessibility, and local data

Studio stores versioned user preferences under the operating system's local application-data directory. English, Polish, German and French are available in the language settings picker. English is the fallback interface language. Additional culture names are reserved for future reviewed packs. The `en-XA` expansion locale exposes clipped controls, hard-coded strings and layouts that cannot accommodate longer translations.

User-facing XAML, dialogs, file pickers, and capability notices resolve stable, feature-scoped resource keys through `IStudioLocalizer`. Document engines remain culture-neutral. A new translation adds satellite resources and a reviewed catalog entry rather than branching view models or document operations by language.

Studio follows Avalonia's platform font selection and fallback instead of forcing a Windows-only typeface. System, light, dark, and explicit high-contrast appearance preferences share the same semantic color resources. Navigation and editing controls expose automation names, icon-only controls include help text, normal tab order follows the visual flow, and the shell supports the primary platform modifier for Open, Find, tab switching, tab closing, zoom, and fit commands. Page navigation also supports arrows, Page Up/Down, Home, and End.

Open documents appear as tabs with a separate close action and an unsaved-changes indicator. Use Left/Right or Home/End while a tab has keyboard focus, or Control+Tab and Control+Shift+Tab to switch from elsewhere in the window. The **Open documents** menu beside the tab strip lists every open document, including those outside the visible strip. On macOS, the native **Window** menu also lists open documents and marks the selected one; Command+Shift+[ and Command+Shift+] switch tabs. Windows supports Ctrl+F4 to close the active document and Ctrl+Y to redo a document edit. Drag a tab within the strip to reorder it, or use Alt+Shift+Left/Right while it has keyboard focus. The document menu and each tab’s context menu also offer Move Tab Left/Right and Close; the document menu includes Reopen Closed Tab. Narrow windows use a document picker with a direct close button. Reordering retains the live document and its edits. Closing a focused tab moves keyboard focus to the next selected tab.

Crash diagnostics stay local, bounded, and privacy-safe. They record stable event codes, runtime metadata, exception type/HResult, and sanitized stack frames. They do not record document contents, document names, document paths, or exception messages.

## Host boundary

Studio's reusable document behavior stays in OfficeIMO packages, while presentation preferences, localization, accessibility, and transport-neutral activation belong to the Studio host layer. A future browser companion should send a bounded activation request through an authenticated local native host and let Studio open the document or workflow. It should not duplicate PDF editing, OCR, conversion, storage, or policy logic in an extension.

## Run and verify

Set `OFFICEIMO_STUDIO_DATA_ROOT` to an explicit directory when running an isolated Studio profile, for example during UI validation. This redirects preferences, recovery, diagnostics and Studio authentication stores together.

```powershell
dotnet run --project OfficeIMO.Studio/OfficeIMO.Studio.csproj
dotnet test OfficeIMO.Studio.Tests/OfficeIMO.Studio.Tests.csproj -c Release
```

The document workspace currently opens PDF files directly. Other supported formats enter through conversion or mixed-source assembly.

Native selected-file acceptance on macOS 27.0.1 ARM64 uses an isolated, ad-hoc-signed sandbox build with user-selected read/write and app-scoped bookmark entitlements. It covers opening and rendering a PDF, reopening after a cold restart without a picker, Save As with exact source bytes, editing and saving through restored permission, and reopening the saved annotation. Cancelling Save As creates no output. Moving the source makes the old reference unavailable; selecting its new location restores access. Managed tests cover cancellation and stream disposal. This evidence does not qualify distribution signing, App Store acceptance, directory packages, other storage providers, revoked grants, or interruption during native I/O.

For printing, choose pages, paper, orientation, 1/2/4/6/9 pages per sheet, and 150 or 300 DPI, then build the sheet preview. **Page subset** keeps odd or even source-page numbers from your selection in the selected order. Scaling offers fit, actual size, fill, or a custom percentage of the original physical page size; custom and fill overflow is cropped to each slot. Choose one of nine alignment positions and expand **Margins** to set each edge in points (72 points = 1 inch). **Grayscale** changes the reviewed and delivered sheet pixels; **Color** retains source colors, with final output determined by the printer.

The preview includes unsaved workspace edits; apply pending form values first. Changing page, layout, resolution, or color settings clears the preview so you review the new sheets before sending them. Select an installed printer with **Find printers**, choose copies, duplex, and an available paper source, and send the reviewed sheets. **Printer default** retains the queue's configured source. Changing the printer resets the source selection and loads that queue's choices. Windows uses the installed GDI printer driver; macOS and Linux require CUPS command-line tools. Windows file printers require a new local output filename.

Printing sends the managed renderer's reviewed pixels, including its reported rendering limitations. PDF print permissions apply, and restricted low-quality printing is limited to 150 DPI. Requested layout margins do not remove the printer's hardware margins: paper edges can still be clipped. A queue receipt confirms acceptance, not physical completion. If submission is interrupted after it begins, Jobs shows **Check output**; inspect the queue before retrying. Driver-specific color settings, broader capability browsing, and physical-printer acceptance remain in the roadmap.

## iPhone and iPad development host

`OfficeIMO.Studio.iOS` hosts the shared Avalonia application. Its navigation provides **Home**, **Documents**, **Tools**, **Convert**, **Jobs**, and **Settings**. The sidebar stays beside the workspace on wide iPads and opens from the navigation button at compact widths. Tool discovery, conversion routes, job results, preferences and document commands use the same models and engines as the desktop app.

Each PDF opens in a document tab with its own reading position, zoom, edits, and undo history. **Open documents** lists all open PDFs, including tabs outside the visible strip. On short landscape screens, tap the document title to switch or close documents. Files imports create a separate local working copy. **Save** updates the active copy; **Save As** asks for a filename and a Files folder without creating an empty output before review. **Share** saves edits and opens the Apple share sheet. Provider writes are verified after saving, but cannot promise atomic replacement or rollback. Closing a modified tab offers Save, Discard, or Cancel; a cancelled close or failed save keeps the document open.

Choose a document task to annotate, edit, organize pages, fill forms, or protect a copy. The shared forms inspector has previous/next arrows and a field-position indicator. Moving between fields shows the corresponding page and retains unapplied entries; Save applies those entries through the same validation as desktop. Move, split, extraction, import, watermark, protection and signature reviews use shared content presented in an application sheet. These commands retain the desktop engine's document capability checks: for example, page-tree rewrites on PDFs with unsupported form structures remain blocked. Conversion accepts multiple Files inputs and exposes progress, results and recovery in **Jobs**. At compact widths, conversion separates setup, queue and details into tabs. Settings cards stack vertically, and document inspectors open one panel at a time.

Studio restores open tabs and their recoverable edits after restart. Working-copy identities remain relative to the app document root so a changed container location does not invalidate them; selected provider copies retain access references. Internal preferences and recovery files live in Application Support. Password-protected documents prompt again when reopened.

Search supports previous and next matches, Enter and Shift+Enter navigation, and Escape to clear highlights and return to the reader. A hardware keyboard also supports Command+O, Command+S, Command+W, Command+F, Command+Z and Command+Shift+Z. Use Control+Tab to switch documents and Command+Shift+T to reopen a closed document.

Wide reading layouts show page thumbnails beside the document and grouped review tools above it. Compact layouts move review tools to the bottom and open thumbnails in a Pages sheet. Pinch to zoom around the point between your fingers; **Fit** returns the whole page to view. Tap the page counter to enter a page number, then choose **Go** or press Enter. The chooser stays above the software keyboard and leaves the reading position unchanged when cancelled. Desktop readers keep an inline page-number field; invalid numbers remain available for correction. Notes and document reviews also account for the software keyboard. Choose **Try a sample** to open a three-page introduction.

**File origin and text integrity** imports an app-owned working copy, then uses the desktop local-file engine. Copies and JSON reports remain on the device; open their entries in **Jobs** to share or save them to Files. The imported source remains unchanged.

External-process OCR, Java-based invoice standards validation, desktop printer queues and checkpointed folder PDF export are unavailable on iOS, with explanations in their respective screens. Multi-file conversion uses **Add files** and **Run pending**. Use **Share** for the system's available sharing and printing actions. Scan preparation, invoice XML/model validation, and in-process document conversion remain separate from those external-tool limits.
