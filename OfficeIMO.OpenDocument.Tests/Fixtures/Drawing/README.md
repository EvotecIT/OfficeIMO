# Draw fixture evidence

The upstream FODG and ODG inputs come from LibreOffice's Draw test corpus. The [manifest](producer-manifest.json) pins their source revisions and SHA-256 hashes. Those fixtures retain the upstream [MPL 2.0 license](LICENSE.txt).

`libreoffice-graphic-text-defaults.source.fodg` is the standard-only OfficeIMO-authored all-defaults case of a six-case comparison. Its eight fixed frames cover graphic, paragraph and text defaults, direct graphic formatting, common graphic parent inheritance, shape-bound and explicit paragraph styles, relative inline sizing and bold-only formatting. `libreoffice-graphic-text-defaults.fodg` is the unmodified LibreOfficeDev 26.8.0.0.alpha0 resave. Both use the repository's MIT license and are separate from independently authored inputs. Raw authored ODG/FODG parts pass ODF 1.4 schemas; the native file contains producer extensions. Native ODG/FODG resaves retain the same native PDF row font sizes and colors. The shared projection preserves the saved bindings, including native changes from 150% of 22pt to 22pt and from a shape-bound 20pt paragraph to 18pt. Window foregrounds and several default/direct-style bindings differ from native paint and remain unqualified. Regression tests protect the original cascade, materialized native bindings, window-color loss reporting and OfficeIMO package/flat preservation; they do not assert native appearance equivalence.

Controlled window-color variants also exercise the numeric `0` and `1` aliases. OfficeIMO tolerates and preserves these input tokens; the strict ODF boolean datatype accepts `false` and `true`. Their preserved numeric declarations remain schema-negative and are not used as standards-conformant authoring evidence. LibreOffice opacity/theme extensions are retained separately; checking their standard ODF portions does not establish strict validity of the unchanged extension-bearing files.

`libreoffice-tab-stops.fodg` is unmodified native output from LibreOfficeDev 26.8.0.0.alpha0 exporting an OfficeIMO-authored tab probe. Its eight rectangles cover left, center, right and comma stops, an absent delimiter, leading/consecutive/default tabs, mixed font sizes and a left margin. The test retains those declarations and body text through projection and package save/reopen. This is native export and round-trip evidence, separate from the independently authored upstream corpus. The authored probe and native fixture use the repository's MIT license. The sample's shared PDF horizontal field starts agree with native output within 0.2 points; vertical font placement differs.

`libreoffice-aligned-tabs.fodg` is an unmodified LibreOfficeDev 26.8.0.0.alpha0 resave of a controlled matrix derived from the earlier OfficeIMO-authored probes. Its 26 tabbed rectangles use full-width justified text areas and cover left, center, right and justified paragraphs, all four tab types, default and multiple stops, margins, first-line indents and start/end aliases. The test verifies paragraph/tab alignment, positive first-line indentation and source-preserving conversion. Centered/right hanging indents and non-left list bodies have separate unsupported-profile regressions. Fitting explicit field starts agree with shared PDF within 0.03 points; default-grid starts differ by up to 0.6 points. Additional controls cover hard breaks, wrapping and text-box frames with full-width justified areas. These MIT-licensed controls are native interoperability evidence, separate from the independently authored upstream corpus. Exact font placement, default grids and wrapped prefixes remain unqualified.

`libreoffice-tab-leaders.fodg` is an unmodified native export of a related typed authoring probe with dot, hyphen and underscore leaders, including consecutive stops and styled following fields. Projection and ODG/FODG reopen retain its leader bindings and logical tabs. Authored ODG and FODG have equal native PDF text and field bounds; the six compared horizontal field starts agree with shared PDF within 0.2 points. Glyph phase and vertical typography differ. This is controlled authoring and native export evidence, not an independently authored corpus. Native output contains producer extensions outside the strict ODF 1.4 schema and automatic-color opacity declarations outside the qualified projection; those limits remain separate from textual leader evidence. The fixture uses the MIT license.

`libreoffice-list-alignment.fodp` retains unmodified bytes from LibreOffice's Impress corpus. `OpenDocumentOdgListLabelTests` adapts only its presentation envelope to drawing in memory, then checks the shared native list content: four styled bullets, legacy label spacing, percentage sizing and explicit RTL loss reporting. This is independent list-content evidence, not an unmodified ODG producer fixture or full presentation-layout qualification.

`OpenDocumentOdgTests` exercises plain text editing while retaining custom enhanced geometry, and opaque StarView image preview preservation across flat XML. `OpenDocumentOdgDiagramTests` also reads and edits saved-view visibility and locking in the independent layer fixture. These are independent-producer inputs, separate from OfficeIMO-generated round trips.

`libreoffice-transparent-text.fodg` qualifies explicit red body text at `25%` opacity. Controls change only its inline percentage to `0%`, `25%`, `50%` and `100%`. Logical text and declarations survive OfficeIMO ODG/FODG saves and native ODG resaves; the native exporter omits fully transparent paint and extracted text. Native SVG uses alpha 64/255 at 25% and 127/255 at 50%; native PDF uses 0.26 and 0.5 respectively. Shared rendering uses byte-rounded alpha, so exact cross-renderer pixels and typography remain unqualified. The fixture's literal enhanced rectangle also projects; body-alpha evidence remains separate from complete shape and text-layout qualification. Alias/inheritance, malformed declarations and the opaque fallback for unqualified label/automatic-color opacity have managed regressions; these do not establish broader native list-label inheritance.

Fresh rectangle, line and connector controls cover the same four percentages, including the legacy import alias on connector text. Public ODG and FODG output has equal native SVG text/alpha and PDF text/alpha; native ODG resaves retain logical text even at zero opacity. These are controlled authoring examples, separate from the upstream fixture. Native baseline placement differs from shared rendering; the evidence qualifies the foreground opacity rather than exact caption appearance.

`OpenDocumentOdgGeometryTests` reads the six-page `libreoffice-sheared-geometry.odg` fixture: rectangles, polygons, and Bézier paths under skew and matrix transforms. It checks local coordinate canvases, inherited hairline paint, and geometry preservation through edits and flat XML. Native LibreOffice renders of all six pages were compared with OfficeIMO's SVG projection; geometry and placement agree, with the reported fixed-width hairline approximation.

Generated drawings with attached connectors, resized shapes, a rotated rectangle, and screen/print/hidden layers have also been schema-validated and opened, rendered, and resaved by LibreOffice. Native resave retains the connector IDs and moved edge coordinates. The bounded enhanced-geometry profile has separate evidence below; embedded object execution and full producer layout fidelity are not covered by those checks.

`OpenDocumentOdgConnectorRouteTests` reads saved orthogonal routes and legacy relative glue points from `libreoffice-routed-glue.odg`. It also checks the automatic saved edge and offset route in `libreoffice-network-connectors.odg`. Both inputs retain their original upstream bytes. The network fixture has a ZIP extra field on `mimetype`, which strict ODF loading rejects; the route test rebuilds the ZIP envelope without changing any XML or resource entry bytes. The routed-glue fixture's embedded SVG lies outside the flat-XML image profile, so its preservation check uses package output. These checks qualify the connector content, not every shape or image in those files.

The four `libreoffice-partial-line-*` ODG fixtures are unmodified LibreOfficeDev 26.8.0.0.alpha0 resaves of OfficeIMO-authored straight-connector controls. They cover start/end custom-glue attachments on a page or master, a free opposite end, fractional coordinates, target resizing/movement and a separately edited clone. `SetConnectorRoute` writes the current endpoint coordinates and straight path before native saving. The fixture tests retain bindings and strict projection, reject stale caches after a target move, and refresh the route through ODG/FODG reopening. These MIT-licensed controls are native save evidence, not an independently authored corpus.

Eight authoring controls also vary connector/target paint order in both containers and pass ODF 1.4 schemas. Shared SVG, raster and PDF exports on .NET 8 and 10 retain the native-saved geometry; native PDF views were inspected separately. Direct XML controls isolate the native cache behavior: endpoint coordinates prevent a saved zero-origin cache, while a path alone and changing shape order do not. The [partially attached straight-connector profile](../../../OfficeIMO.OpenDocument/README.md#partially-attached-straight-connectors) keeps broader route kinds, automatic glue, transforms, labels and other producers unqualified.

`OpenDocumentOdgImageTextTests` reads and edits image captions through the existing paragraph/list APIs without combining alternate image, text-box, object or annotation stories. The network fixture supplies twelve nonempty caption instances, including nested groups and two overlapping Xenarthra frames. Native PDF comparisons retain all twelve instances, while shared PDF and raster output paint complete overwide labels centered over the original image frames. Authored ODG/FODG one-line controls pass the ODF 1.4 schemas and native open/render/resave checks; crop, horizontal mirror and image opacity affect image paint while captions remain upright and opaque. The flat image payload precedes caption content. Native font substitution and baseline placement differ from shared rendering. Native resaves materialize inherited padding and wrapping defaults that the public inputs omit. Fitting one-line controls do not qualify those defaults for wrapping/overflow, automatic fitting, broader typography or additional producers. See the [image-caption contract](../../../OfficeIMO.OpenDocument/README.md#draw-image-captions).

Generated connected diagrams and a transformed free curve pass the ODF 1.4 flat schema and open, render, and resave in LibreOfficeDev 26.8.0.0.alpha0. Applying transforms to group children retains the tested curve placement and controls through native resave. LibreOffice can recalculate attached orthogonal, segmented, and curved routes, and its automatic edge selection differs from the bounded nearest-edge profile. OfficeIMO projects the saved native result on reopen; native recalculation is separate from preserving an explicitly supplied route. Full circles emitted by native ellipse resave are projected; circle and ellipse sectors/arcs remain reported outside the profile.

Generated geometry documents pass the ODF 1.4 schema and open in LibreOffice. Native rendering agrees for the tested ordinary polygons, curves, polylines, and circular rounded rectangles, including a nonzero view-box origin. LibreOfficeDev 26.8.0.0.alpha0 drops `svg:rx`/`svg:ry` and `svg:fill-rule` during ODG resave; its rendering also differs for oversized circular radii and zero-height polylines. These native differences remain explicit interoperability limits, separate from OfficeIMO's geometry and serialization tests.

`OpenDocumentOdgLineLabelTests` projects the network fixture's complete two-paragraph caption on partially attached `id13` without changing its XML. Generated controls cover horizontal, vertical, diagonal and reversed lines, saved bends outside the endpoint rectangle, page-edge labels and free connector translation baking. LibreOfficeDev 26.8.0.0.alpha0 native SVG controls confirm directed line captions and horizontal connector captions. ODG and FODG exports and native ODG resaves retain the tested authored and detached/translated/baked producer captions. Authored rendering controls use explicit paragraph fonts and colors; native defaults can differ. The generated labelled package and flat document pass ODF 1.4 schemas. These checks qualify the [unwrapped label profile](../../../OfficeIMO.OpenDocument/README.md#draw-line-and-connector-labels), with exact typography, broader insets/alignment and native rerouting outside that evidence.

Direct XML controls derived from the same producer caption cover cubic, quadratic, reversed, upper, sideways, asymmetric and mixed line/curve routes. Relative native SVG caption origins follow the curve's true bounds within one native coordinate unit (0.01 mm), rather than its control-point hull or endpoint rectangle. The public writer retains those origins through both containers. Native SVG/PDF exports and ODG resaves retain the tested captions and baked curves, including group-child translation; LibreOffice reroutes curves with an unbaked transform, as reproduced by a direct XML control. Native body text-opacity declarations use the bounded [body-opacity profile](../../../OfficeIMO.OpenDocument/README.md#draw-text-opacity); caption presence and anchor checks alone do not qualify their native style. These controls establish placement and content retention, not exact native font metrics or general routing equivalence.

Long-caption controls compare explicit wrapping and no-wrapping declarations on horizontal, vertical and diagonal lines/connectors, a wide connector, a saved bend and a curve. LibreOffice retains identical unwrapped caption lines and origins in each pair. Additional direct XML controls with fixed/auto-growing and minimum/maximum frame widths also remain unwrapped on the tested lines and connectors. OfficeIMO preserves the complete caption with an unsupported `label-wrapping` diagnostic, including inherited declarations and explicit hard breaks. Native SVG/PDF/resave and ODG/FODG reopening checks qualify this text-retention behavior; they do not establish width-constrained line-label wrapping.

Direct XML caption controls derived from the producer routes also cover left-aligned plain paragraphs, bullets, decimal labels and left/center/right/comma tabs on straight and diagonal lines and straight and curved connectors. The controls use explicit Arial paragraph fonts and `100%` label sizing. Raw native SVG field and numeric-label origins agree with shared projection within 0.2 points along the caption direction; native PDF views establish rendered placement, while vertical baselines and exact typography remain unqualified. Publicly authored bullet/tab captions pass ODF 1.4 schemas; ODG/FODG exports and native ODG resaves retain the tested content and declarations. Managed regression cases exercise short routes and empty item bodies with larger visible markers, which require intrinsic measurement to include list and tab layout.

Direct XML rotations of detached straight lines and connectors cover positive/negative 30 degrees, translated 90/180 degrees and an equivalent rotation matrix. Native line captions follow the transformed directed segment while connector captions remain horizontal; the explicit 10-point font is retained. Shared projection and public ODG/FODG output preserve these captions. The native vertical connector exports a left-aligned caption far off-page in SVG/PDF; changing only paragraph alignment to center retains it. This remains a native appearance limit, with exact baselines and typography outside the evidence. Native one-argument `scale` controls leave Y unchanged in the tested build, contrary to the ODF rule that the omitted Y factor equals X; OfficeIMO keeps the standard's uniform-scale interpretation. Group transform-attribute controls are nonconforming negative evidence, not a supported native editing workflow.

Explicit inset controls use centered Arial 10-point two-paragraph captions with top/middle/bottom alignment and zero, symmetric or asymmetric side padding. They cover horizontal and diagonal lines, horizontal, vertical and narrow straight connectors, connectors shorter than their combined padding, taller straight connectors and a tall curved connector. The controls change only the producer-derived routes and referenced styles; they are separate from freshly authored public API examples. Relative raw SVG caption-origin changes agree within 0.2 points with shared projection; native PDF views show the placement change independently of rotated SVG rendering. ODG/FODG output and native ODG resaves retain the tested caption content and padding declarations. Freshly authored cases pass ODF 1.4 schemas. This qualifies the bounded inset/alignment profile, with exact font baselines, other producers and combined list/tab/rotation inset layouts still open.

Direct XML controls vary only horizontal text-area alignment and paragraph alignment in producer-derived horizontal/diagonal lines and horizontal, curved, narrow and vertical connectors. They cover `justify`, `left`, `center` and `right` areas, all three paragraph alignments, middle vertical alignment and zero/asymmetric padding with explicit Arial 10-point text. The measured paragraph block aligns independently of its paragraphs, including overflow beyond narrow routes. Visible raw native SVG origins agree with shared projection within 0.3 points along the caption direction; native PDF views confirm placement. For zero-width routes, left/right areas and noncentered justified paragraphs export native text far off-page; OfficeIMO retains that text near the route with a `label-degenerate-area` approximation. Public ODG/FODG output and native resaves retain the tested declarations; fresh authored cases pass ODF 1.4 schemas. Exact baselines, other fonts/producers and broader combined list/tab/rotation area layouts remain outside this evidence.

Raster regression controls compare tightly fitted diagonal italic captions with a larger paint canvas carrying the identical logical text frame. They cover negative bearings and right overhang on all four caption-area values, including a justified caption wider than its route, through ODG/FODG reopening at two raster scales. The caption canvas retains all reference glyph pixels without moving the logical frame. This establishes shared raster ink retention, separately from native font-placement qualification.

Structured-caption controls combine all four horizontal area values with asymmetric insets on producer-derived horizontal connectors, diagonal lines and curved connectors. They cover bullets, decimal labels, four body-tab alignments, and decimal list items containing comma-tab fields. Explicit Arial 10-point paragraphs and `100%` label fonts isolate the declared layout. Field and numeric-label origins agree within 0.3 points along the caption direction; native PDF views show the correction from a body-indent shift to the original paragraph tab origin. Public numbered-tab examples pass ODF 1.4 schemas, and ODG/FODG native exports retain equal origins and complete body fields. Native resaves can introduce inherited graphic text-opacity declarations; unqualified list-label opacity retains its unsupported mapping and strict-policy rejection while cached field content is retained. Fresh authoring with omitted label color produces white native number labels; their raw SVG origins remain measurable, but label-color inheritance is not appearance-qualified. Producer controls with black labels supply visible label-placement evidence. Broader modern list-spacing modes, non-left tab paragraphs, broader transform-attribute rotation combinations, exact baselines and other fonts/producers remain unqualified.

Numbered comma-tab rotation controls combine translation, positive/negative 30 degrees and an equivalent rotation matrix with all four text areas and asymmetric insets on detached straight lines and connectors. Explicit black labels remove the inherited-color ambiguity. Raw native SVG label/field starts agree within 0.2 points along the caption direction; actual native PDF views retain both numbered body paragraphs. Fresh public authoring passes ODF 1.4 schemas, and both containers retain equal native origins. OfficeIMO reopening preserves transform strings, while native resaves flatten them into endpoints within 0.03 points of the declared coordinates. Equivalent native line rotations have equal starting origins but export text at 29.9 versus 30 degrees, with within-word glyph starts differing by up to 0.042 points; equivalent connector exports retain horizontal captions. Native PDF fonts resolve to Liberation Sans at approximately 10.006 points. These are producer-derived controls and public examples, not an independently authored corpus or exact font/baseline qualification. The tab fields contain ordinary text rather than dynamic ODF field elements.

`libreoffice-master-artwork.odg` retains unmodified upstream Draw bytes. Its master contains two enhanced custom shapes and a styled text frame; the page also contains text. The projection reads the master's part-local font and color declarations and paints its text at the master frame's coordinates before page content. ODG/FODG reopening retains both stories without mutating the source. Its literal master rectangle and ellipse, and the page diamond and ellipse, also project through the enhanced-path profile. Formula-driven artwork and the page square-gradient background remain preserved with explicit loss diagnostics; this fixture does not qualify complete page appearance.

`OpenDocumentOdgEnhancedGeometryTests` covers literal paths, full ellipses, even-odd subpaths, horizontal/vertical mirrors, ordinary bounds/paint editing and source-preserving ODG/FODG reopening. Eight edited authored controls pass ODF 1.4 schemas and open, export and resave in LibreOfficeDev 26.8.0.0.alpha0. Their filled-shape bounds agree with shared raster output within one point at 72 dpi; filled-mask intersection-over-union ranges from 0.9748 to 1.0. Native paper rounding adds one empty trailing raster row, which is removed without rescaling for the comparison. Rendered views were inspected separately.

The native hole control uses spaced commands: the same LibreOffice build renders the whitespace-equivalent compact enhanced path blank and truncates it to `M 0 0` during resave in both containers. OfficeIMO retains and projects both notations; the compact native failure remains an interoperability limit. Native geometry evidence does not qualify equations/modifiers, partial arcs, multiple independently painted path sets, enhanced text areas, stretch points, extrusion, exact typography or other producers.


The [page-background profile](../../../OfficeIMO.OpenDocument/README.md#draw-page-backgrounds) uses native controls for solid fills and stretched PNG bitmaps, 50% opacity, master inheritance, page color overrides, asymmetric margins and full/border paint areas in ODG and FODG. The tested Draw build keeps the master fill when page fill is `none`, uses the master's paint area, and ignores presentation-only background visibility. Shared bitmaps use pixel-preserving interpolation to match the controlled native PDF appearance. Generated documents pass ODF 1.4 schemas; referenced fill-image bytes survive flat export and package reopening. A labelled derivative of the independent master fixture removes only the page style binding to expose its existing bitmap, retaining upstream fixture bytes on disk. The unmodified square gradient, formula artwork, text metrics, broader image formats/producers and background authoring remain outside this evidence.

Ten authored background-gradient controls cover linear angles and full/border areas, endpoint intensities, borders, mirrored axial fields, offset and corner radial centers, uniform opacity, a solid 100% linear border and a page gradient overriding master paint. ODG and FODG output pass ODF 1.4 schemas. At 72 dpi, twenty native PDF comparisons have at least 99.67% of pixels within four channel values and mean absolute channel error below 0.66. Automatic native banding remains a continuous-interpolation approximation. These controls do not add an independently authored gradient corpus or qualify the existing square-gradient fixture, fixed bands, extended/SVG definitions, off-area radial centers or other native producers.

The controlled native master-field fixture retains LibreOffice page-number placeholders, page counts and fixed date/time display caches. Projection resolves page placeholders from each rendered page without changing the saved XML. Native formatting and offsets, automatic foreground opacity and exact text placement remain separate limits; this fixture is not an independently authored drawing corpus.

`libreoffice-intrinsic-rectangle-areas.fodg` and `libreoffice-intrinsic-textbox-areas.fodg` are unmodified LibreOfficeDev 26.8.0.0.alpha0 native resaves of controlled derivatives of the earlier OfficeIMO-authored probes. Each contains 36 cases: all nine left/center/right area and paragraph combinations with hard-break text, tabs, paragraph margins and long text, using explicit Liberation Sans 12-point fonts and asymmetric frame padding. The text-box controls wrap; the rectangle controls retain an unwrapped intrinsic area despite a wrapping declaration. Tests retain both profiles and native declarations without mutating the source. These controls use the repository MIT license and provide native interoperability evidence, separate from the independently authored upstream corpus. Exact baselines, additional fonts/producers and combined lists/indents remain unqualified.
