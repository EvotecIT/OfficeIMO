# Content safety support matrix

OfficeIMO reports content that remains machine-readable while it is hidden from, de-emphasized for, or outside an ordinary human review surface. These findings are ingestion-security evidence. They are not proof that AI created the file, and a clean report is not proof that a human created it.

Every format adapter uses the shared `OfficeIMO.ContentSafety` contracts. Encoded bytes, package entry counts, declared ZIP expansion, decoded characters, and findings are bounded before the relevant allocation boundary. Cleanup requires an explicit list of current finding IDs, rechecks that selection against the current artifact, applies the format owner's native mutation path, and reinspects the output. Existing signatures fail closed unless the caller explicitly selects a supported invalidated-signature disposition.

For SVG, active paint-server references and active `use` instances make the native paint projection incomplete. The inspector reports otherwise unclassified text in those documents as informational and report-only, even when visual comparisons are disabled; it cannot infer that a browser would paint the text the same way. Unused definitions do not impose this restriction on unrelated text.

## Risk interpretation

- `Informational` means the location is normally non-primary metadata or accessibility content.
- `ContextDependent` means the mechanism has legitimate uses but should be reviewed before model ingestion.
- `PotentiallyDangerous` means concealed text also matched bounded instruction-like signals such as instruction override, decision manipulation, tool/data extraction, or a request to conceal content.

Instruction-like matching raises the risk of an exact concealment finding; it does not replace the native mechanism. A white-on-white instruction remains `LowContrastText`, a hidden run remains `HiddenByProperty`, and an off-canvas accessibility helper remains `OffCanvas` with context-dependent risk unless its text supplies stronger evidence.

## Images and compound web publications

`OfficeIMO.Reader.Image` emits bounded OCR candidates for broader Reader workflows. Raster content-safety assessment is the separate `OfficeIMO.Workflows` contract described above; neither path classifies an image as clean, malicious, or AI-generated from metadata alone. MHTML and EPUB reuse the same HTML owner for concealment semantics while their package owners retain responsibility for bounded resource resolution, preservation, signature policy, and reopen validation.
