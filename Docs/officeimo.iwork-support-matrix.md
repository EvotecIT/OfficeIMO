# Apple iWork source-reader support

OfficeIMO reads modern IWA-based Pages, Numbers, and Keynote sources through the bounded `OfficeIMO.IWork` package. Opt-in adapter packages project supported semantics into the existing Word, Excel, and PowerPoint owners. The source layer is read-only, and the default destination packages do not depend on iWork.

The current level is **extended semantic reconstruction**. Normal document content becomes editable destination objects with recovered structure, typography, sizing, and geometry where the corpus proves those fields. It is not a pixel-identical renderer or a claim that every application-only feature can be translated.

## Public ownership

| Source | Typed source projection | Opt-in adapter | Entry points |
|---|---|---|---|
| Pages | `IWorkPagesProjection` | `OfficeIMO.Word.IWork` | `ToWordDocument`, `ToWordDocumentResult` |
| Numbers | `IWorkNumbersProjection` | `OfficeIMO.Excel.IWork` | `ToExcelDocument`, `ToExcelDocumentResult` |
| Keynote | `IWorkKeynoteProjection` | `OfficeIMO.PowerPoint.IWork` | `ToPowerPointPresentation`, `ToPowerPointPresentationResult` |

`IWorkSourceDocument.Open` is the shared loading and inspection entry point. It accepts paths, streams, and byte arrays; exposes normalized package entries, IWA payload records, producer build history, previews, diagnostics, and application-specific typed projections; and can be converted more than once with independent destination options. Adapter result APIs retain that same source model beside the generated Office document.

`OfficeIMO.Reader.IWork` registers directory bundles as individual documents. Path reading, async reading, folder ingestion, and discovery retain the package owner's bounds, physical-root checks, cancellation, and captured content hash. Resources inside a registered bundle are not ingested as separate documents. `ContainerLengthBytes` records ZIP bytes or physical bundle file bytes before nested expansion; `ComputePackageContentHash()` hashes the captured normalized entries and does not reopen the filesystem.

`OfficeIMO.Workflows.IWork` registers all three Apple-to-OOXML routes without adding iWork to the default workflow dependency graph. Local ZIP files, local directory packages, and provider ZIP streams use bounded captured inputs, destination reopen validation, source verification, and safe publication. Defaults reject explicitly partial editable reconstruction and visual previews without known complete coverage. `ConversionEvidence` retains typed fidelity categories and compact source/projection facts after destination disposal. Directory packages use a deterministic private ZIP transport snapshot, with package-root identity and file membership/content checked again before publication. Destinations inside the package or aliased to a package member are rejected. The snapshot checksum describes that transport archive. Native permission-scoped directory-package intake remains outside this local-filesystem contract. The CLI exposes these routes through `officeimo convert`. Studio uses the same runner for file-picker, drop, and startup intake, with per-job representation and acceptance settings, captured source SHA-256, retained fidelity evidence, and saved-output preview. These workflow settings are copied before asynchronous source capture.


## Bounded NativeAOT qualification

`OfficeIMO.Reader.IWork.AotSmoke` publishes and executes the source reader and shared
Reader handler on macOS arm64 with .NET 8.0.31 and .NET 10.0.12. The host rejects
managed execution. Five hash-pinned corpus fixtures exercise Pages body text,
Numbers sparse typed cells and selected arithmetic/range/string formulas, and
Keynote slide titles, body text and presenter notes. The native comment fixture
checks three Reader root comments against its independent manifest, including
exact content, author, creation time, native identity and source cell anchors.
It also checks source and
Reader path/stream parity, caller-owned streams, source preservation and
unassessed-fidelity diagnostics, Reader JSON transport round-trip, pre-cancellation
and configured input byte limits. Fixture provenance and licenses remain in the
[corpus](../OfficeIMO.TestAssets/Documents/IWorkCorpus/README.md).

Run the coordinated native gate from PowerShell with the pinned SDK and platform
compiler installed:

```powershell
./Build/Test-AotScenarios.ps1 -Scenario reader-iwork-net8,reader-iwork -RuntimeIdentifier osx-arm64 -JsonOutputPath <evidence.json>
```

The gate retains executable SHA-256, exit codes and output before deleting isolated
publish and SDK directories. The scenario is also included in the full gate;
`-Scenario` selects known scenario IDs and rejects unknown IDs before publishing.
This evidence covers the invoked source/Reader paths, not every public API or
all-file compatibility. It does not qualify destination conversion/save, rendered
appearance, portable fonts, Windows/Linux execution, iOS/iPad, sandbox permissions
or signed application distribution.

## Package and IWA boundary

| Capability | Current contract |
|---|---|
| Containers | ZIP packages, directory bundles, and packages with nested `Index.zip` |
| Package safety | Configurable package, entry, entry-count, aggregate-uncompressed-size, and path bounds; top-level package paths and directory entries must be regular files rather than links, pipes, or devices; duplicate, absolute, traversal, and empty-segment paths are rejected; directory reads verify the opened regular-file handle remains under the captured physical package root |
| IWA framing | Raw Snappy chunks used by modern iWork, with declared-size, chunk-size, aggregate-size, copy-offset, truncation, and integer-overflow checks |
| Object envelope | Bounded ArchiveInfo and MessageInfo protobuf parsing with field-count, depth, record-count, record-size, wire-type, varint, reference, and unique primary-object validation |
| Preservation | Defensive access to all package entries and all primary or auxiliary IWA payloads; conversion reports retain source payloads for inspection through `PreservedRecords`, including consumed, partially consumed, and auxiliary records; this count does not measure omitted content |
| Active content | No macros, scripts, external links, embedded executables, or application services are executed |
| Legacy packages | Pre-IWA `index.xml` and `index.apxl` packages are rejected as unsupported rather than guessed |

Public source and adapter path/stream APIs accept cancellation; source byte-array loading accepts it as well. The source token governs subsequent projections and conversions. Destination construction checks cancellation between objects, cells, paragraphs, and runs and disposes a partially constructed destination on failure. Caller-owned streams remain open. Fixed cancellation latency, allocation, and retained-memory budgets remain unqualified. The opt-in [runtime evidence lane](../OfficeIMO.IWork.Benchmarks/README.md) measures elapsed time and managed allocations for synthetic Pages paragraphs, Numbers numeric cells and Keynote titles at three scales, with complete saved-package semantic readback. Working-set deltas do not qualify peak or retained memory, and these measurements do not establish portable ceilings or native appearance.

`IWorkReadOptions` supplies source-reading and semantic-projection limits. `IWorkConversionOptions` independently chooses automatic, editable-only, or visual-only destination representation. Defaults cap a package and aggregate expanded entries at 512 MiB, one entry at 128 MiB, one compressed IWA archive at 64 MiB, one decompressed archive at 256 MiB, all decompressed IWA archives at 512 MiB, one Snappy chunk at 64 MiB, one record at 128 MiB, the source-wide record count at 1,000,000, and combined ArchiveInfo version/reference values at 8,000,000. Semantic projection also bounds decoded and destination-expanded text characters, including repeated shared strings, font families, list labels, and hyperlinks; text items and attribute boundaries; cross-record style inheritance; sparse materialized cells; string/formula catalogs; source-wide formula rendering work including repeated formula uses; tables; projected images; merged ranges; table dimensions; Numbers sheets; and Keynote slides. Word and PowerPoint owner preflight additionally bounds the aggregate destination table-cell area before allocating editable table grids.

Tables expose sparse one-based `RowHeights` and `ColumnWidths` in source points. `GetRowHeight` and `GetColumnWidth` resolve an explicit size or the table default. Zero-size native headers use that default. All row-header buckets are read under the source-wide `MaximumTableDimensionEntries` bound, which counts headers and bucket references. Malformed, duplicate, unresolved, or hidden sizing records emit `IWORK_TABLE_HEADER_DIMENSIONS_UNSUPPORTED` and make reconstruction incomplete. Header-dimension visibility and cell/text styles are not reconstructed. Qualified base user-hidden state has the separate contract below. Table-model text defaults have the separate contract below.

Supported modern numeric cells expose `IWorkTableCell.NumberFormat` independently of their values and formula caches. The selected modern format catalog (`4/22`) supports decimal numbers, percentages, and currencies with explicit zero-to-thirty decimal places or automatic mode, digit grouping, and the four minus/red/parentheses negative styles. Scientific selections support the same precision range for the mantissa, the default minus style, and no grouping; other scientific negative/grouping selections remain unqualified. Format values are traversed only for selected keys; all catalog entries count toward `MaximumTableCatalogEntries`. Catalog Boolean BNC metadata is validated. Currency selections take precedence over inactive numeric slots. Supported currency metadata includes a three-letter uppercase identifier and accounting style with the default minus negative-style setting. Other accounting/negative-style combinations remain unqualified. Unsupported properties, ambiguous keys, and unresolved catalogs emit `IWORK_TABLE_NUMBER_FORMAT_UNSUPPORTED`; partial reconstruction retains raw values. Selected format declaration failures use `3[n]/6` evidence. XLSX applies supported format codes without converting values to strings. Currency codes become visible prefixes; accounting negatives retain parentheses. `IWORK_NUMBERS_CURRENCY_DISPLAY_APPROXIMATED` reports missing symbols, locale-specific placement, and accounting alignment. Retained currency identifiers count toward projection text limits. Scientific XLSX cells use a single-digit mantissa with `E+00`. Automatic decimals use fifteen optional fractional places (mantissa places for scientific cells) and report `Approximation`; this does not reproduce Numbers' significant-digit, rounding, or exponent-presentation selection. DOCX and PPTX table cells apply the same shared numeric formatter as Excel visual snapshots: supported precision, grouping, percentages, scientific and fraction text, currency-code prefixes, negative parentheses and red format color become editable text and run color. `IWORK_PAGES_NUMBER_FORMAT_APPROXIMATED` and `IWORK_KEYNOTE_NUMBER_FORMAT_APPROXIMATED` report locale, automatic precision and appearance differences. Raw source values, formula caches and `DisplayText` properties remain unchanged. Cells with retained rich text or an unrepresentable scaled value keep their raw text and report numeric-format `Omission`. Save/reopen cases qualify destination text and color through synthetic native-format packages; native Pages/Keynote exports and full appearance remain unqualified.

Selected fraction formats (native type `262`, precision field `11`) retain `FractionAccuracy` independently of decimal places. The qualified modes bound the denominator to one, two, or three digits, or fix it at 2, 4, 8, 16, 10, or 100. The default minus/no-grouping subset is supported; unknown, duplicate, or conflicting controls retain declaration evidence and remain unassessed. XLSX uses mixed-fraction codes with explicit negative and zero sections. `IWORK_NUMBERS_FRACTION_DISPLAY_APPROXIMATED` reports rounding, normalization, and spacing differences; it does not change typed values or formula caches. A fraction's null `DecimalPlaces` is not automatic decimal formatting.

Finite Decimal128 values with more than fifteen significant digits retain a recovered numeric value, `NumericValueIsApproximate`, and exact normalized coefficient/exponent text in `SourceNumberText`. `IWORK_TABLE_NUMERIC_VALUE_APPROXIMATED` reports `Approximation`, including numeric formula caches; their cache assessment is `Approximate`. These values remain editable, while nonfinite, noncanonical, overflowing, and nonzero underflowing values retain decode-failure evidence. Exact numeric source text counts toward projection text limits.

Excel preserves individual point heights and converts column widths to character units; dimensions outside XLSX bounds are rejected before destination creation. Word writes sizes in twips under its existing precision policy. PowerPoint preserves individual sizes, scaling them proportionally when their total differs from the drawable extent; this emits `IWORK_KEYNOTE_TABLE_SIZING_SCALED` as an approximation. EMU quantization remains diagnosed separately.

Tables in all three formats resolve text cells backed by either plain strings or rich-text storage. Rich-text cells expose normalized plain text through `IWorkTableCell.Value` and `DisplayText`, and source paragraphs, runs, styles, and hyperlinks through `IWorkTableCell.RichText`. Word and PowerPoint adapters write supported runs and links into editable table cells. Excel writes supported character formatting and a cell hyperlink when every non-empty run has the same absolute target; list markers, mixed run links, and run highlights produce a conversion diagnostic because those details cannot be represented in XLSX rich text. Unresolved rich-text references in non-formula cells produce a cell error and a table diagnostic instead of a blank label. `FormulaIsComplete` describes the formula expression; `CachedValueIsComplete` describes its cached result separately. Partial formula caches emit `IWORK_TABLE_FORMULA_CACHE_PARTIAL` even when the expression remains complete. Word and PowerPoint require a complete cached value and, for rich formula caches, complete styles before editable table output; Excel can preserve a complete formula without its partial cache.

Editable reconstruction means the supported content is represented as normal DOCX, XLSX, or PPTX objects and can be edited and saved through its owner. It does not mean the destination is visually identical or that unsupported iWork records are written into the Office package. Keynote point measurements finer than PPTX's integral EMU grid remain editable, are quantized to the nearest EMU, and emit `IWORK_KEYNOTE_PPTX_PRECISION`; the original bounded geometry remains available on the load result.

Finite rectangular cross-table references resolve a strict four-word CFUUID against unique textual UUIDs of selected table models in native byte order. Source expressions retain quoted sheet/table labels; XLSX expressions use the actual worksheet names, including forward targets and normalized collisions. Active endpoint sticky flags preserve mixed absolute/relative coordinates; relative coordinates accept protobuf int32 sign extension. Missing, inactive, malformed or duplicate identities remain incomplete and retain valid typed caches.

Table-local and cross-table coordinate-backed whole-row/column references (native nodes `36` and `67`), including header-name aliases, retain coordinate expressions in the source model. XLSX maps missing columns to the current table columns after header columns, and missing rows to the current rows after headers and before footers. The absent axis uses absolute bounds; the specified axis retains each endpoint flag. `IWORK_NUMBERS_TABLE_BODY_RANGE_APPROXIMATED` records lost native labels and automatic expansion. Duplicate, wrong-wire or overlapping dimension/header/footer metadata prevents body binding. An empty body cannot be represented as a nonempty XLSX range and requires destination fallback. Coordinate-backed single cells use the contract below; other named-reference families remain unqualified. Whole-axis forms from other reference node families retain caches with incomplete expressions.

Coordinate-backed single-cell references from native node `36` resolve the same strict CFUUID identity and selected-table bindings as rectangular ranges. Their signed relative offsets and absolute flags retain the exact cell address. Qualified endpoint pairs (`29`/`45`) require the same target identity and emit a single table/worksheet qualifier; a missing or different target endpoint remains incomplete. Supported whitespace nodes retain that endpoint identity. Other cell-reference node families remain unqualified for cross-table binding. Single cells do not introduce the fixed-body-range approximation.

The [independent single-cell corpus](../OfficeIMO.TestAssets/Documents/IWorkCorpus/README.md#single-cell-and-endpoint-formulas) checks five native reference expressions with numeric/text caches and mixed flags, four scalar text/Boolean expressions, and five saved/reopened XLSX expressions using endpoint ranges, a single-cell `OFFSET` base, `NOT` and `UPPER`. Independent current-cell computations agree with their native caches. Edited destination values exercise the shared Excel evaluator separately. The larger source includes pre-1900 dates and correctly uses destination fallback as a whole workbook; its qualification covers source decoding. Apple export/render equivalence and broader native recalculation remain open.

Binding consumes the cumulative formula-work budget; source labels consume projection text limits, and destination formulas remain within XLSX limits. Merge extraction accepts a matching own-table qualifier; external qualifiers retain rejected-declaration evidence.

The independent rectangular corpus qualifies all sixteen endpoint combinations, exact saved/reopened destination expressions and numeric caches. The same native package supplies 59 whole-axis cases: independently resolved body values agree with every native cache, and saved/reopened XLSX expressions retain those body bounds and endpoint flags. Synthetic footer and ambiguous/empty-body cases protect the destination contract. These comparisons supply no native Apple export, appearance, recalculation or cache-freshness oracle.

### Pages inline attachments

Pages body runs expose `IWorkTextRun.InlineObject` for qualified image and table attachments. `CharacterOffset` is the zero-based UTF-16 offset in the original text storage, before replacement-marker removal; attachment and drawable identities remain available separately. The reader assesses the body attachment table and selected drawable references under the existing attribute, reference, declaration, and projection budgets. Missing targets, malformed tables, unknown attachment envelopes and unsupported placement modes keep the body incomplete and retain source evidence.

The qualified native mode declares horizontal and vertical offset types and offsets as zero. DOCX inserts images at their run positions and standalone tables between the surrounding body paragraphs. A table must occupy its own paragraph; repeated positions for one drawable and linked attachment runs are rejected by the destination policy. Reader emits tables and image-anchor blocks in body order, including images without alternative text. Image assets point to those blocks, and attachment-run links retain the emitted image or table block anchor. Reader charges every emitted image use against `MaximumProjectedImages` and each copied payload against `MaximumProjectedImageBytes`, including repeated references to one source drawable. Mixed text/object paragraphs become ordered blocks with `IWORK_READER_INLINE_PARAGRAPH_SPLIT`, because Reader does not preserve inline paragraph layout.

The independently extracted [Pages attachment manifest](../OfficeIMO.TestAssets/Documents/IWorkCorpus/pages-inline-anchors.json) qualifies five source positions across two unmodified native fixtures: one table in the Pages 14.1 package and three tables plus an image in the representative package produced by Pages 14.5. Saved/reopened DOCX tests check the representative fixture's table/image order; synthetic cases check supplementary Unicode, two images in one paragraph, failed references, placement limits and budgets. This evidence does not qualify native Apple export, pagination, wrapping, or rendered equivalence. Header/footer, text-box and table-cell attachments remain unresolved, along with other attachment kinds and placement modes.

### Table row sizing

`IWorkTable.AutoResizeRows` retains the selected native table-style automatic-resize Boolean, including bounded parent inheritance and child overrides. It is null when absent or unresolved. Invalid Boolean encodings, ambiguous style properties, missing or wrong-type styles, cycles and excessive inheritance depth diagnose `IWORK_TABLE_ROW_SIZING_UNSUPPORTED` and prevent complete editable reconstruction. Source declaration and reference issues retain the selected owner paths.

Pages converts a resolved true setting into Word minimum row heights, keeping the source point values while allowing wrapped text and paragraph spacing to increase the row. Explicit false settings and absent settings keep exact heights. `pages-table-sizing.json`, extracted through independent numbers-parser 4.19.0 schemas, qualifies the three tables in the unchanged PicoDocs Pages fixture; saved/reopened DOCX preserves their 16.5-point minimum constraints. The shared PDF renderer keeps a fitting text line visible when paragraph-after spacing exceeds a fixed row, while still clipping lines whose actual boxes exceed it. Full table styling, Apple export pagination and rendered equivalence remain unqualified. Numbers and Keynote retain the setting in the source model; their destination automatic row sizing remains open.

### Selected table-cell fills

`IWorkTableCell.Fill` preserves the fill from a selected modern cell-style key, including bounded parent inheritance. A solid fill exposes an opaque sRGB or gray `Color`; `IsNone` identifies an explicit empty fill declaration that clears the parent. Null means absent or unresolved. Styled empty cells remain sparse materialized cells with `Kind == Empty`, empty display text, and no value; they count toward `MaximumMaterializedCells`. Unselected style entries are indexed for uniqueness and catalog bounds but their references and properties are not traversed.

Pages writes these fills through Word cell shading, including explicit no-fill overrides. The [independent manifest](../OfficeIMO.TestAssets/Documents/IWorkCorpus/pages-cell-fills.json) covers 64 selected cells across three tables in the unchanged PicoDocs Pages fixture. Saved/reopened DOCX checks include four styled empty cells and header colors `D9EAF7` and `EFEFEF`; the source's explicit no-fill declarations suppress blue parent fills. This qualifies selected source fills and saved destination shading, without an Apple export or full appearance claim.

Numbers writes selected solid fills into XLSX cell backgrounds; explicit no-fill retains the unfilled destination state. The [independent Numbers manifest](../OfficeIMO.TestAssets/Documents/IWorkCorpus/numbers-cell-fills.json) covers 130 selected no-fill cells in the unchanged cross-table formula fixture. Keynote writes solid fills and explicit no-fill into PPTX cell properties, overriding the destination table theme. Inherited, solid and no-fill save/reopen cases for both adapters use synthetic native-format packages and include styled empty cells; native Keynote selected fills and Numbers solid fills remain independently unqualified. The newer Numbers 15.1 fixture contains an additional color field outside the supported subset and retains its fill diagnostics.

Malformed, ambiguous or missing selected styles, unsupported color spaces/transparency, gradients and image fills produce `IWORK_TABLE_CELL_FILL_UNSUPPORTED` with `Unassessed` fidelity and prevent complete editable reconstruction. Source reference and declaration issues retain selected catalog (`4/5`, `3[n]/4`) and style (`1`, `11`, `11/1`) paths. Conditional fills, borders and other cell-style properties remain unqualified. Reader reports plain-table style loss and counts only value/diagnostic cells as filled.

### Table-fill defaults and banding

`IWorkTable.FillStyles` exposes applicable body, header-row, header-column and footer-row fills through bounded style inheritance and the shared solid/no-fill decoder. `BandedBody` retains an active supported band fill. `GetFill(row, column)` resolves a one-based position without allocating unstored cells. A selected supported fill overrides its region and band, including explicit no-fill; an unresolved selected fill suppresses defaults. A selected style with no fill declaration inherits its effective default. Header and footer rows precede header columns. Banding replaces body fill on every second body row, counting after the headers, and excludes header columns and footers.

The [native Numbers 14.5 reference](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/numbers-banding-v14.5.json) contains three eight-row tables with zero, one and two header rows, one header column and one footer row. The [Keynote manifest](../OfficeIMO.TestAssets/Documents/IWorkCorpus/keynote-table-fill-defaults.json) separately qualifies unbanded explicit no-fill roles in the unchanged Keynote 15.2.1 fixture; all nine saved/reopened PPTX cells suppress destination theme backgrounds. Synthetic native-format cases cover inherited role colors, band colors, selected overrides and saved DOCX/XLSX/PPTX properties. Native Pages and Keynote banded exports, other producer versions, gradients, transparency and complete table appearance remain unqualified.

Unsupported or unresolved active banding suppresses fill defaults rather than substituting unbanded colors. Unsupported role fills produce `IWORK_TABLE_FILL_DEFAULTS_UNSUPPORTED` with `Unassessed` fidelity and prevent complete editable reconstruction; selected supported fills and values remain available under the partial policy. Disabled banding ignores inactive band fills. Inactive roles are not traversed. Failed role references retain model paths `18`–`21`; invalid banding declarations and fills retain table-style paths `11/1` and `11/2`. Excel region and band styling use the existing 100,000-cell per-table and 1,000,000-cell per-conversion destination budget. Reader reports these defaults as plain-table style loss.

### Selected table-cell padding and vertical alignment

`IWorkTableCell.Padding` retains nonnegative finite left, top, right and bottom insets in points. `VerticalAlignment` retains `Top`, `Middle` or `Bottom`. Both use the same selected style catalog and bounded parent chain as fills. A declared padding message replaces the whole inherited property: omitted scalar sides default to zero, including an explicit empty message. An absent property inherits; null means absent or unresolved. Padding-only and alignment-only empty cells remain materialized and count toward the existing cell budget.

The independent `pages-cell-fills.json` manifest also qualifies middle alignment and four-point padding in all 64 selected cells of the unchanged Pages fixture. Saved/reopened DOCX compares each side and alignment with those facts. Synthetic native-format cases cover inherited properties, explicit zero resets, partial padding messages and saved output in all three destination adapters. Pages maps padding to Word cell margins and vertical alignment; Keynote maps them to PowerPoint table-cell margins and anchors. Numbers maps vertical alignment and reports `IWORK_NUMBERS_CELL_PADDING_OMITTED`, because XLSX has no four-sided cell-padding equivalent. Reader reports these properties as plain-table style loss.

Malformed, repeated, unknown or invalid selected padding/alignment declarations produce `IWORK_TABLE_CELL_LAYOUT_UNSUPPORTED` with `Unassessed` fidelity and source paths `11/9` or `11/8`. Recovered values and independently valid fill/layout properties remain available. Values beyond destination margin ranges require fallback even under the partial policy; partial conversion permits measurement rounding with the destination precision diagnostic. This does not qualify table-role layout defaults, native Apple export, pagination or complete appearance.

## Formula functions

The shared formula reader qualifies native function identifiers and supported argument counts for `ABS`, `AND`, `AVERAGE`, `AVERAGEA`, `COLUMN`, `COUNT`, `COUNTA`, `COUNTBLANK`, `COUNTIF`, `DATE`, `DAY`, `EXACT`, `FALSE`, `FIND`, `HOUR`, `HYPERLINK`, `IF`, `INDEX`, `LEFT`, `LEN`, `LOWER`, `MAX`, `MAXA`, `MEDIAN`, `MID`, `MIN`, `MINA`, `MINUTE`, `NOT`, `NOW`, `OFFSET`, `OR`, `PI`, `POWER`, `PROB`, `RANDBETWEEN`, `RIGHT`, `ROUND`, `SECOND`, `SUM`, `SUMIF`, `TEXTJOIN`, `TRIM`, `TRUE`, and `UPPER`. `TEXTJOIN` accepts three-to-254 arguments; other variadic calls are limited to 255 arguments and all expressions remain subject to syntax, text and rendering-work budgets. Completeness also requires supported operands and resolved references. This is a reconstruction contract, not a promise of equal evaluation for every argument type or of fresh cached results.

The pinned independent `function-identities.json` manifest checks all 45 identifiers. Three expressions in the unmodified native corpus qualify nested `OR`, `POWER`, and cross-table `TEXTJOIN` through saved/reopened XLSX formulas and typed caches. The native `TEXTJOIN` cache agrees with an independent join of its referenced cells. XLSX stores `_xlfn.TEXTJOIN` through the shared Excel owner; edited and empty source cells exercise the shared evaluator separately. Quoted worksheet names retain apostrophes, commas and parentheses. Joining errors remain typed errors, and text results above 32,767 characters produce `#VALUE!`.

Unrecognized identifiers and calls outside their qualified argument counts remain incomplete; valid caches remain available without an editable Excel formula.

`MINA`, `MAXA` and `AVERAGEA` identities and variadic arities are checked against the independent map and synthetic native-format cases, with saved/reopened editable XLSX formulas, numeric caches and local recalculation. The shared evaluator separately checks referenced Boolean/text types, blank ranges and typed errors through `MINA`, `MAXA` and `AVERAGEA`; ordinary numeric aggregates skip nonnumeric references. Apple-produced documents, exports and native recalculation remain unqualified for these three functions. Argument-type equivalence is also unqualified: Apple disallows direct text arguments to `MAXA`, while the shared Excel evaluator treats them as zero. Date/time and duration combinations need separate qualification.

`NOT`, `TRUE`, `EXACT`, `LOWER`, `TRIM` and `UPPER` use exact argument counts. Six expressions in the unchanged single-cell and endpoint fixtures qualify native `NOT`, `EXACT`, `LOWER`, `TRIM` and `UPPER` nodes and Boolean/text caches against independent computations. The endpoint `NOT` and `UPPER` cases also retain typed caches through saved/reopened XLSX and local recalculation after literal edits. The larger single-cell fixture retains its pre-1900-date whole-workbook fallback. Synthetic native-format cases cover `TRUE()` with a stale Boolean cache, quoted text literals and empty trim results. These cases qualify ASCII casing and ordinary spaces; locale/Unicode casing, other whitespace, Apple exports and broader native recalculation remain unqualified.

The OfficeIMO-authored `numbers-functions-v14.5` and `numbers-function-edges-v14.5` fixtures qualify native `OFFSET` (three-to-five arguments), `PROB` (three or four), and `RANDBETWEEN` (two). Cache-free OOXML intakes are imported, evaluated, saved and exported by Numbers 14.5 independently of OfficeIMO. The checked-in manifest matches 26 expressions, their native function nodes and numeric caches with Apple XLSX exports. Saved/reopened OfficeIMO XLSX retains these expressions and caches; edited referenced values exercise fresh evaluation through the shared Excel owner.

The Excel evaluator supports single-cell `OFFSET` results and finite rectangular `OFFSET` arguments to range-consuming functions, with worksheet bounds, existing cell budgets and 32 nested reference levels. Multi-cell scalar results, spills, implicit intersection and formulas stored in defined names remain outside this subset. `PROB` evaluates finite numeric vectors within a shared 100,000-cell budget, inclusive bounds and omitted upper bounds; zero probabilities are supported and invalid distributions produce typed Excel errors. Mixed text/Boolean/blank vector coercion remains unqualified. `RANDBETWEEN` locally evaluates inclusive integer bounds within Int32; fractional and larger bounds retain formulas and producer caches without local evaluation. Random snapshots do not qualify identical random sequences. Native error cells in these Apple exports have no XLSX error cache, so the typed Excel evaluator errors do not establish native error-code equivalence. Full appearance and additional producer versions remain unqualified.

## Conversion acceptance and fidelity

`SourceIdentity` links projected documents, sheets, slides, tables, images, and text to native IWA records. `SourceUnits` and `SourceUnitCounts` retain per-object outcomes and per-kind counts independently of payload preservation. They cover identified units selected by the semantic projection, including unsupported drawables and Numbers sheet references with unsupported native types. `UnsupportedObject` preserves their native identity when no recognized kind applies. Inactive templates, auxiliary table models/tiles, unresolved references, and unassessed content paths remain excluded. Text storages and repeated selected identities are deduplicated. Explicit selected-object omissions are distinguished from reconstructed objects; visual fallback leaves individual unit coverage unassessed. These counts do not establish field-level completeness or visual equivalence.

`SourceReferenceIssues` retains failed declared reference occurrences separately from the identified-object inventory. Coverage includes Pages body and decoded body attachment-table/drawable references, stacking-order, decoded floating-canvas, shape text-storage, section, declared header/footer template and header/footer storage references; Numbers document-sheet, sheet-drawable and shape text-storage references; and Keynote show, slide-tree-node, node-slide, slide-drawable, selected drawable text-storage, slide-note and note-storage references. Evidence distinguishes absent targets, malformed references and readable siblings in a rejected reference set, retaining owner identity, protobuf path, occurrence and an unambiguous target identifier when available. Existing targets whose native type is unsupported by the selected path use `UnexpectedTargetType`. This covers decoded paragraph, list, character and hyperlink attribute references, traversed style parents, and applicable table style, role and selected cell-style references. Character attributes accept both character and paragraph styles. Unselected catalog values and inapplicable roles remain outside this assessment. Repeated occurrences within a source field remain separate, while revisiting a shared archive reports each physical field once. These occurrences are not labelled omitted objects; visual fallback does not establish their coverage. Selected table-info/model, tile, row/column sizing-bucket, string/formula/rich-text catalog and selected rich-text wrapper/storage references are also assessed. Tile paths retain physical entry positions, excluding entries rejected before their target is read. Declared unresolved or malformed string/formula catalog links prevent complete editable reconstruction; valid cell caches remain recoverable through the explicit partial-conversion policy. Unreferenced templates, unused storage fallbacks and unparseable graph containers remain unassessed. `MaximumSourceReferenceIssues` bounds cumulative inspection of occurrences in distinct fields with failures, including readable siblings; the default is 100,000. `IWORK_SOURCE_REFERENCES_UNRESOLVED` retains category `Unassessed` in downstream fidelity reports.

`SourceDeclarationIssues` records unreadable, rejected or unsupported declarations separately from failed references and identified objects. Each item retains its owner, protobuf path, failure kind and known outer field-value count. A whole payload uses `$` and has no outer count; nested repeated entries use one-based positions. These counts do not reveal nested reference totals or omitted content. Coverage includes selected document roots, Pages body/shape/section/header/footer records and stacking/floating graph envelopes, Numbers sheet/plain-text record failures, Keynote show/tree/node/slide/drawable/note record failures, table-info/model/store/tile-list and row-header containers, selected string/formula/rich-text catalog envelopes and entry keys, plain-string values and formula-message envelopes, row/column sizing-bucket payloads and header metadata, selected merge-owner/store/pair/formula declarations, selected rich-text wrapper/storage records, decoded rich-text attribute containers and invalid entry positions, unreadable styles or style-parent envelopes actually traversed for text, and invalid values in supported character and paragraph properties, list label/type/indent vectors, style names and selected hyperlink text. Inactive records and unused rich-text value traversal are excluded. Other unsupported fields and remaining unmaterialized cell storage beyond the selected modern-row evidence remain coverage gaps. Shared paths report once per projection. `MaximumSourceDeclarationIssues` defaults to 100,000 and bounds distinct retained paths; evidence survives disabled source-payload preservation and visual fallback, with category `Unassessed` through `IWORK_SOURCE_DECLARATIONS_UNASSESSED`. Configured protobuf field, repeated-value and depth limits remain fatal; text-budget failures propagate rather than being reported as malformed declarations.

Modern row selection retains `InvalidValue` evidence at tile paths `5[n]/2` for a malformed, ambiguous or inconsistent declared cell count, and `5[n]/6` for a non-empty modern buffer with no selected offsets. A readable count is compared with selected physical cell records, including unformatted empty records that need no destination cell. An absent count remains supported. These paths describe outer field values, not missing-cell totals; no cell coordinates or formula presence are inferred from unselected bytes. Recoverable cells remain available through explicit partial conversion, while `IWORK_TABLE_ROW_STORAGE_UNASSESSED` reports `Unassessed` fidelity. Empty buffers with no selected offsets remain valid. Legacy companion buffers are not treated as unselected modern content when modern storage is present. Shared paths use the existing declaration budget and report once per projection.

`IWorkTableCell.UnsupportedFeatures` identifies selected modern conditional-style, applied-rule and unresolved or unsupported comment fields after complete cell decoding. Qualified root comments use `IWorkTableCell.Comment`; flagged fields remain unassessed. `None` does not establish complete cell fidelity. Cells with these features, including otherwise empty cells, remain materialized under `MaximumMaterializedCells`. Their row buffer retains `UnsupportedField` declaration evidence at tile path `5[n]/6`, deduplicated under the existing declaration budget; its outer count is not a cell, rule or comment count. `IWORK_TABLE_CELL_FEATURES_UNASSESSED` reports the number of affected selected cells as `Unassessed` and requires the existing partial-conversion policy to retain editable values. Reader retains the warning. Truncated cells keep decode-failure evidence instead of assessed feature presence. Unused feature catalogs, conditional-rule contents and remaining modern selectors stay outside this inventory.

Selected style-value failures use `InvalidValue` with their physical property path, such as `11/3` for font size, `11/7` or `11/26` for an unresolved foreground/background color value, `12/1` for alignment, `1/1` for a style name and `2` for hyperlink text. Counts describe that property’s outer values, including zero for missing required hyperlink text. Ambiguous Boolean values and clear-font/color selectors do not replace qualified inherited values. Rejected list vectors retain qualified parent metadata rather than removing invalid entries and shifting later levels. List evidence uses root fields `11` for label types, `13` for indents and `16` for labels; a packed label-type field counts as one outer value rather than its decoded element count.

Catalog keys are indexed before values are trusted. A malformed value with a readable, distinct key leaves healthy sibling values recoverable. Duplicate keys remain unresolved, including when a duplicate value is malformed; an unreadable entry or key leaves uniqueness unassessed and prevents resolving any catalog value. Formula cells retain valid caches when their expressions cannot be resolved. Catalog evidence uses `3[n]` for an unreadable physical entry, `3[n]/1` for key metadata, `3[n]/3` for invalid plain-string values (`InvalidValue`), and `3[n]/5` for rejected or unreadable formula messages. The catalog-entry budget includes unreadable entries. Rich-text value, wrapper, storage and style traversal stays limited to entries selected by decoded cells.

Sizing-bucket evidence uses `2[n]` for unreadable physical headers, `/1` for invalid or duplicate indexes, `/2` for invalid sizes, and `/3` for unsupported visibility values. `InvalidValue` covers size and visibility failures. An unknown index or unresolved bucket makes overrides on that axis untrusted, including overrides in other selected buckets; the other axis remains recoverable. Invalid values at readable, distinct indexes leave healthy sibling sizes available. Native zero continues to select the table default. Repeated bucket references retire their readable indexes while retaining unrelated overrides, and are reported at model path `4/1/2`; shared physical header paths report once. Explicit partial conversion retains recovered sizes using each destination owner's existing default and geometry rules.

Table-model hidden and filtered counts are assessed separately from dimension headers. Positive total hidden-row/column counts (`14`, `15`), filtered-row counts (`40`) and user-hidden row/column counts (`41`, `42`) retain `UnsupportedField` evidence at their model paths. Duplicate, wrong-wire or out-of-axis-bounds counts retain `InvalidValue` evidence. Absent counts and single correctly encoded zero values do not introduce a visibility warning. `IWORK_TABLE_VISIBILITY_UNASSESSED` reports `Unassessed` fidelity and requires explicit partial conversion for editable output; Reader keeps the warning because either route may include source-hidden content. Evidence uses the existing declaration budget, deduplicates shared model paths, and survives disabled source-payload preservation. Count values are not hidden-cell identities or omitted-content totals. Counts alone cannot reconstruct positions; qualified base states use the separate UUID mapping contract below. Zero counts do not prove hidden-state records empty.

Selected model hidden-state owners (`70`) are assessed independently of those counts. Paths `70/2[n]/2` and `/3` identify column and row extents; unresolved base (`2[m]`) user-hidden (`2`) selections, summary (`12[m]`) selections, and true filtered (`3`) or pivot-hidden (`4`) flags retain `UnsupportedField` evidence. Ambiguous/non-Boolean flags and invalid axis directions retain `InvalidValue` evidence. Malformed envelopes preserve their physical paths. Import-update flags and threshold/group/index payloads remain unassessed when selected. Model filter references (`38`) and extent filter references (`8`) retain unresolved-reference evidence; wrong-type or malformed filter targets retain whole-record declaration evidence. Enabled filters retain `UnsupportedField` evidence at filter path `2`; disabled filters do not select their rule/formula graphs. Empty extents and false flags add no visibility warning. `IWORK_TABLE_HIDDEN_STATES_UNASSESSED` reports `Unassessed` fidelity through conversion and Reader, requiring the existing partial policy for editable values. `MaximumTableDimensionEntries` charges owner/state/extent declarations, state entries, unqualified payloads and filter references before nested assessment; configured parser limits remain fatal. Shared declaration paths deduplicate under the existing evidence limit. Filtering, summary and pivot hiding, collapsed groups and Apple export equivalence remain unqualified. The [independent empty-state corpus](../OfficeIMO.TestAssets/Documents/IWorkCorpus/README.md#empty-hidden-state-extents-and-disabled-filters) qualifies the supported empty/disabled path only.

Base user-hidden states in a single state set resolve through model reference `46` to a `ColumnRowUIDMapArchive` (`6267`). The selected axis requires unique UUIDs and a complete permutation from UUID ordinals to zero-based positions; a supplied inverse vector must agree. Packed and unpacked indexes are supported. Missing, malformed, duplicate or ambiguous identities retire visibility recovery on the affected axis and retain declaration/reference evidence. Parser limits remain fatal. UUID declarations and decoded index vectors consume `MaximumTableDimensionEntries`. False states participate in identity validation when the axis selects a hidden position; inactive maps are not traversed.

`IWorkTable.HiddenRows` and `HiddenColumns` are immutable, sorted one-based positions. Values, styles and formula caches remain available, including after cross-table formula binding. XLSX applies the Excel owner’s row/column hiding APIs. Reader retains the complete bounded grid and emits `IWORK_READER_HIDDEN_TABLE_CONTENT_INCLUDED`. DOCX and PPTX table output requires explicit partial reconstruction, retaining visible content with `IWORK_PAGES_TABLE_VISIBILITY_OMITTED` or `IWORK_KEYNOTE_TABLE_VISIBILITY_OMITTED`; strict conversion uses visual fallback when available.

The [independent positive corpus](../OfficeIMO.TestAssets/Documents/IWorkCorpus/README.md#base-user-hidden-columns) qualifies six hidden columns across three tables whose legacy counts are all zero. Those columns contain empty cells. Positive rows, populated hidden cells and other iWork kinds have synthetic format-boundary proof; native export and rendered appearance equivalence remain open.

Merged-range evidence uses model paths `47` and `47/2` for rejected or unreadable owner/store messages, `47/2/3[n]` for unreadable physical pairs, and `47/2/3[n]/2` for formula declarations with unsupported bounds or conflicts. Counts describe the outer field at that path. Conflicting rectangles are all retired; disjoint, valid merges remain recoverable through explicit partial conversion. A decoded out-of-bounds rectangle disqualifies only intersecting merges and is never exported as a clipped merge. Exact valid duplicates normalize to one merge; every physical alias retains evidence when that merge conflicts. An unreadable range can conceal any overlap, so cells remain recoverable without applying merges. Configured pair, syntax-node, protobuf and evidence limits remain fatal. Destination guards still protect populated covered cells.

Selected native table tiles retain unreadable payloads as `$`, rejected row sets as `5`, and unreadable or invalid rows as `5[n]` using their physical one-based positions. Tile-list selection failures retain model paths `4/3/1[n]`. Invalid row indices, modern buffer/offset metadata and unsupported legacy storage retain row-level evidence without inventing cell counts. Readable sibling rows survive malformed entries; the table remains incomplete and requires explicit partial reconstruction for editable output. Shared tile paths report once per projection. Rejected envelope/count bounds are checked before nested rows are parsed; configured parser limits remain fatal on content actually parsed.

Pages body/shapes/headers/footers, Keynote drawable/note and selected table-cell rich text assess decoded paragraph, list, character-style and hyperlink table references and traversed style-parent references. Valid-offset decoded entries include end-of-text declarations; nested paths preserve physical entry positions. Only styles used for the decoded text are traversed. Invalid offsets and unparseable attribute containers remain unassessed. Numbers plain shape text does not assess formatting references. Rich-text catalogs retain bounded structural and duplicate-key validation across all declarations, then resolve text, styles and wrapper/storage references only for entries selected by decoded cells. Aliases share decoding; per-cell text use remains budgeted. Unused entries add no text materialization or reference evidence. Unparseable table containers and unsupported table/text/style fields stay open coverage gaps.

`FormulaCells` and `FormulaSummary` assess source formula expressions and recovered caches separately. A complete expression can have a partial or missing cache; a complete cache can accompany an unresolved expression. High-precision Decimal128 values and generic error markers are approximate caches. Supported version-5 cell headers with the formula flag retain known declarations even when value decoding fails. Those cells keep error output and have `ExpressionIsAssessed = false` and cache status `Unassessed`, with separate summary counts and fidelity diagnostic `IWORK_FORMULA_CELLS_UNASSESSED`. Unsupported versions, unreadable headers, inactive tables and unmaterialized cell storage remain outside this inventory. Existing materialized-cell budgets and cancellation bound the assessment. Evidence survives visual fallback and disabled source-record preservation; it does not establish destination formula retention, recalculation or cache freshness.

`AllowPartialEditableReconstruction` defaults to `false`. Enabling it retains recovered editable objects when supported source or destination details are incomplete. Source byte/materialization limits and destination bounds remain enforced. The report exposes `IsPartialEditableReconstruction`; `RequireCompleteEditableReconstruction()` rejects explicitly partial output. Pages can approximate positioned tables as flowing tables and round finite measurements to DOCX units under this policy. Keynote can retain slides while diagnosing paragraph pagination flags that PowerPoint cannot represent.

Numbers `NormalizeWorksheetNames` defaults to `false`. Enabling it uses the Excel owner's collision-safe normalization. `NumbersToExcelResult.WorksheetMappings` preserves source sheet/table ordinals and names beside destination names. Renames are typed approximations. Qualified finite rectangular references bind structurally to the actual worksheet names after normalization; formula labels are not rewritten by string replacement.

Numbers retains generic source error text when it has no known XLSX error mapping and emits `IWORK_NUMBERS_ERROR_VALUE_APPROXIMATED`. Formula expressions remain available, but generic error presentation does not establish equivalent Excel error semantics.

`SourceCellIssues` identifies materialized selected cells whose storage or value could not be decoded, with table identity, one-based coordinates and the decoding message. `IWorkTableCell.HasDecodeError` distinguishes these failures from recovered native `#ERROR` markers; it does not assess every field of a successfully decoded cell. The inventory survives visual fallback and disabled record preservation, stays within the source-wide materialized-cell budget and reports `Unassessed` through `IWORK_SOURCE_CELLS_UNDECODED`. Undecoded formula cells also retain their separate formula/cache assessment. Unreadable rows, rejected storage and inactive tables do not establish cell coordinates and add no guessed cell counts. These source assessments do not describe destination cell retention.

`IWorkDiagnostic.LossKind` separates proven omissions, approximations, failures, and information. Text content separately exposes `HasInvalidSourceText`, `HasUnresolvedInlineObjects`, and `IsFormattingComplete`; unresolved replacement markers are not labelled invalid UTF-8. `PreservedRecordCount` counts source records, while `UnassessedRecordCount` identifies the records without a field-level fidelity assessment. `IWORK_RECORD_FIDELITY_UNASSESSED` has category `Unassessed` and is rejected by `RequireNoLoss()`; it is not evidence that all source content was omitted.

## Visual fallback

`IWorkConversionOptions.Mode = IWorkConversionMode.Auto` uses editable reconstruction when supported semantics exist and otherwise uses an embedded raster preview. `EditableOnly` rejects sources without supported editable structure. `VisualOnly` always requests the raster preview. Set `RequireCompleteVisualCoverage = true` to reject a preview that is not known to cover the complete source. The default remains `false` for callers that explicitly accept first-page or composite preview output.

Every adapter report exposes `IWorkProjectionKind.EditableReconstruction` or `IWorkProjectionKind.VisualFallback`. `IWorkPreviewAsset.Coverage` distinguishes a known full-document asset from a first-page or composite preview. Current adapters embed PNG or JPEG previews; structurally validated classic-xref PDF previews remain available on the source model but are not silently rasterized. Xref-stream PDFs are rejected until their filtered cross-reference entries can be decoded and traversed within the same bounded contract.

## Intentional authoring boundary

OfficeIMO does not create, edit in place, or write `.pages`, `.numbers`, or `.key` files. Authoring remains deferred until a broader independently produced corpus can prove deterministic package reconstruction, unknown-record retention, reopen behavior in multiple iWork versions, and stable semantic and visual round trips. Save the editable projections as DOCX, XLSX, or PPTX instead.

### Table text defaults and selected styles

`IWorkTable.TextStyles` retains applicable body, header-row, header-column and footer-row paragraph defaults from table-model fields 24–27. `GetParagraphStyle(row, column)` resolves the effective style for a one-based cell without allocating a dense source grid: selected modern bit-6 text styles take precedence, followed by header row, header column, footer row and body. A selected unresolved style stays null rather than silently using a role default. Explicitly styled empty cells remain materialized; unselected empty cells remain sparse and can use role defaults.

Selected text keys use the same bounded style catalog as cell fills/layout. Only selected text references and applicable role references are traversed. The existing paragraph decoder resolves bounded inheritance, font size/family, emphasis, colors and supported paragraph alignment, indentation, spacing and pagination flags. Missing, ambiguous or unsupported declarations produce `IWORK_TABLE_TEXT_STYLE_UNSUPPORTED` with `Unassessed` fidelity and prevent complete editable reconstruction. Native list styles, tabs, line spacing, additional typography and full field fidelity remain unqualified.

The opt-in `extract-table-text-styles.py` uses pinned independent protobuf schemas to regenerate `table-text-styles.json`. It qualifies role declarations in the unchanged Keynote table fixture, 64 selected Pages text styles and 23 selected Numbers text styles. The Keynote table’s 32-point HelveticaNeue font, centered alignment and header emphasis survive saved/reopened PPTX. These source facts and first-party rendered output do not establish Apple export or complete appearance equivalence.

DOCX and PPTX apply supported fonts and paragraph formatting to plain and empty cells, with explicit rich-text formatting taking precedence. XLSX applies cell fonts and horizontal alignment while preserving numeric values and formula caches. XLSX reports unsupported paragraph layout, highlights or transparency as `IWORK_NUMBERS_TABLE_TEXT_STYLE_PARTIAL`. PPTX paragraph pagination flags require the explicit partial policy and produce `IWORK_KEYNOTE_PARAGRAPH_PAGINATION_OMITTED`; strict conversion uses fallback. Font sizes must fit each destination’s range and precision. Word’s partial policy permits half-point rounding with its precision diagnostic. XLSX default-style expansion is bounded to 100,000 cells per table and 1,000,000 cells per conversion. Reader reports style loss in plain-text tables.

### Table-cell comments

Selected modern bit-19 comments resolve through store field `19`, a type-6005 comment catalog (list kind 10), entry field `10`, a type-3056 root and its type-212 author. `IWorkTableCell.Comment` retains exact plain text, display author, UTC creation timestamp and both record identities. Native UUID metadata is shape-checked without mapping it to a destination ID. Author color and collaboration metadata are not projected. Otherwise empty commented cells remain materialized. Repeated uses charge the existing source-wide text and catalog budgets; malformed selected records retain declaration evidence and parser limits remain fatal.

Missing or rejected selected references retain model path `4/19`, catalog path `3[n]/10`, or comment path `3`; invalid text, date and UUID metadata use root paths `1`, `2` and `5`. Replies retain `UnsupportedField` at root path `4` and remain unqualified. Unused catalogs and unselected comment values are not traversed. Qualified roots do not set `UnsupportedFeatures.Comment`; unresolved and unsupported selections retain it and require explicit partial reconstruction for editable values.

XLSX preserves qualified root text, author, timestamp and cell address through the existing threaded-comment owner. Empty comment text, author normalization and case-colliding author names require destination fallback instead of silent rewriting. DOCX preserves roots through the Word batch comment owner with cell-scoped paragraph ranges, exact text, display author and UTC time, including empty commented cells. Text or author names that require normalization use destination fallback. Other layout and source limitations retain their conversion policy. PPTX table projections require partial reconstruction to omit comments and report `Omission`. Reader emits separate root-comment blocks, chunks and `table.comment` metadata with native identities, source table/cell anchors, exact text, author and UTC creation time. Its Markdown labels comments separately from table values. Qualified comments outside Reader row, column or dense-cell limits retain explicit omission counts. Three native roots are pinned in `cell-comments/native-roots.numbers`; the independent adjacent manifest verifies selected identities, text, author and timestamps, including Reader JSON transport and bounded NativeAOT output. Pages/Keynote root behavior has synthetic boundary proof; saved-and-reopened DOCX anchors have package validation. Replies, native Apple exports and rendered comment appearance remain unqualified.
