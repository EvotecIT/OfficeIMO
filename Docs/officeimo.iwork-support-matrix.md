# Apple iWork support

OfficeIMO reads modern IWA-based Pages, Numbers, and Keynote sources through the bounded `OfficeIMO.IWork` package. Opt-in adapter packages project supported semantics into the existing Word, Excel, and PowerPoint owners. Source snapshots remain immutable; separate native edit sessions preserve captured content and apply the bounded mutations below. The default destination packages do not depend on iWork.

The same package owns separate bounded native Keynote, Pages and Numbers creation models. Their scope and independent acceptance evidence are listed below; they do not edit loaded iWork sources.

The current level is **extended semantic reconstruction**. Normal document content becomes editable destination objects with recovered structure, typography, sizing, and geometry where the corpus proves those fields. It is not a pixel-identical renderer or a claim that every application-only feature can be translated.

## Public ownership

| Source | Typed source projection | Opt-in adapter | Entry points |
|---|---|---|---|
| Pages | `IWorkPagesProjection` | `OfficeIMO.Word.IWork` | `ToWordDocument`, `ToWordDocumentResult` |
| Numbers | `IWorkNumbersProjection` | `OfficeIMO.Excel.IWork` | `ToExcelDocument`, `ToExcelDocumentResult` |
| Keynote | `IWorkKeynoteProjection` | `OfficeIMO.PowerPoint.IWork` | `ToPowerPointPresentation`, `ToPowerPointPresentationResult` |

`IWorkSourceDocument.Open` is the shared loading and inspection entry point. It accepts paths, streams, and byte arrays; exposes normalized package entries, IWA payload records, producer build history, previews, diagnostics, and application-specific typed projections; and can be converted more than once with independent destination options. Adapter result APIs retain that same source model beside the generated Office document.

`OfficeIMO.Reader.IWork` registers directory bundles as individual documents. Path reading, async reading, folder ingestion, and discovery retain the package owner's bounds, physical-root checks, cancellation, and captured content hash. Resources inside a registered bundle are not ingested as separate documents. `ContainerLengthBytes` records ZIP bytes or physical bundle file bytes before nested expansion; `ComputePackageContentHash()` hashes the captured normalized entries and does not reopen the filesystem.

`OfficeIMO.Workflows.IWork` registers all three Apple-to-OOXML routes without adding iWork to the default workflow dependency graph. Local ZIP files, local directory packages, provider ZIP streams and provider directory packages use bounded captured inputs, destination reopen validation, source verification, and safe publication. Defaults reject explicitly partial editable reconstruction and visual previews without known complete coverage. `ConversionEvidence` retains typed fidelity categories and compact source/projection facts after destination disposal. Directory packages use a deterministic private ZIP transport snapshot, with package-root identity and file membership/content checked again before publication. Destinations inside the package or aliased to a package member are rejected. The snapshot checksum describes that transport archive. Provider directory intake uses `OfficeWorkflowDirectoryPackageInput` with a permission-aware identity/output-separation guard; the shared runner stages bounded member snapshots and verifies provider membership and bytes before publication. Native sandbox/bookmark acceptance remains separate. The CLI exposes these routes through `officeimo convert`. Studio uses the same runner for file-picker, drop, and startup intake, with per-job representation and acceptance settings, captured source SHA-256, retained fidelity evidence, and saved-output preview. These workflow settings are copied before asynchronous source capture.

## Native Keynote creation

`IWorkKeynoteDocument.Create` creates an owned, template-free `.key` package. `AddSlide`, `AddText`, `AddRichText`, `AddImage` and `AddTable` build static slides with opaque sRGB backgrounds, positioned text boxes, validated PNG/JPEG images and scalar tables. Immutable character runs retain their own font, size, color, bold, italic, single underline and single strikethrough, with explicit plain resets and UTF-16 range boundaries. Images snapshot their payload, retain PNG alpha and optional accessibility descriptions, and fill fixed frames, stretching when aspect ratios differ. Combined drawable insertion order determines stacking. `SaveBytes`, stream saves and atomic path saves accept cancellation and operation-level slide, text-box, character-run, UTF-16 text, image-count, aggregate encoded/RGBA image, table/grid-position and output/archive bounds. ZIP entry order and timestamps, object identities and archive bytes are deterministic for the same model, including across tested host timezones. There is no seed-file patching, external writer, OOXML projection or Apple runtime dependency.

Text frames use explicit finite geometry within the canvas, zero padding and left/top alignment. Tables snapshot a one-based scalar grid of up to 256 rows and 256 columns with equal dimensions, uniform text style, white fills, black one-point borders, four-point padding and top alignment. Native numbers use Decimal128 storage; booleans use their distinct native type. No shaping, measurement, automatic fit, embedded fonts, links, lists, table formulas/merges/header regions/per-cell formatting, image crops/masks/rotations/adjustments, transitions or builds are authored. Font substitution and wrapping belong to the receiving application. Loaded-source saving and image translations use the separate [native preservation profile](#native-source-preservation).

Native localized number/boolean display, font substitution and color emoji differ from the invariant/monochrome destination profile.

[`keynote-created-v15.4.json`](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/keynote-created-v15.4.json) records a three-slide C# output independently decoded through pinned protobuf schemas. ## Native Pages creation

`IWorkPagesDocument.Create` builds a template-free native `.pages` body document. The model owns finite page dimensions, four nonnegative body margins and insertion-ordered plain/rich paragraphs. Wider pages carry landscape orientation; margins must leave a positive body area. Paragraphs remain left-aligned with zero indents. Immutable `IWorkPagesParagraphLayout` supports positive relative spacing, nonnegative before/after spacing and sorted unique left/center/right/decimal tabs without leaders. Defaults are single spacing, zero paragraph spacing and a 36-point tab interval; custom layout uses a period decimal separator. The plain layout overload accepts TAB text. Immutable `IWorkTextRunData` snapshots retain fonts, point sizes, opaque sRGB colors and bold/italic/underline/strikethrough flags with explicit plain resets. Blank paragraphs retain their font metrics. Separate calls create separate paragraphs; public rich-run constructors reject TAB, line breaks, other control characters and invalid UTF-16.

The writer creates the document, section, required empty header/footer storages, theme presets, styles, object/reference envelopes and deterministic package. It reuses the shared native archive/package encoder and Core's ZIP/atomic-file owners. Operation-level paragraph/run/UTF-16-character/custom-tab/package limits and cancellation apply before output staging; stream saves leave their caller open. Stream copy failure can leave partial bytes. No seed archive, native application or new runtime dependency is required.

The [Pages creation reference](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/pages-created-v15.4.json) records independent pinned-schema decoding of all 189 objects, required fields, references, UTF-16 run offsets and hidden header/footer storages. Pages 15.4 opens the 83-paragraph document without repair. An edit from `reset` to `edited` survives native save, close and reopen; both exported PDF pages retain the requested formatting and complete flow. Strict saved/reopened OfficeIMO DOCX retains the source text, character styles and page settings. Apple's DOCX export agrees on all 83 authored paragraphs and page geometry but changes selected font runs and bold/italic overrides; equivalent native DOCX typography is unqualified. The terminating LF also projects an empty trailing paragraph, retained by OfficeIMO.

The same reference includes a custom landscape document opened by Pages and exported to a one-page 792-by-612-point PDF. Its left and top text bounds agree with the requested 36- and 45-point body margins.

The [paragraph-layout reference](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/pages-created-layout-v15.4.json) independently decodes a 37-object, seven-paragraph creation with relative spacing 1.25/1.5/2, before/after spacing, all four tab alignments, blank metrics and mixed-run/default resets. Pages 15.4 accepts its native text edit, save and close/reopen; all one-page PDF content is inspected. Native-saved source decoding and strict saved/reopened OfficeIMO DOCX agree with Apple's DOCX text, spacing and custom tab positions. Explicit period/comma source decimal symbols are retained on `IWorkParagraphStyle.DecimalTabSymbol`; uniform active DOCX decimal tabs use that document setting, while differing or mixed specified/unspecified symbols require destination fallback. PPTX reports an explicit separator omission and requires partial acceptance. Pages 15.4's import of the OfficeIMO DOCX retains all content and 74 matching word bounds, but places `123.45` 15.0146 points left of its native source despite the stored period setting. DOCX decimal-tab rendered equivalence remains unqualified.

Decimal-tab acceptance uses effective paragraph overrides and table-cell defaults. Empty tab overrides, explicit separator clears and covered merged cells do not introduce inactive symbols into destination assessment. Word's PDF owner carries the document separator into body and table-cell tab stops; an explicit period or comma ignores grouping punctuation and right-aligns a value without that separator. Focused rendered regression checks cover both symbols, grouped values and values without a decimal separator. These checks qualify the managed rendering contract separately from the Apple DOCX reimport comparison.

The receiving application selects fonts and paginates. This creation profile does not measure text, embed fonts, author lists/tables/images/custom headers or footers, author additional section layouts, or edit loaded packages. Other application versions, fonts, scripts, pagination contexts and runtime architectures need their own qualification.

Its [composed PDF evidence](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/pages-created-layout-v15.4.json) retains all 75 native words in order and reconstructs eight selected source paragraphs with no omitted or unassessed content units. The complete page is inspected for spacing, custom tabs, blank height and rich/default resets. The portable profile reports Arial-to-Helvetica substitution; native typography, emoji appearance and pagination equivalence remain separate qualification boundaries.

The [macOS arm64 NativeAOT receipt](Compatibility/iwork-pages-paragraph-layout-native-aot-macos-arm64-2026-10-10.json) records actual .NET 8 and .NET 10 execution of this deterministic paragraph profile, strict saved/reopened DOCX and custom-tab bounds alongside the existing creation and preservation profiles. Composed PDF, other architectures and signed sandbox/device acceptance retain their separate qualification gates.

## Native Numbers creation

`IWorkNumbersDocument.Create`, `AddSheet` and sheet `AddTable` author an owned, template-free `.numbers` spreadsheet with named sheets and positioned scalar tables. Names are unique without regard to case within their document/sheet scope, contain at most 128 UTF-16 units and reject control characters. Each sheet requires at least one table. Tables snapshot the shared one-based `IWorkTableData` grid, with 1–256 rows/columns, equally sized positive dimensions, finite positions, a uniform requested font/size/opaque color, white fills, black one-point borders, wrapping and four-point padding. Strings, finite Decimal128 numbers, booleans and completely unset grids retain their distinct native storage. Leading `=` text is literal.

The separate Numbers document/sheet/sidebar and calculation-metadata adapter reuses shared native table, style, archive/Snappy, deterministic ZIP and Core atomic-publication codecs. It writes the modern TSK custom-format-list reference in TSA field 12; legacy field 7 refers to a different native class. Hidden headers/footers retain all six required blank storages per sheet. No seed archive, native application or new runtime dependency is required. Operation-level sheet/table/dense-cell/UTF-16-name-and-text/package bounds and cancellation apply before output staging; caller streams remain open, while copy failures can leave partial stream bytes. Path staging preserves an existing destination on failure.

The [Numbers creation reference](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/numbers-created-v14.5.json) pins the 22,090-byte two-sheet/three-table package and independent decoding of all 108 required-field and reference-complete records. Numbers 14.5 opens without repair; a numeric edit survives native save, close/reopen and PDF/XLSX export. Both sheets and PDF pages are inspected. Native saved-source readback has no declaration/reference issues or projection diagnostics. Strict saved/reopened OfficeIMO XLSX agrees with Apple's populated-table typed values and retains the completely empty 2-by-3 grid. Apple's empty-table export uses B2:D3 instead of the adapter's A1:C2; exact Excel placement and appearance are unqualified. Formula authoring, selected formats, comments, merges, header regions, rich cell text, other drawables and loaded-source editing remain unsupported. Other versions, fonts, scripts and layout/runtime profiles need separate qualification.

## Native source preservation

`IWorkSourceDocument.BeginEdit()` starts a separate native edit session over an immutable captured source. Unchanged byte, stream and atomic path saves retain every physical file-entry payload for modern Pages, Numbers and Keynote ZIP/directory packages. Nested `Index.zip` remains byte-identical inside the output carrier. Unknown records and fields, auxiliary payloads, IDs, references, version fields, resources and previews survive unchanged. Conversion-report `PreserveSourceRecords` does not disable this native preservation contract. Normalized package content hashes agree for unchanged saves.

The ZIP carrier uses deterministic stored entries. Its compression, timestamps, extra fields, comments, directory entries and filesystem metadata are not retained. The report describes these carrier changes separately from semantic conversion fidelity. Package/input-entry bytes, changed-archive decompressed bytes and edited-record counts are bounded. Encoding precedes destination writes; caller streams remain open, and atomic path saves preserve an existing destination on failure. A directory source's own members and aliases cannot be publication targets.

`MoveKeynoteImage` changes only the two existing position floats of one selected primary image record. The image must be a direct unlocked, unrotated, unmasked slide child with complete geometry and a known canvas, and its entire frame must fit at the new finite nonnegative coordinates. Native ArchiveInfo/MessageInfo bytes, sibling payloads, payload lengths, image resources, dimensions, IDs and references remain intact. The original snapshot is unchanged. Restoring original coordinates removes the pending edit. Other semantic/structural changes and nested-index mutations are unsupported.

Every edited save requires explicit `AllowUnassessedVisualCaches`. Native previews and visual caches remain captured without regeneration; wider application metadata is not assessed. `IWORK_NATIVE_VISUAL_CACHES_UNASSESSED` records this boundary as `Unassessed`, including for a fixture that passes native reopen. No-op saves preserve their existing caches and need no such acceptance.

The [native preservation reference](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/native-preservation-macos.json) independently compares every file-entry payload and all raw IWA headers/siblings for Apple-saved Pages, Numbers and Keynote inputs. Keynote translation changes only record 154's position bytes, from 80/120 to 100/130 points. Keynote 15.4 opens that output without repair, changes X to 101, and retains 101/130 and the 600-by-240 frame after native save/close/reopen. Image resources are unchanged, and all three native PDF slides are inspected. Unchanged saves open in Pages 15.4, Numbers 14.5 and Keynote 15.4; the two-page body through paragraph 80, all two sheets/three tables, typed cell content and original Keynote geometry are observed. Apple may update its own view state when opening a package; the byte-preservation comparison applies to the OfficeIMO encoding before that application opens it. Other application versions, fonts, cache consumers and wider edits are unqualified.

## Package and IWA boundary

| Capability | Current contract |
|---|---|
| Containers | ZIP packages, directory bundles, and packages with nested `Index.zip` |
| Package safety | Configurable package, entry, entry-count, aggregate-uncompressed-size, and path bounds; top-level package paths and directory entries must be regular files rather than links, pipes, or devices; duplicate, absolute, traversal, and empty-segment paths are rejected; directory reads verify the opened regular-file handle remains under the captured physical package root |
| IWA framing | Raw Snappy chunks used by modern iWork, with declared-size, chunk-size, aggregate-size, copy-offset, truncation, and integer-overflow checks |
| Object envelope | Bounded ArchiveInfo and MessageInfo protobuf parsing with field-count, depth, record-count, record-size, wire-type, varint, reference, and unique primary-object validation |
| Preservation | Defensive access to all package entries and all primary or auxiliary IWA payloads; conversion reports retain source payloads for inspection through `PreservedRecords`, including consumed, partially consumed, and auxiliary records; this count does not measure omitted content |
| Active content | No macros, scripts, external links, embedded executables, or application services are executed |
| Legacy packages | Pre-IWA `index.xml` and `index.apxl` packages are rejected as unsupported rather than guessed |

Public source and adapter path/stream APIs accept cancellation; source byte-array loading accepts it as well. The source token governs subsequent projections and conversions. `source.WithCancellation(token)` shares the loaded source and parsed-message cache with an independent replacement token; it permits reuse after the original token is cancelled. Destination construction checks cancellation between objects, cells, paragraphs, and runs and disposes a partially constructed destination on failure. Caller-owned streams remain open. Fixed cancellation latency, allocation, and retained-memory budgets remain unqualified. The opt-in [runtime evidence lane](../OfficeIMO.IWork.Benchmarks/README.md) measures synthetic scale workloads and hash-pinned native fixtures, with complete saved-package semantic readback. The [portable run](benchmarks/officeimo.iwork-portable-runtime-2026-10-04.md) records 6,390 validated samples on Linux x64, macOS arm64 and Windows x64, including repeated managed baselines, sampled managed/resident changes and active I/O cancellation. Sampled maxima are lower bounds on peaks; the observations do not establish attributed native-memory retention, portable ceilings or native appearance.

`IWorkReadOptions` supplies source-reading and semantic-projection limits. `IWorkConversionOptions` independently chooses automatic, editable-only, or visual-only destination representation. Defaults cap a package and aggregate expanded entries at 512 MiB, one entry at 128 MiB, one compressed IWA archive at 64 MiB, one decompressed archive at 256 MiB, all decompressed IWA archives at 512 MiB, one Snappy chunk at 64 MiB, one record at 128 MiB, the source-wide record count at 1,000,000, and combined ArchiveInfo version/reference values at 8,000,000. Semantic projection also bounds decoded and destination-expanded text characters, including repeated shared strings, font families, list labels, and hyperlinks; text items and attribute boundaries; cross-record style inheritance; sparse materialized cells; string/formula catalogs; source-wide formula rendering work including repeated formula uses; tables; projected images; merged ranges; table dimensions; Numbers sheets; and Keynote slides. Word and PowerPoint owner preflight additionally bounds the aggregate destination table-cell area before allocating editable table grids.

## Native lifecycle boundaries

OfficeIMO creates `.key`, `.pages` and `.numbers` files through separate [Keynote](#native-keynote-creation), [Pages](#native-pages-creation) and [Numbers](#native-numbers-creation) models. The [native preservation profile](#native-source-preservation) separately saves captured sources and translates qualified direct Keynote images. It does not provide general Pages/Numbers semantic editing, Keynote text/table/structural editing, or native visual-cache regeneration. Broader creation and edited-source preservation follow the independent decoding, native reopen/edit/export and operation-level loss requirements in [I6](ROADMAP.md#i6-native-creation-and-lifecycle).

### Table text defaults and selected styles

`IWorkTable.TextStyles` retains applicable body, header-row, header-column and footer-row paragraph defaults from table-model fields 24–27. `GetParagraphStyle(row, column)` resolves the effective style for a one-based cell without allocating a dense source grid: selected modern bit-6 text styles take precedence, followed by header row, header column, footer row and body. A selected unresolved style stays null rather than silently using a role default. Explicitly styled empty cells remain materialized; unselected empty cells remain sparse and can use role defaults.

Selected text keys use the same bounded style catalog as cell fills/layout. Only selected text references and applicable role references are traversed. The existing paragraph decoder resolves bounded inheritance, font size/family, emphasis, colors and supported paragraph alignment, indentation, spacing and pagination flags. Missing, ambiguous or unsupported declarations produce `IWORK_TABLE_TEXT_STYLE_UNSUPPORTED` with `Unassessed` fidelity and prevent complete editable reconstruction. Native list styles, non-single XLSX paragraph spacing, nonempty XLSX custom tabs, additional typography and full field fidelity remain unqualified. The shared paragraph decoder qualifies empty spacing/tab defaults as described above.

The opt-in `extract-table-text-styles.py` uses pinned independent protobuf schemas to regenerate `table-text-styles.json`. It qualifies role declarations in the unchanged Keynote table fixture, 64 selected Pages text styles and 23 selected Numbers text styles. The Keynote table’s 32-point HelveticaNeue font, centered alignment and header emphasis survive saved/reopened PPTX. These source facts and first-party rendered output do not establish Apple export or complete appearance equivalence.

DOCX and PPTX apply supported fonts and paragraph formatting to plain and empty cells, with explicit rich-text formatting taking precedence. XLSX applies cell fonts and horizontal alignment while preserving numeric values and formula caches. Natural left-to-right alignment maps to General, allowing numbers to align right and text left as in the native Numbers export; right-to-left text retains right alignment.
