# Apple iWork support

OfficeIMO reads modern IWA-based Pages, Numbers, and Keynote sources through the bounded `OfficeIMO.IWork` package. Opt-in adapter packages project supported semantics into the existing Word, Excel, and PowerPoint owners. Source snapshots remain immutable; separate native edit sessions preserve captured content and apply the bounded mutations below. The default destination packages do not depend on iWork.

The same package owns separate bounded native Keynote, Pages and Numbers creation models. Their scope and independent acceptance evidence are listed below; they do not edit loaded iWork sources.

The current level is **extended semantic reconstruction**. Normal document content becomes editable destination objects with recovered structure, typography, sizing, and geometry where the corpus proves those fields. It is not a pixel-identical renderer or a claim that every application-only feature can be translated.

## Public ownership

| Source | Typed source projection | Opt-in adapter | Entry points |
|---|---|---|---|
| Pages | `IWorkPagesProjection` | `OfficeIMO.Word.IWork` | `ToWordDocument`, `ToWordDocumentResult` |
| Numbers | `IWorkNumbersProjection` | `OfficeIMO.Excel.IWork` | `ToExcelDocument`, `ToExcelDocumentResult` |
| Keynote | `IWorkKeynoteProjection` | `OfficeIMO.PowerPoint.IWork` | `ToPowerPointDocument`, `ToPowerPointDocumentResult` |

`IWorkSourceDocument.Open` is the shared loading and inspection entry point. It accepts paths, streams, and byte arrays; exposes normalized package entries, IWA payload records, producer build history, previews, diagnostics, and application-specific typed projections; and can be converted more than once with independent destination options. Adapter result APIs retain that same source model beside the generated Office document.

`OfficeIMO.Reader.IWork` registers directory bundles as individual documents. Path reading, async reading, folder ingestion, and discovery retain the package owner's bounds, physical-root checks, cancellation, and captured content hash. Resources inside a registered bundle are not ingested as separate documents. `ContainerLengthBytes` records ZIP bytes or physical bundle file bytes before nested expansion; `ComputePackageContentHash()` hashes the captured normalized entries and does not reopen the filesystem.

`OfficeIMO.Workflows.IWork` registers all three Apple-to-OOXML routes without adding iWork to the default workflow dependency graph. Local ZIP files, local directory packages, provider ZIP streams and provider directory packages use bounded captured inputs, destination reopen validation, source verification, and safe publication. Defaults reject explicitly partial editable reconstruction and visual previews without known complete coverage. `ConversionEvidence` retains typed fidelity categories and compact source/projection facts after destination disposal. Directory packages use a deterministic private ZIP transport snapshot, with package-root identity and file membership/content checked again before publication. Destinations inside the package or aliased to a package member are rejected. The snapshot checksum describes that transport archive. Provider directory intake uses `OfficeWorkflowDirectoryPackageInput` with a permission-aware identity/output-separation guard; the shared runner stages bounded member snapshots and verifies provider membership and bytes before publication. Native sandbox/bookmark acceptance remains separate. The CLI exposes these routes through `officeimo convert`. Studio uses the same runner for file-picker, drop, and startup intake, with per-job representation and acceptance settings, captured source SHA-256, retained fidelity evidence, and saved-output preview. These workflow settings are copied before asynchronous source capture.

## Native Keynote creation

`IWorkKeynoteDocument.Create` creates an owned, template-free `.key` package. `AddSlide`, `AddText`, `AddRichText`, `AddImage` and `AddTable` build static slides with opaque sRGB backgrounds, positioned text boxes, validated PNG/JPEG images and scalar tables. Immutable character runs retain their own font, size, color, bold, italic, single underline and single strikethrough, with explicit plain resets and UTF-16 range boundaries. Images snapshot their payload, retain PNG alpha and optional accessibility descriptions, and fill fixed frames, stretching when aspect ratios differ. Combined drawable insertion order determines stacking. `SaveBytes`, stream saves and atomic path saves accept cancellation and operation-level slide, text-box, character-run, UTF-16 text, image-count, aggregate encoded/RGBA image, table/grid-position and output/archive bounds. ZIP entry order and timestamps, object identities and archive bytes are deterministic for the same model, including across tested host timezones. There is no seed-file patching, external writer, OOXML projection or Apple runtime dependency.

Text frames use explicit finite geometry within the canvas, zero padding and left/top alignment. Tables snapshot a one-based scalar grid of up to 256 rows and 256 columns with equal dimensions, uniform text style, white fills, black one-point borders, four-point padding and top alignment. Native numbers use Decimal128 storage; booleans use their distinct native type. No shaping, measurement, automatic fit, embedded fonts, links, lists, table formulas/merges/header regions/per-cell fonts/fills/borders, image crops/masks/rotations/adjustments, transitions or builds are authored. Font substitution and wrapping belong to the receiving application. Loaded-source saving and image translations use the separate [native preservation profile](#native-source-preservation).

## Native Pages creation

`IWorkPagesDocument.Create` builds a template-free native `.pages` body document. The model owns finite page dimensions, four nonnegative body margins and insertion-ordered plain/rich paragraphs, inline PNG/JPEG images and scalar tables. Wider pages carry landscape orientation; margins must leave a positive body area. Paragraphs remain left-aligned with zero indents. Immutable `IWorkPagesParagraphLayout` supports positive relative spacing, nonnegative before/after spacing and sorted unique left/center/right/decimal tabs without leaders. Defaults are single spacing, zero paragraph spacing and a 36-point tab interval; custom layout uses a period decimal separator. The plain layout overload accepts TAB text. Immutable `IWorkTextRunData` snapshots retain fonts, point sizes, opaque sRGB colors and bold/italic/underline/strikethrough flags with explicit plain resets. Blank paragraphs retain their font metrics. Separate calls create separate paragraphs; public rich-run constructors reject TAB, line breaks, other control characters and invalid UTF-16.

`SetHeader` and `SetFooter` author one left-aligned paragraph for every page in the single section. Each accepts one immutable character run or plain text with font/size/color arguments. Nonnegative edge distances must lie inside the corresponding body margin; zero-length text, tabs and line breaks are rejected. Styled zero-length paragraphs are outside this profile because projection does not retain their paragraph formatting. Native wrapping depends on fonts and available width. Clearing an area disables it and restores its blank storage.

The writer creates the document, section, all six required header/footer storages, theme presets, styles, object/reference envelopes and deterministic package. It reuses the shared native archive/package encoder and Core's ZIP/atomic-file owners. Operation-level paragraph/run/image/encoded-and-decoded-image-byte/table/dense-cell/UTF-16-character/custom-tab/package limits and cancellation apply before output staging. Header/footer text shares the paragraph, run and character budgets. Stream saves leave their caller open; stream copy failure can leave partial bytes. No seed archive, native application or new runtime dependency is required.

## Native Numbers creation

`IWorkNumbersDocument.Create`, `AddSheet` and sheet `AddTable` author an owned, template-free `.numbers` spreadsheet with named sheets and positioned scalar tables. Names are unique without regard to case within their document/sheet scope, contain at most 128 UTF-16 units and reject control characters. Each sheet requires at least one table. Tables snapshot the shared one-based `IWorkTableData` grid, with 1–256 rows/columns, equally sized positive dimensions, finite positions, a uniform requested font/size/opaque color, white fills, black one-point borders, wrapping and four-point padding. Strings, finite Decimal128 numbers, booleans and completely unset grids retain their distinct native storage. Leading `=` text is literal.

The separate Numbers document/sheet/sidebar and calculation-metadata adapter reuses shared native table, style, archive/Snappy, deterministic ZIP and Core atomic-publication codecs. It writes the modern TSK custom-format-list reference in TSA field 12; legacy field 7 refers to a different native class. Hidden headers/footers retain all six required blank storages per sheet. No seed archive, native application or new runtime dependency is required. Operation-level sheet/table/dense-cell/UTF-16-name-and-text/package bounds and cancellation apply before output staging; caller streams remain open, while copy failures can leave partial stream bytes. Path staging preserves an existing destination on failure.

The [Numbers calculation reference](../OfficeIMO.TestAssets/Documents/IWorkCorpus/native-exports/numbers-created-calculation-v14.5.json) qualifies the current two-sheet/three-table codec. Its 22,573-byte scalar example and 22,574-byte numeric-reference input each contain 111 independently decoded, required-field and reference-complete records. ## Native numeric table formats

`IWorkTableData.SetNumber(row, column, value, format)` applies immutable `IWorkNumberFormat` metadata to new Pages, Numbers and Keynote tables. `CreateNumber` and `CreatePercentage` support explicit precision 0–30, grouping and all four negative styles. `CreateScientific` supports explicit mantissa precision 0–30 with minus negatives and no grouping. Automatic, currency, fraction, temporal, custom and locale-specific formats remain outside creation. The scalar remains a finite double; formatting does not increase its precision. Replacing a cell without a format clears its selection, while added tables retain their snapshots.

### Pages alternate text-storage recovery

When a selected Pages shape declares two single, resolved storage references and exactly one targets text storage, the reader retains that text and reports the other target as `UnexpectedTargetType`. Automatic conversion still uses the preview fallback; explicit partial editable conversion preserves the recovered text box through saved/reopened DOCX.
