# OfficeIMO.Bibliography support matrix

This matrix defines the current `OfficeIMO.Bibliography` data, preservation, conversion, and managed CSL rendering contract. Remote metadata lookup, library synchronization, attachments, Word integration, scripting, DRM, and encrypted-resource handling are outside this package.

## Format lifecycle

| Format | Create | Read | Edit | Deterministic write | Reopen output | Exact unchanged source |
| --- | --- | --- | --- | --- | --- | --- |
| BibTeX | Yes | Yes | Yes | Yes | Yes | Text and loaded bytes |
| BibLaTeX | Yes | Yes | Yes | Yes | Yes | Text and loaded bytes |
| CSL JSON | Yes | Yes | Yes | Yes | Yes | Text and loaded bytes |
| RIS | Yes | Yes | Yes | Yes | Yes | Text and loaded bytes |
| NBIB/MEDLINE | Yes | Yes | Yes | Yes | Yes | Text and loaded bytes |
| EndNote XML | Yes | Yes | Yes | Yes | Yes | Text and loaded bytes |

`.bib` paths default to BibLaTeX because the extension cannot distinguish the two profiles. Callers can select `BibliographyFormat.BibTex` explicitly when classic BibTeX output is required.

## Typed model

| Capability | Contract |
| --- | --- |
| Identity | Stable citation key plus original native item type; deterministic generated and destination-normalized keys avoid collisions with supplied keys |
| Item kind | All 45 standard CSL item types have typed values, including legal, audiovisual, performance, reference-work, review, and post types; proceedings remain a separate format-neutral kind with explicit CSL conversion loss |
| Contributors | Ordered personal or literal organization names with all 26 standard CSL roles, plus `Other`; destination formats diagnose roles outside their supported vocabulary |
| Names | Given, family, literal, suffix, dropping-particle, and non-dropping-particle components; family-only multiword names and literal names ending in commas reopen without changing shape; surrounding or repeated component whitespace, a suffix without its required given-name position, and empty or entirely unset names that a non-CSL destination would normalize are diagnosed before strict output |
| Dates | Ordered partial, literal, or ranged issued, accessed, submitted, original, event, available, and other dates; incomplete numeric sequences, null-valued empty dates, and literal-date whitespace are diagnosed when a destination cannot preserve their distinction |
| Identifiers | Ordered scheme/value pairs, including DOI, ISBN, ISSN, PMID, PMCID, and source-specific schemes; destination-specific scheme spelling changes are diagnosed before strict output |
| Publication data | Title, container and collection titles, publisher and place, edition, volume, issue, pages, abstract, language, and URL |
| Repeatable values | Contributors, dates, identifiers, keywords, notes, and native fields preserve order |
| Extensions | Unknown record, CSL name, and CSL date fields remain in their owning `NativeFields`; document directives remain in `BibliographyDocument.NativeEntries` where supported |

## Native parsing and canonical writing

| Format | Native behavior and known limits |
| --- | --- |
| BibTeX/BibLaTeX | Reads braced, quoted, numeric, identifier, nested-brace, and `#`-concatenated values. Retains unknown fields, `@string`, `@preamble`, `@comment`, and top-level `%` comments. Native item-type, identifier-scheme field casing, unknown-field spelling, parsed empty keyword entries and positions, keyword delimiters and surrounding whitespace, classic BibTeX month-only dates, positive source years beyond four digits, empty literal years, and the relative order of supported BibLaTeX date roles survive canonical output, and malformed fields recover at the next safe field boundary with diagnostics. Contributor name lists recognize top-level `and` separators delimited by any Bib whitespace; names with surplus top-level comma segments retain their complete source field and are reported as recovered loss before canonical output. Diagnostic line and column locations recognize LF, CRLF, and CR-only sources. Retained duplicate typed fields are diagnosed if an edit would promote them into the typed model. Issued dates with no numeric parts and a null literal, which classic BibTeX cannot express, are diagnosed before strict output. Odd terminal backslash runs are normalized with a loss diagnostic so they cannot escape writer-added delimiters, and unsafe post-escape values are omitted rather than producing malformed records. Per-value and cumulative string expansion are bounded and non-executing; large name-list and citation-key scans avoid per-character substring allocation and observe cancellation. Structured name components containing BibTeX separators such as top-level commas or `and` are diagnosed as lossy before strict output. Canonical writing does not evaluate TeX macros. |
| CSL JSON | Reads a single item object or item array. Known scalar properties become typed values when their JSON shape is a string. A numeric `id` also becomes a citation key while its numeric JSON representation is retained for same-format output. Other numeric, Boolean, null, object, and array shapes remain raw native JSON for exact same-format output. Recognized native type spelling, cross-format unknown native type strings, typed identifier value whitespace, blank identifier properties, empty recognized contributor arrays, signed integer date parts, and safe edited aggregate-native JSON formatting survive canonical output when their emitted CSL shape reopens exactly with default read limits. A native type is accepted as exact only when both the emitted spelling and parsed typed item kind reconstruct the current public values; unpreservable non-null native type values are diagnosed before strict output. Native JSON nesting is bounded to leave room for its item, name, or date owner inside the default 128-level destination read depth; deeper values are diagnosed and emitted as strings only in permissive output. Direct root-array values that are not item objects count toward the value limit before JSON DOM materialization. Incomplete numeric date sequences whose month, day, or range components lack their required owner, and numeric months or days outside the typed model's documented ranges, remain native JSON with diagnostics; model-created out-of-range month or day values are likewise diagnosed before strict output. Blank keyword values remain distinct from an absent keyword list. Escaped string values are bounded by decoded UTF-16 length rather than their JSON escape syntax, limit diagnostics use zero-based UTF-16 source offsets across LF, CRLF, and CR-only input, and token, malformed-input location, and post-materialization contributor/date projection scans observe cancellation between bounded input segments. Invalid UTF-16 input is rejected instead of being replaced during UTF-8 conversion. Invalid UTF-16 introduced through model edits is diagnosed before CSL JSON serialization, replaced in permissive output, and rejected by strict no-loss writes. Unknown properties are likewise preserved as raw JSON values. Retained duplicates are diagnosed if an edit would move them from native storage into a typed scalar, contributor, or date owner. JSON comments and trailing commas are accepted but normalized. CSL JSON is treated as an interchange shape; the external CSL schema remains the authority for a consumer's chosen profile. |
| RIS | Reads ordered tags, repeated tags, records delimited by `TY`/`ER`, and continuation lines. Recognized native type spelling, blank identifier tags, native extension-tag casing, qualified accession value whitespace, positive source years beyond four digits, and issued or accessed date ranges survive same-format canonical edits. Identifier continuations bind to the identifier created by their immediately preceding `DO`, `SN`, or `AN` tag; a continuation that supplies the value for an initially blank identifier tag promotes it to the same typed owner, and a later accession cannot change a key sourced from an earlier accession. Recognized type tokens that require normalization are diagnosed before strict output. Blank source date literals remain distinct from absent dates; model-created null-valued empty dates and blank native name/date tags that would bind into typed owners on reopen are diagnosed before strict output. Nonempty `ER` payloads are diagnosed as recovered source loss. Single start-page and end-page tags retain their distinct roles through canonical edits. Retained repeated scalar tags are diagnosed if clearing their typed owner would promote the retained value. Explicitly empty unsupported model properties are diagnosed before strict output rather than being silently normalized to null. Per-value and accumulated continuation limits are enforced before materialization, and canonical value normalization and continuation emission observe cancellation in bounded chunks. Unknown safe two-to-five-character tags survive same-format canonical output. |
| NBIB/MEDLINE | Reads four-character-style tags, repeated fields, continuation lines, blank-record boundaries, PMID identity, and bracket-qualified identifiers such as DOI. Automatic detection recognizes canonical leading NBIB tags before `PMID`. Qualified identifier-scheme casing, native extension-tag casing, blank `IS` serial-identifier tags, positive source years beyond four digits, issued date ranges, and the relative order of retained publication types and extension tags survive same-format canonical edits. A continuation that supplies the value for an initially blank `IS`, `LID`, or `AID` identifier tag promotes it to the same typed owner. Continued publication types update explicit first-recognized-type state from the complete value without rescanning earlier `PT` fields; recognized retained types that conflict with an edited typed kind are diagnosed before omission, while a source with no recognized publication type does not gain a synthetic `PT` tag. An unknown typed item cannot use an unrecognized retained `PT` value as exact round-trip evidence because NBIB reopens that record with the journal-article fallback. Compact/full author pairing is cancellation-aware, Unicode-scalar-safe, and indexed by normalized compact name. Retained repeated scalar tags are diagnosed if clearing their typed owner would promote the retained value. Explicitly empty unsupported model properties are diagnosed before strict output rather than being silently normalized to null. Per-value and accumulated continuation limits are enforced before materialization, and canonical value normalization and continuation emission observe cancellation in bounded chunks. Unknown safe tags survive same-format canonical output. |
| EndNote XML | Reads record numbers and types, contributors, titles, dates, identifiers, publication fields, URLs, keywords, notes, and unknown record elements. Numeric-only recognized reference-type codes map to their typed kinds; unsupported, nonnumeric, or conflicting numeric codes paired with named types are diagnosed before strict canonical output. Automatic detection accepts `xml`, direct `records`, and other root names with an immediate same-namespace `records` container, matching the explicit codec and enforcing the configured nesting limit while scanning custom roots. Recognized and unknown native type aliases, accepted root, records-container, and record element names and prefixes, identifier-scheme casing, positive source years beyond four digits, empty or whitespace-only recognized record-level containers, empty issued dates, distinct nonnumeric or blank year/publication-date components (including year-only carriers), blank notes, empty primary URLs, empty identifier elements, blank or redundant secondary/periodical title representations, the source order of retained direct-record native fields—including additional related URLs—and interleaved namespace and ordinary attribute carriers survive same-format canonical edits. Namespace prefixes inherited by records containers, records, and their namespaced attributes remain attached to their metadata carriers and survive canonical edits. Empty recognized nested groups mixed with typed siblings are retained as source evidence and diagnosed before strict canonical output. Case-variant `name` and `type` attributes are retained as unsupported native XML and diagnosed when a typed owner prevents exact canonical output. Conflicting recognized type names and numeric type codes are diagnosed as recovered source loss before strict output. Duplicate root, records-container, or per-record attribute carriers are diagnosed before additional entries are omitted or coalesced. Attribute carriers are preserved only when their wrapper names match the root, records container, or record they describe and the wrapper contains no text or child elements. Literal tabs and line breaks in attribute values on carriers and safe extension elements are diagnosed because XML normalizes them to spaces. PMID scheme identity is not representable by the accession element and is diagnosed before strict output rather than silently narrowed. Safe unknown root elements and direct record elements survive same-format canonical output when their declared native-entry names match their XML element names; mismatches, root extensions that become structural `records` containers, and records-container extensions that introduce reserved direct `record` elements are rejected before strict output. Their XML parsing and emission observe cancellation in bounded text chunks, keep UTF-16 surrogate pairs intact across chunk boundaries, and diagnose raw carriage returns that XML would normalize before strict output. Typed EndNote element text uses the same cancellation-aware emission path. A direct `records` document reports document-level outer-root extensions that have no output location instead of silently consuming them. Unsupported shapes inside known containers, such as an `author` directly beneath `contributors`, remain raw native XML and are preserved when no typed owner must share that container; retained known-container content that would repopulate a cleared typed owner is diagnosed and omitted. Direct mixed text in structural root, records, or record elements is bounded before DOM materialization and diagnosed as recovered source loss. XML comment and processing-instruction values are bounded before DOM materialization. Byte loading scans the complete bounded XML declaration for declared legacy encodings and scans all bounded leading BOM-less UTF-16/32 whitespace before markup, with cancellation throughout. Automatic detection and explicit EndNote parsing consume large XML text and attribute tokens through cancellation-aware readers. Edited native-value validation, structural inspection, and writing also use cancellation-aware XML parsing and bounded scans. Invalid XML characters and unpaired surrogates in typed text, preserved native types, and supported serial identifiers are diagnosed and replaced in permissive output. Declared or caller-selected encodings that cannot represent the generated text are reported and use replacement bytes in permissive output; strict no-loss mode rejects them before encoding. Preserve-mode byte generation rejects unsupported XML encoding declarations rather than returning bytes that contradict the declaration. DTD processing and external resolution are prohibited. |

## Preservation and conversion

- Preserve mode returns the original source only when the destination format matches and the semantic model is unchanged.
- Loaded bytes are retained exactly. Parsed text is retained exactly and is encoded with the selected writer encoding when bytes are requested, except that unchanged EndNote XML text with an encoding declaration uses the declared encoding so the XML declaration and returned bytes remain consistent.
- Any edit switches output to deterministic canonical syntax. Untouched trivia inside a modified record is not position-preserved.
- Unknown native fields remain in the model. Same-format writers preserve safe extensions; cross-format writers report fields they cannot carry.
- A supplied native CSL JSON or EndNote XML raw representation is trusted only when it matches the decoded value and, for XML, the field name; mismatches use the decoded value and are reported as loss.
- Non-CSL writers diagnose structured contributor names without a family component because their comma syntax reopens a missing family as an empty string. Numeric dates use the model's syntactic year/month/day ranges rather than Gregorian calendar validation.
- Date parsing bounds component scanning before allocating substrings. Nonnumeric literal dates retain their original surrounding whitespace; strict output reports only whitespace that the selected destination actually normalizes, while trailing whitespace survives BibLaTeX, RIS, NBIB, and EndNote XML.
- BibTeX and BibLaTeX keep whitespace-only literal contributor names distinct from structured names, report structured components hidden by a literal name, and observe cancellation during field and directive escaping, terminal-backslash checks, and delimiter-safety scans. CSL native objects and arrays accepted with comments or trailing commas retain their JSON shape and are normalized to strict canonical JSON after edits.
- `BibliographyConversionReport` records stable codes, severity, action, item key, and field. `HasLoss` covers approximated, omitted, and error decisions.
- `BibliographyWriteOptions.RequireNoLoss` rejects a write before bytes are returned when conversion would lose data.
- Writer options reject undefined mode or destination-format enum values before preserve or canonical output can mutate a destination.

## Local reference resolution

`BibliographyDocument.ResolveReferences` is an opt-in operation over local records. It deep-copies the document and codec bindings, retains reference fields and data containers, and exposes citation-eligible records separately. It never changes the source or opens files or network resources.

| Capability | Contract |
| --- | --- |
| Keys | Case-sensitive lookup; empty and duplicate keys are diagnosed, and ambiguous parents are not selected |
| Crossref | Missing-field fallback; common book, proceedings, and periodical titles map to container titles |
| Xdata | Whole-entry cascading containers, applied in listed order before crossref; later containers replace earlier values and child values by default, with optional missing-field fallback |
| Field groups | Contributor roles, date roles, identifier schemes, keyword lists, note lists, and native-field groups are copied without shared mutable children |
| Provenance | Immutable final inherited-field origins with ultimate source index/key/field and complete parent path |
| Graph failures | Cyclic records and their dependents retain original values; graph depth is checked independently of input order |
| Diagnostics | `BIBREF001` empty key, `002` duplicate/ambiguous key, `003` missing parent, `004` cycle dependency, `005` depth, `006` repeated/empty reference, `007` non-container xdata target, `008` failed parent |
| Limits | Defaults: 250,000 items, 1,000,000 edges, 64-edge chains, 2,000,000 copied values, 64 MiB aggregate copied UTF-16 characters, 10,000 diagnostics; cooperative cancellation |
| Limits of interpretation | Granular `xdata=key-field-index`, custom Biber field mappings, entry-key aliases, and multivolume title mappings are not interpreted |

Native codecs retain references without resolving them automatically. The resolved snapshot retains unknown/native evidence; conversion to another format still uses the ordinary fidelity report.

## Input and security limits

| Control | Default |
| --- | ---: |
| Encoded bytes | 64 MiB |
| Decoded UTF-16 characters | 64 MiB |
| Items | 250,000 |
| Values across records | 2,000,000 |
| One decoded value | 4 MiB |
| Parser diagnostics | 10,000 |
| BibTeX/JSON/XML nesting | 128 |

Stream decoding enforces the decoded-character limit incrementally before a full source string is materialized and uses exception fallbacks so malformed byte sequences are rejected even when a caller supplies a replacement-fallback encoding. Automatic detection recognizes leading Bib and CSL line comments terminated by LF, CRLF, or CR. BOM-less UTF-16 and UTF-32 EndNote XML is detected from leading XML markup with or without a declaration and after XML whitespace. EndNote line offsets use exact zero-based UTF-16 positions resolved by a constant-memory, cancellation-aware scan rather than a per-line index. Parsing, automatic content detection, baseline and preserve-mode fingerprinting, conversion inspection, and writing observe cancellation, including EndNote post-DOM projection, per-record contributor, identifier, keyword, note, native-field, and native-entry collections, final output encoding or preserved-byte cloning, and bounded synchronous or asynchronous stream writes. Save operations check cancellation before mutating a destination. The library does not execute BibTeX/TeX, fetch URLs, load XML external entities, invoke native citation tools, or inspect local files named by citation data.

## Fixture provenance

The checked-in codec fixtures are repository-authored minimal interoperability records containing fictitious citation data. They do not copy third-party library exports or personal bibliography data. Contract tests reopen every canonical output through its owning codec.

## CSL rendering

The managed renderer accepts local CSL 1.0 style XML using the CSL 1.0.2 vocabulary. It implements a subset of the standard and does not claim complete conformance for arbitrary styles.

| Capability | Current contract |
| --- | --- |
| Style loading | Bounded XML, immutable parsed style, caller-resolved independent parents, default locale inheritance; DTDs, external entities, recursive and undefined macros are rejected |
| Output | Plain text or escaped HTML entries and citation clusters; supported rich-text formatting and case-protection carriers are interpreted without executing markup. HTML entities remain text alongside emphasis, escaped tags remain literal, and small-caps CSS accepts whitespace without forwarding unsupported declarations or attributes. |
| Short-title input | CSL-JSON `shortTitle` and `journalAbbreviation` resolve through `title-short` and `container-title-short` for rendering, conditions, sorting, and substitution. Explicit canonical fields take precedence, including empty values; writing retains the supplied field names. Notes remain annotation text. |
| Bibliography layout | Immutable hanging-indent, line-spacing, entry-spacing, and second-field alignment metadata; automatic left-margin/right-inline HTML blocks and explicit display blocks retain layout, group, and macro-wrapper affixes and quotes with their owning fields. Inline fields retain their positions among display blocks; links and input emphasis retain their context. Left-margin hints count final visible UTF-16 text after transformations; hosts apply spacing and measure glyph width. |
| Names and dates | Personal/literal contributors, particles and name-part affixes, initials with supported input emphasis, et-al rules, substitution, date parts/ranges, locale terms and ordinals; ordinal days use the month term's grammatical gender |
| Page ranges | Opt-in expansion and minimal, minimal-two, Chicago 15/16 abbreviation; compatible repeated prefixes, significant endpoint digit widths, Unicode decimal glyph preservation, Roman delimiters and locale overrides. Endpoints are expanded before numeral-form conversion. Distinct prefix/suffix identifiers are not numerically reinterpreted. `cs:text` retains page text when the option is absent; citation locators keep their separate policy. |
| Numbers and labels | Numeric units are transformed individually without reparsing generated ordinal or connector terms. Contextual labels recognize Arabic and Roman numeral lists, and count variables use their numeric count. Ordinals use the selected locator or count noun's gender. Partial modern suffix sets retain their matching rules; complete legacy sets retain the CSL 1.0 rules. Explicit empty long ordinals remain empty. Unicode superscript characters in locale terms remain Unicode text. |
| Name counts | `cs:name form="count"` counts selected contributors after ordinary/subsequent abbreviation, retained-last-name selection, and editor/translator collapsing. Missing lists use substitutions; a present list selected down to zero renders `0`. Macro sort keys apply name-selection overrides to counts. |
| Contributor labels | An implicit name precedes its role label. With an explicit `cs:name`, its position relative to `cs:label` selects the rendered order. Inherited defaults, substitutions, and separate label formatting are retained. Complete bibliography name replacement retains the role label, its order, formatting, and inherited label settings. Names used by an empty replacement remain selected for substitution suppression. Later names expressions retain their own names and labels. |
| Name option pairs and roles | Abbreviation requires effective minimum and first-name settings, including inherited values, subsequent-citation replacements and macro sort overrides. Count form uses the same selection. Identical editor/translator lists combine only when exactly those two roles are selected; other role selections render independently. Single-letter given-name initials compare independently of their periods and spacing for disambiguation and role collapsing; hyphenated initials retain their separate structure. Full given names and corporate literal names retain their distinct identities. |
| Name input and compound initials | Explicit dropping and non-dropping particle fields control placement and sorting; family/given text is retained without inferred particle splitting or quote markers. Existing multiletter initials can be supplied in given names. Compound continuations are initialized with their original letter case and emphasis; output hyphenation follows the style option. Standalone lowercase particles and uninitialized full names retain their text. |
| Empty rendered entries | Complete snapshots retain citation/bibliography keys and citation numbers when a style produces no text. `CslRenderedEntry.IsEmpty` identifies these entries independently of HTML wrappers so hosts can omit blank rows. Explicit style whitespace remains content. |
| Name and title sorting | Family, particle, given-name, and suffix priorities are distinct from display punctuation. Punctuation is ignored while internal word spaces, numeric runs, and contributor boundaries remain distinct. Short-name macros omit hidden dropping particles and suffixes; mononyms sort by their visible name. Initial English articles are omitted from institutional sort keys with Unicode word spacing preserved in displayed names. Equal name/text fallback keys retain secondary sorting. |
| Substitution | Repeated variables and short forms are suppressed while a fallback renders. Variable-presence and numeric conditions continue to inspect source values; unsuccessful candidates release variable, name-comparison, and alignment state. All four bibliography replacement rules apply to text fallbacks, and empty replacements keep nested fallbacks selected. Combined contributor labels honor local overrides in both supported term spellings. |
| Punctuation boundaries | Collisions are resolved between adjacent fields, delimiters, and affixes; punctuation within a field and surrounding HTML formatting are preserved. Locale quote rules move adjoining commas and periods across inline formatting, retaining their original emphasis and link context. Matched input quotes, including adjacent single and double quotes across formatting boundaries, retain their quotation levels alongside nested style quotes and custom locale terms. Apostrophes and unmatched quotes retain their distinct treatment. Display containers retain their own punctuation. Further complex combinations remain subject to qualification. |
| Text casing | Versioned CSL English stop words and phrases, separate hyphenated words, dotted initials, case protection, and item-language Unicode casing; English title-case eligibility follows the item language or style default, independently of output-locale overrides. Sentence case preserves other words in mixed-case input; all-uppercase input is lowercased after its first character. Title case treats hyphenated parts as distinct words, including letter parts after numbers. |
| Bibliography links | HTML URL, DOI, PMID, and PMCID anchors with rendered URI prefixes inside and descriptive affixes outside; absolute HTTP/HTTPS targets only; caller can disable links; plain text and citation clusters have no anchors |
| Document flow | Complete-sequence rendering recalculates citation sorting and positions, note numbers, disambiguation, numbering, year suffixes, narrative name formatting and substitutions, and supported collapse rules after document edits. Date-only layouts and empty name expressions share an empty visible-name group for year-suffix and ranged collapse. Citation affixes prevent adjacent collapse. Hosts decide which output regions to refresh. |
| Citation positions | Body and note sequences have separate histories. Empty and absent locators are equivalent. Across notes, `ibid` requires consecutive note numbers, a single preceding citation item, and one distinct work in the preceding note; within clusters it follows rendered order. Empty clusters do not consume history. Near-note distance retains the previous note across body citations. First-note variables are empty in body citations, the first note, and non-note styles. |
| Note openings | The first rendered citation in a note receives locale-aware capitalization while retaining HTML formatting and case protection. Set `NoteHasPrecedingText` for citations inserted into existing note prose; a prefix containing text also prevents automatic capitalization. Body and narrative citations, numeric openings, and later citations retain their casing. |
| Note disambiguation | Text is compared across full, subsequent, and near-note forms for distinct works. Subsequent name options and first-note variables trigger their forms without requiring a position condition. First-note references can distinguish short notes; overlapping ambiguity sets share suffixes assigned in bibliography order. |
| Conditional detail | Branches add distinguishing detail in style order; only still-matching works receive further fields. Repeated macros and citation forms retain separate choices where needed. Observed locator types and numeric/textual locator branches participate without allowing different page numbers to conceal ambiguous source identities. Nested gates and sibling combinations participate, unhelpful trials roll back, and explicit conditional year suffixes are reconsidered after assignment. Repeated citations reuse choices when the style defines one reusable form. |
| Dotted values and identifiers | Contextual labels treat a dotted version such as `4.2` as one value and a version list or range as plural. Nonnumeric identifiers such as `ES-22-8` retain their hyphens. |
| Locale data | Embedded versioned CSL locales and caller overrides; no automatic download. XML indentation in empty terms is ignored; `xml:space="preserve"` retains whitespace-only terms. Nonempty term values retain padding and separators across XML comments and CDATA. Output-significant attribute whitespace remains content. |
| Caller metadata and name spacing | `citation-label` comes from record data; automatic author/year label generation is outside the renderer. Annotation `note` text does not populate other CSL fields. Conjunction spacing follows generic name rules; an explicit name delimiter expresses script-specific spacing. |
| Limits | Style character/depth limits and operation-level citation, output, intermediate, and work budgets including element evaluations and sorting comparisons; cooperative cancellation. Numeric classification, numeral extraction, separators, and page ranges use linear scans with cancellation checkpoints; numeral and connector expansion enforces the intermediate limit. |
| Data fidelity | `DataConversionReport` reports source-to-CSL data loss; strict rendering can reject that projection before output |
| Remaining qualification | Punctuation collisions, advanced name/disambiguation and date-range cases, full style grammar, and complex nested bibliography display layouts are not fully qualified |

Style/data conversion diagnostics and successful codec round trips do not establish complete CSL rendering conformance. Rendered-output qualification is a separate contract.

## Integration boundary

`OfficeIMO.Bibliography` is format-neutral and has no Word or Open XML dependency. `OfficeIMO.Word` remains unchanged. The roadmap retains a future decision about an optional `OfficeIMO.Word.Bibliography` bridge that would translate Word bibliography sources to and from this model.
