# XLSX package metadata read, 2026-09-28

The native XLSX reader now processes the package content-type manifest and the root/workbook relationship lists with a forward-only XML reader. It retains the same bounded ZIP part reads, XML settings, relationship and URI checks, strict/transitional workbook handling, cancellation checks, and SDK fallback decisions. Workbook metadata still uses the existing XML document parser. This is an incremental allocation improvement; it does not close the [remaining XLSX read target](../ROADMAP.md#spreadsheet-and-csv-delivery-order).

The baseline was `57fa2f90f`. Both assemblies were built from the same tree and .NET 10.0.12 toolchain except for the metadata parser change. The pinned 65,535-row, 14-column fixture was `65K_Records_Data.xlsx`, SHA-256 `0F44D3E06454508DBD2CDBAF701B04160637162AB71471616D8ADC59D2EDD3A8`. The baseline and candidate `OfficeIMO.Excel.dll` hashes were `2212DC30E3B7B51954E32B2CC8FC54ADDB819B5F81A807ECA8DDAB98D6C0A58E` and `0EE56FD5CF1B46621F6AFD2F20FFA81A43265D95B155D36924EBF693DD3B71BE`, respectively.

Windows 11 on an AMD Ryzen 9 9950X3D2 was measured at Normal priority. Separate process runs pinned to logical processors `0xFFFF` (A) and `0xFFFF0000` (B) were rotated candidate/baseline/baseline/candidate and then candidate/baseline/baseline/candidate across the two domains. Each typed-scan process performed 24 complete public `ExcelDocument.OpenDataReader` scans and each sheet-name process performed 21 batches of 100 public `ExcelDocument.GetSheetNames` calls. The first iteration or batch in each process was warm-up and is omitted below. Every later sample, including outliers, is retained in [the raw samples](xlsx-metadata-2026-09-28/samples.csv). The [probe source](xlsx-metadata-2026-09-28/reproduction/Program.cs) performs the same public calls and validates the row count and typed-value checksum.

The complete typed scan saves 4,408 managed bytes, or 3.9%, per warmed operation. All typed-scan samples produced the same checksum. The metadata-only profile confirms that the saved allocation comes from the changed path and shows no repeatable elapsed-time regression. Full-scan elapsed time was bimodal and moved in opposite directions on the two processor domains; it does not establish a whole-scan speed gain or loss. The prior 50% allocation-reduction target relative to 183,832 B/scan would require at most 91,916 B/scan under an equivalent measurement contract. This result remains above that threshold; peak-memory and native Linux/macOS budgets are also still open.

The native package contract tests passed on Windows .NET 8 and .NET 10 (22 each), .NET Framework 4.7.2 (20), and Ubuntu under WSL .NET 10 (22). The Excel library builds for all four declared targets, including .NET Standard 2.0. These tests cover malformed or duplicate content-type entries, missing or duplicate relationships, invalid target modes, unsupported package shapes, metadata encoding, DTD rejection, and SDK fallback. The probe source can be run against a hash-verified copy of the fixture with `dotnet run -c Release --project Docs/benchmarks/xlsx-metadata-2026-09-28/reproduction/Probe.csproj -- typed-scan <fixture-path> FFFF` or `sheet-names-100` in place of `typed-scan`. Build each code revision in its own checkout and rotate separate processes for comparisons; the probe is not an equivalence substitute for those package contract tests.
