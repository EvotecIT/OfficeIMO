# Archive support

| Container | Supported read profile | Boundaries |
| --- | --- | --- |
| ZIP | Single-disk archives with stored or Deflate members | Prepended self-extracting stubs, encryption, patched data sets, other compression methods, multi-disk archives, ambiguous directory layouts (including distant ZIP64 locators with saturated classic counts), unflagged non-ASCII and invalid UTF-8 names are rejected; central-directory member count, ZIP64 coordinates, matching local names/flags/methods, exact Deflate framing, actual decoded EOF, declared lengths, CRC-32 and expansion bounds are enforced |
| CAB | Single cabinets with Store, MSZIP and the shared LZX decoder | Cabinet sets, continuation/spanning and unsupported compression are rejected; finite entry/folder/output bounds and available checksums are enforced |
| MSI | Ordinary installer database CFB; schema-driven strings and Directory, Component, File and Media tables; embedded complete cabinets | External cabinets and loose files, transforms, patches and action-dependent installation layouts are unsupported; no Installer actions, conditions or properties are executed |

CAB member names support ASCII or explicitly flagged UTF-8, with at most 256 encoded bytes in the container. Extracted path segments are separately limited to 255 UTF-8 bytes and 255 characters for portable filesystem output, before selection or staging writes. Unflagged names containing non-ASCII bytes fail explicitly because the container does not identify the producer's locale. Unsupported CAB compression, continuation and filename-encoding profiles raise `NotSupportedException`; corrupt or unsafe content raises `InvalidDataException`.

MSI strings support two- and three-byte references, extended lengths, nullable 16-/32-bit integers and authored short/long names. Metadata schemas determine field widths: older and newer packages can use different `Media.LastSequence` widths. Unsupported code pages fail explicitly. Code page zero accepts ASCII deterministically rather than inheriting a host locale.

On .NET 8/10, legacy string decoding uses the runtime code-page provider directly without registering it globally. The portable netstandard2.0 assembly includes OfficeIMO.Core's supported single-byte fallback encodings (1250, 1252, 437, 850 and Mac Roman); additional encodings depend on the host's available strict .NET decoder. UTF-8 is supported on every target. .NET Framework supplies its installed code-page support.

MSI CAB member keys must match authored File-table identifiers exactly, including case. File-table identifiers must remain unique without case sensitivity. Directory identifiers, references and embedded cabinet stream names preserve their case-sensitive MSI identity. Media sequence ranges follow `DiskId` order. Filename case is preserved. The extractor does not reproduce an installation: feature selection, registry state, transforms, custom actions and environment folder properties do not alter the extracted payload.

MSI source compression uses bit 1 of the Word Count Summary property (`PID_WORDCOUNT`, default zero when absent). File attributes `0x4000` and `0x2000` override it as compressed and noncompressed respectively; setting both is invalid. A loose source row raises `NotSupportedException` even when filtered out. Every embedded CFFILE length must match its FileSize before payload selection; this check does not retain excluded singleton payloads.

Distinct MSI File identifiers may alias one target only when parent directory spelling is identical and filenames are identical or differ solely by ASCII letter case. All aliases must declare the same length, and their actual payloads are compared byte for byte, including excluded files and aliases spanning cabinets. The logical path is the ordinal-smallest authored path across the complete alias group; it is selected and reported once. Different bytes, directory-case changes and Unicode-normalization aliases remain invalid. An ordinary CAB still rejects all output-path collisions. The source package's File identifiers and original names remain its authoritative authored layout; extraction does not simulate which component Windows Installer would install.

MSI directory depth counts the root and directories authored as `.`, including directories with no payload files. Cached ancestors retain their complete depth. Output segment and path-length bounds are checked before a resolved directory prefix is assembled or cached.

MSI compound storage is indexed once per extraction. Embedded cabinet input bytes, members, decoded bytes and decompression work share aggregate limits. `MaxCabinetCount` defaults to 256 and includes cabinets whose mapped files are empty or excluded by `IncludeFile`.

Alias coalescing does not reduce source resource charges: every File row counts toward entry limits, every selected or compared alias contributes its declared length to the aggregate retained-content bound, and all cabinet members and folder bytes still count. A representative comparison file is kept outside the output staging tree until its complete group is verified, then removed. Published file count and TotalBytes include each selected logical target once.

`MaxDecompressionWorkBytes` defaults to 2 GiB independently of the 1 GiB expanded-content default. Every Store, MSZIP or LZX CFDATA frame consumes `max(32768, 8 + reserveBytes + compressedBytes, expandedBytes + msZipDictionaryBytes)` work bytes before checksum processing, decoder buffers or decoding. `msZipDictionaryBytes` is the preceding folder history, capped at 32 KiB, and is zero for other codecs. Repeated folders, folder gaps and filtered files still consume this shared budget; zero-frame cabinets do not. Exceeding it raises `InvalidDataException` with diagnostic code `CAB_WORK_LIMIT`. These units bound frame processing and replay rather than exact CPU time, and increasing the limit permits more work on hostile inputs.

Names are checked for absolute paths, traversal, alternate data streams, reserved Windows device names, invalid portable segments, case/Unicode collisions outside the verified MSI filename-alias profile, and file/directory conflicts. The destination, staging directory, alias-comparison directory and paths within these controlled directories must not be symbolic links or reparse points. Caller-selected parent directories and read-only input paths may traverse operating-system or caller-owned links. Existing files are not overwritten. Atomic publication uses a same-parent directory move; callers must coordinate access to the destination and its parent during extraction.

Focused qualification covers Windows administrative-template MSI payload profiles and Microsoft Edge CAB payloads. It does not imply compatibility with every MSI or LZX cabinet producer. Runtime package availability and source qualification are separate release states.
