# Archive support

| Operation | Containers | Verification and ownership |
| --- | --- | --- |
| `ArchiveReader.TraverseZip` | ZIP | Bounded metadata traversal with ingestion warnings; file content is not decoded or checksum-verified. |
| `ArchiveReader.ReadZip` | ZIP | Strict metadata/path preflight and complete selected-content length, framing and CRC verification; selected arrays belong to the caller. Input streams stay open. No partial result or filesystem output. |
| `ArchiveInspector.Open` / `PlanRead` / `OpenRead` / `ReadMembers` | ZIP, CAB, MSI | Raw ordinal-preserving inventory, complete verified member reads and atomic grouped reads. |
| `ArchiveInspection.Verify` / `CopyTo` | ZIP, CAB, MSI | Structured integrity outcomes; verified copying uses a private decoded spool for every format. CAB/MSI verify the complete containing folder. |
| `ArchiveExtractor.Extract` | ZIP, CAB, MSI | Strict verified extraction through a sibling staging directory and completed-directory publication. |

In-memory reading defaults to 64 MiB compressed input, 10,000 physical members, 16 MiB per declared member and 64 MiB aggregate selected bytes. These are logical data limits; snapshots, buffering and owned result copies add memory overhead. CAB/MSI complete member reads are available through inspection. Related containers can share `ArchiveOperationBudget`; lazy unverified member streams are not exposed.

| Container | Supported read profile | Boundaries |
| --- | --- | --- |
| ZIP | Single-disk archives with stored or Deflate members | Prepended self-extracting stubs, encryption, patched data sets, enhanced Deflate and reserved flag profiles, compression-level flags on stored members, other compression methods, multi-disk archives, ambiguous directory layouts (including distant ZIP64 locators with saturated classic counts), unflagged non-ASCII names require an explicit `ZipLegacyCodePage`, and flagged invalid UTF-8 names are rejected; central-directory member count, ZIP64 coordinates, matching local names/flags/methods, exact Deflate framing, actual decoded EOF, declared lengths, CRC-32 and expansion bounds are enforced; directory members must have verified empty payloads |
| CAB | Single cabinets with Store, MSZIP and the shared LZX decoder; passive CFFILE/folder inventory, complete member reads and grouped ordinal reads | Cabinet sets and continuation/spanning are rejected; unsupported compression is visible in inventory and rejected for reads/extraction; finite entry/folder/output bounds and available checksums are enforced during reads |
| MSI | Ordinary installer database CFB; schema-driven strings and Directory, Component, File and Media tables; embedded complete cabinets; passive File-row and raw storage-stream inventory | External cabinets and loose source rows are inventory-only and never opened; transforms, patches and action-dependent installation layouts are unsupported; no Installer actions, conditions or properties are executed |

Passive inspection preserves raw names and source ordinals, declared sizes, compression parameters, shared-folder compressed/expanded sizes and unsupported-source diagnostics. MSI File rows retain original identifiers, short/long FileName fields, sequences and raw cabinet references; aliases remain separate. Authored target paths are assembled under finite length/depth limits without applying extraction path-safety or collision rules. Every embedded compressed File mapping must match its CAB name, declared size and sequence. Raw storage streams retain MSI's encoded compound names and directory traversal order, including inert Binary content. Inspection never evaluates actions or reads external source paths or URLs.

Inventory validates directory structure and declared expansion without decoding or checksum verification. `CanRead` describes supported source/codec features, not verified content. `OpenRead` uses the existing managed CAB decoder to verify a complete containing folder and member before returning any bytes. `OpenStorageStream` returns a complete raw MSI stream without interpreting it. `FolderFrameCount` and `FolderChecksumFrameCount` retain the total frames and nonzero checksum declarations. A successful member read checks those declared nonzero checksums; zero-checksum frames receive no checksum verification. These are corruption checks, not cryptographic authenticity evidence. Neither API returns partial prefixes or hashes. Returned streams are read-only, caller-owned and independent of inspection disposal.

`ReadMembers` returns an atomic batch of complete read-only member streams in requested ordinal order. It decodes each selected cabinet/folder pair once, copies only selected members, and never coalesces raw names or MSI aliases. Ordinals must be distinct. Unsupported selections, selected-payload size and aggregate remaining expansion are checked before any decoding. A failed or canceled read exposes no partial result. The explicit selected-byte cap bounds retained batch payload; the existing inspection expansion and frame-work budgets bound complete selected folders and processed frames. Batch totals report selected payload bytes, decoded folder bytes including unselected members/gaps, and charged processing-work units. The input snapshot, folder-frame metadata, bounded codec history/frame scratch and retained selected arrays coexist; decoded folders are not retained as whole arrays. These are not hard peak-RSS guarantees. There is no decoded-folder cache between calls. Batch disposal closes its streams and empties its member collection; its inventory records and totals are ordinary detached metadata.

`PlanRead` is passive and detached. It applies the grouped selection's ordinal and supported-source rules, sums complete selected member sizes and deduplicates cabinet/folder costs. It reports compressed payload bytes, full decoded bytes, canonical work charges and CAB folder/frame counts without payload reads, checksum checks or budget reservations. Its costs describe a successful complete grouped read; failure can stop processing earlier, and the actual read can still fail a remaining quota. ZIP compressed totals exclude headers; CAB totals include every payload in each selected folder. No memory, elapsed-time or exact-I/O estimate is implied.

CAB Store, MSZIP and LZX decode incrementally through one shared core path for inspection, grouped reads and extraction. MSZIP uses a rolling 32 KiB dictionary and reusable frame buffer. LZX retains an untranslated circular history window, capped at its configured 32 KiB–2 MiB size and reduced for small folders, with a separate translated output frame. E8 translation uses absolute folder offsets and never changes future dictionary history. Selected ranges can cross frames or overlap; each authored member remains independent. Complete folder checksums, frame boundaries and final LZX block/padding are verified before selected results escape. Excluded extraction folders are still decoded and charged without retaining their expansion.

ZIP inspection preserves duplicate and unsafe raw paths without writing them. Supported ZIP members use the same local-header, length, exact framing and CRC verification as strict reading and extraction. Unsupported methods and flags remain visible with `ZIP_COMPRESSION` and `ZIP_FLAGS` diagnostics. ZIP inspection reports DOS timestamps with zero offset because the format does not declare a timezone. Traversal retains the existing `ZipArchive` convention of interpreting those wall-clock fields in the host local zone before returning `LastWriteUtc`.

Input is snapshotted within `MaxInputBytes`. ZIP input above 64 MiB uses private temporary storage, and traversal reuses its existing private snapshot without an archive-sized managed copy. ZIP inventory is not restricted by an Int32 input-array ceiling. CAB/MSI input and complete in-memory member reads retain Int32 managed-array bounds. Metadata and declared member/folder totals are bounded at inventory time. A shared directory budget counts CAB folders, CFFILE records and CFDATA records across embedded cabinets, while the compound reader separately retains finite slot/stream limits. Subsequent reads share cumulative decoded-folder/raw-stream bytes and CAB work limits; repeated `OpenRead` calls charge their full folder again, while a batch charges each selected folder once. Attempted decode failures keep their folder charge; frame work reports only the charges reached before failure. Seekable inputs are read from the beginning and restored; nonseekable inputs are consumed from the current position and left open. Opening cancellation applies to snapshot creation; each later read has its own token. Disposing a session prevents further reads and releases its snapshot and indexes.

CAB member names support ASCII or explicitly flagged UTF-8, with at most 256 encoded bytes in the container. Extracted path segments are separately limited to 255 UTF-8 bytes and 255 characters for portable filesystem output, before selection or staging writes. Unflagged names containing non-ASCII bytes fail explicitly because the container does not identify the producer's locale. Unsupported CAB compression raises `NotSupportedException` for reads and extraction and remains visible with diagnostic codes in passive inventory. Continuation and unsupported filename-encoding profiles raise `NotSupportedException` while opening. Corrupt or unsafe extraction content raises `InvalidDataException`.

ZIP central-directory digital-signature records are accepted as opaque metadata, including in empty archives. Extraction does not authenticate those signatures. Stored members must declare equal compressed and uncompressed sizes, including excluded members. A self-consistent end record nested in another end record's comment is an ambiguous layout and is rejected.

MSI strings support two- and three-byte references, extended lengths, nullable 16-/32-bit integers and authored short/long names. During filesystem extraction, Directory and File target names remove trailing ASCII spaces and dots before portable validation, `IncludeFile` and collision checks. A directory `.` keeps its parent meaning; names that normalize entirely away remain invalid. Before splitting or normalization, long target names are limited to 255 characters, short/long pairs to 511, and complete target/source directory definitions to 1,023, even under an unbounded authored schema. Metadata schemas determine field widths: older and newer packages can use different `Media.LastSequence` widths. Unsupported code pages fail explicitly. Code page zero accepts ASCII deterministically rather than inheriting a host locale.

On .NET 8/10, legacy string decoding uses the runtime code-page provider directly without registering it globally. The portable netstandard2.0 assembly includes OfficeIMO.Core's supported single-byte fallback encodings (1250, 1252, 437, 850 and Mac Roman); additional encodings depend on the host's available strict .NET decoder. UTF-8 is supported on every target. .NET Framework supplies its installed code-page support.

MSI CAB member keys must match authored File-table identifiers exactly, including case. File-table identifiers must remain unique without case sensitivity. Directory identifiers, references and embedded cabinet stream names preserve their case-sensitive MSI identity. Media sequence ranges follow `DiskId` order. Filename case is preserved. The extractor does not reproduce an installation: feature selection, registry state, transforms, custom actions and environment folder properties do not alter the extracted payload.

MSI source compression uses bit 1 of the Word Count Summary property (`PID_WORDCOUNT`, default zero when absent). File attributes `0x4000` and `0x2000` override it as compressed and noncompressed respectively; setting both is invalid. During extraction, a loose source row raises `NotSupportedException` even when filtered out. Every embedded CFFILE length must match its FileSize before payload selection; this check does not retain excluded singleton payloads.

Distinct MSI File identifiers may alias one target only when normalized parent directory spelling is identical and normalized filenames are identical or differ solely by ASCII letter case. All aliases must declare the same length, and their actual payloads are compared byte for byte, including excluded files and aliases spanning cabinets. The logical path is the ordinal-smallest normalized path across the complete alias group; it is selected and reported once. Directories whose installed spelling matches merge; conflicting files still fail. Different bytes, directory-case changes and Unicode-normalization aliases remain invalid. An ordinary CAB still rejects all output-path collisions and retains strict portable names. Source File identifiers remain authoritative for cabinet member mapping, while extraction reports installed target spelling without simulating which component Windows Installer would install.

MSI directory depth counts the root and directories authored as `.`, including directories with no payload files. Cached ancestors retain their complete depth. Output segment and path-length bounds are checked before a resolved directory prefix is assembled or cached.

MSI compound storage is indexed once per extraction. Embedded cabinet input bytes, members, decoded bytes and decompression work share aggregate limits. `MaxCabinetCount` defaults to 256 and includes cabinets whose mapped files are empty or excluded by `IncludeFile`.

CAB extraction reserves the aggregate selected-member byte allowance after directory validation and filtering, before any containing folder is decoded. A selection quota refusal consumes no expansion or frame work.

Alias coalescing does not reduce source resource charges: every File row counts toward entry limits, every selected or compared alias contributes its declared length to the aggregate retained-content bound, and all cabinet members and folder bytes still count. A representative comparison file is kept outside the output staging tree until its complete group is verified, then removed. Published file count and TotalBytes include each selected logical target once.

`MaxDecompressionWorkBytes` defaults to 2 GiB independently of the 1 GiB expanded-content default. Every Store, MSZIP or LZX CFDATA frame consumes `max(32768, 8 + reserveBytes + compressedBytes, expandedBytes + msZipDictionaryBytes)` work bytes before checksum processing, decoder buffers or decoding. `msZipDictionaryBytes` is the preceding folder history, capped at 32 KiB, and is zero for other codecs. Repeated folders, folder gaps and filtered files still consume this shared budget; zero-frame cabinets do not. Exceeding it raises `OfficeInspectionResourceLimitException` for `MaxDecompressionWorkBytes`, retaining the native `CAB_WORK_LIMIT` failure in `InnerException`. These units bound frame processing and replay rather than exact CPU time, and increasing the limit permits more work on hostile inputs.

Extraction checks names for absolute paths, traversal, alternate data streams, reserved Windows device names, invalid portable segments, case/Unicode collisions outside the verified MSI filename-alias profile, and file/directory conflicts. The destination, staging directory, alias-comparison directory and paths within these controlled directories must not be symbolic links or reparse points. Caller-selected parent directories and read-only input paths may traverse operating-system or caller-owned links. Existing files are not overwritten. Atomic publication uses a same-parent directory move; callers must coordinate access to the destination and its parent during extraction.

Extraction qualification covers Windows administrative-template MSI payload profiles and Microsoft Edge CAB payloads. Public inspection and grouped-read proof compares makecab-produced LZX cabinets byte for byte with their independent original OneNote fixtures. A solid-folder selection returns separate duplicate-name payloads under one folder/frame allowance that rejects the corresponding repeated single-member reads. Managed fixtures also cover selected-byte refusal, checksum/work failures, source order, selective unsupported-folder coverage and detached stream lifetimes. MSI inspection proof includes synthetic ordinary-database fixtures for embedded payload mapping, raw streams, external/loose-source diagnostics and limits. The packed consumer also qualifies the official 7-Zip 26.04 x64 MSI: all 106 selected payload hashes and published extraction hashes match an independent 7-Zip extraction on macOS. This is native-producer input evidence, not Windows Installer execution. It does not imply compatibility with every MSI or LZX cabinet producer. Runtime package availability and source qualification are separate release states.

Resource exhaustion is a public `OfficeIMO.OfficeInspectionResourceLimitException` (`Owner = "archives"`), with the exact limit identity and effective maximum. Configured byte, count, metadata, path and work bounds are separate from corruption. Fixed managed array and MSI compound directory/stream ceilings use the same resource contract; reduced remaining native allowances retain their actual maximum. Native failure codes remain available through `InnerException`; callers must not classify quotas by message text. This intentionally changes quota failures previously reported as `InvalidDataException`. Malformed declarations, unsafe paths, failed checksums and inconsistent MSI mappings retain `InvalidDataException`, and unsupported profiles retain `NotSupportedException`. No partial batch is returned; extraction removes its staging output on a quota failure.


Raw MSI stream read admission checks local bounds and reserves shared selected, expanded and work charges together before opening the source. A preflight refusal consumes no read bytes; failures after admission retain their charges.

Shared operation limits and resource reports follow the [public budget contract](README.md#verify-copy-and-budget-related-containers). Copying uses bounded transfer buffers and a complete private decoded spool under the per-copy MaxTemporaryBytes allowance (default 256 MiB). The member size is admitted before staging or read charges. CAB/MSI verify their complete containing folder; in-memory reads/verification and input snapshots retain their documented array bounds. ZIP input spills above 64 MiB. Folder decoding uses bounded frame/history state. `CopyTo` protects a destination from integrity failures, while final-copy cancellation or I/O failure requires caller rollback. No hard peak-memory, unlimited-size or lazy-stream claim follows from these APIs.

The checked-in independent ZIP corpus includes 7-Zip 26.04 UTF-8 and unflagged UTF-8 names, CPython CP1250 names, and CPython streaming classic and ZIP64 descriptors with original public-domain payloads. The producer manifest records hashes and encoding policies. Native Windows Explorer production of Polish filenames remains a separate acceptance check; a synthetic CP1250 regression or macOS 7-Zip run does not establish it. The opt-in package consumer also supports comparing ordinary MSI member bytes with an independent extracted payload directory and makecab LZX members with their original files.

A pinned Windows-labelled ZIP from the .NET runtime-assets corpus passes complete verification and byte/hash comparison for all four members on macOS. Its producer version is unspecified and its ASCII names do not qualify Windows Explorer Polish-name behavior. Packed consumer runs cover .NET 8 and 10 on macOS and Windows. The Windows net472 consumer runs on .NET Framework 4.8.9345.0; an installed .NET Framework 4.7.2 runtime has not been exercised. Each Windows target passes the five independent ZIP cases, all 106 pinned native MSI payload comparisons and native makecab verified copying. Windows Shell production of the Polish-name fixture remains unqualified and is an opt-in run on a suitable Windows machine, separate from required runtime CI and interactive Explorer UI acceptance.
