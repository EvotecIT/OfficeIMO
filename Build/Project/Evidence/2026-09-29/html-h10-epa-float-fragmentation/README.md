## Full-archive break-rule intervention

The original archive's computed print styles are `break-inside:auto` on the floated outer box, `break-after:avoid` on its 93px title, and `break-inside:avoid` on its 153px list item. The title and list-item keep rules combine to move the box's visible content to page 2 while paragraph and list text on page 1 still wrap beside its original float position. This is a print-fragment distinction between float exclusion and descendant paint; the box itself was not authored as unbreakable.

Diagnostic copies of the same MHTML changed exactly one or two inline break declarations while keeping its other resources and styles. With `break-inside:avoid` on the **outer box**, Chromium moved the whole float and let page-1 text use the full width, matching OfficeIMO's current first-page flow. Changing only the title to `break-after:auto` painted the title on page 1 but kept the paragraph narrow. Changing only the list item to `break-inside:auto` painted the title and part of the list on page 1, again retaining narrow text. The compact reference PDFs `epa-outer-avoid.pdf`, `epa-title-auto.pdf`, and `epa-list-item-auto.pdf` are retained locally at `Ignore/HtmlUnknownPageQualification/h10-epa-float-fragmentation-506cb672b/`; their SHA-256 hashes are `97feddf0a4b8a11ffb712d65d89a9f6076063bdef1f0d6ba9db2f75069af35d6`, `b6846a4b6682d1d2e45baf8c855f836f28aadceaec12dbf71e7cb61eb273af28`, and `b5ad3d9dee8711dd3c1758bf5a471d478bd18a71247404f30b4e77c2bb72aac3`, respectively. The first-page rasters were inspected. Live DOM style edits to a loaded MHTML did not alter Chromium's print raster; byte-preserving MHTML source edits did, so only the latter were used as print interventions.
