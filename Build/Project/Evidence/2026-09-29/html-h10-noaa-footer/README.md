# NOAA Chesapeake footer pagination

At clean source `fb9ad4b51d8ecaf2adec04493b0ba50c25453312`, the top-level paginator lets a block with a legal internal break use the remaining page space even when the whole block would fit on a fresh page. The focused regression in `Html.Rendering.PagedContainerEntry.cs` failed before this change and passes afterward. This moves the frozen Chesapeake article's feedback buttons and social links onto print page 2, where Chromium places them. The dark site footer still starts on page 3 in OfficeIMO; Chromium starts it at the bottom of page 2. All final article paragraphs, two credited photos and footer links remain present, but print appearance is not accepted.

The offline archive replay is retained at `Ignore/HtmlUnknownPageQualification/h10-noaa-footer-clean-fb9ad4b51/`: Chromium and OfficeIMO default print each have three pages, Chromium and OfficeIMO screen-media each have four, and OfficeIMO screen snapshot has five. An independent read-only review found no actionable P0-P2 issue.

The first rebuilt macOS H4 static-budget run exceeded only the cold and warm time ceilings while concurrent Swift and CI compilation was using the host; deterministic output, allocations, memory and cancellation passed.
