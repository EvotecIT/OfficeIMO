# Frozen FWS CSS cost probe

The H10 FWS archive is the predeclared held-out source with SHA-256 `644ccacfe10dde7484549e46642be88727c34f9ba98fb36407cb6fca9f1f2fd4`. This probe used OfficeIMO branch head `9e97774710cfffd6a37b37f484406013ac27d9b1` before any CSS code change, .NET SDK 10.0.303 on macOS, and an explicit `MaxCssRules=40000` override. That override is exploratory; the untrusted profile still limits selector-expanded entries to 10,000. The browser CSSOM count is 21,521 active print style blocks and approximately 28,518 comma-split selectors. OfficeIMO materializes 28,302 selector entries for this replay. The two counts are not interchangeable because the browser count is approximate and OfficeIMO applies its own rule recovery and nesting resolution.

The conversion probe loads the unchanged MHTML and writes the default print PDF. On the unmodified source it allocated 3,238,996,808 bytes in total and `/usr/bin/time -l` observed a 424,919,040-byte maximum resident set. The conversion produced 7,715,834 PDF bytes, SHA-256 `d0f3af6bb5fbc5ea3adea8429e36f51b9c495de6e522ce1ba90c59f473401de2`. A temporary, operation-scoped cache of candidate rule lists for repeated tag/ID/class signatures allocated 3,171,395,064 bytes and reached 445,972,480 resident bytes; its PDF was byte-identical. The page has 1,688 DOM elements and 313 such signatures, but the roughly 68 MB allocation saving was only 2.1% of the probe total and came with a higher measured resident peak. Sharing one completed declaration dictionary across a qualified rule's selectors allocated 3,239,366,104 bytes with the same PDF, also too small to retain. Both experimental code changes were removed.

Temporary allocation counters, removed after the run, attributed about 9.8 MB to custom-property registration, 1.13 GB to CSS rule preparation and 662 MB to element matching. Inside rule preparation, scanning used 43 MB, CSS text transformations 54 MB, owned syntax parsing and indexing 331 MB, provider parsing 82 MB, adding parsed rules 578 MB and raw-rule recovery 41 MB. `StyleRule` construction itself accounted for 111 MB over 28,302 entries; the larger parsed-rule costs were spread across selector handling and declaration work. These counters overlap the total probe measurement and were collected in separate instrumented runs. Their purpose is to identify the next optimization owner, not to establish a timing or memory acceptance budget.

The default rule cap should remain unchanged while the larger CSS preparation and matching costs, output fidelity, and supported-platform budgets are unresolved. A resource-policy change needs a controlled supported-platform measurement of all three PDF intents and the editable targets, with conversion-only allocation, elapsed time, and resident memory. The current macOS runs were affected by other developer-machine load; elapsed times are intentionally excluded from acceptance claims.

## Bounded selector-match memo

At clean source `19e074376`, `HtmlCssSelectorMatchContext` retains its maximum of 262,144 match states in one operation-scoped table keyed by selector identity and element/compound identity. The prior layout used one dictionary per selector. The frozen FWS print replay with the same exploratory 40,000-entry cap allocated 3,093,126,632 bytes at that exact source, about 146 MB (4.5%) less than the clean baseline above. A pre-commit candidate run allocated 3,092,607,184 bytes. The two candidate runs reached 376,274,944 and 399,196,160 bytes maximum resident set on this Mac, against 424,919,040 bytes in the one baseline run; this observed range is not an accepted platform budget. The PDF remains byte-identical at SHA-256 `d0f3af6bb5fbc5ea3adea8429e36f51b9c495de6e522ce1ba90c59f473401de2`.

The focused selector suite passed 23/23; the full HTML suite passed 3,722/3,722 on both .NET 8 and .NET 10. Two selector cases passed with checked arithmetic enabled, and `OfficeIMO.Html.Core` built for netstandard2.0 with zero warnings. The clean-source H4 `advanced-held-out` gate passed all eight cases with zero failures across its screen, print and screen-to-page outputs. A fresh read-only review found no actionable memoization regression. These checks cover the shared matching change; they do not qualify FWS's remaining appearance gaps, editable targets, default 10,000-entry rejection, or Windows/Linux resource budgets.

The 7.5 MiB H4 report and page artifacts are retained locally under `Ignore/HtmlUnknownPageQualification/h10-h4-css-flat-memo-19e074376/`. The temporary EventPipe trace, trace tool installation, and superseded PDF copies were removed after their measurements were recorded here.
