# NASA card text wrapping qualification

At clean source `cb18906c2cb65045a3f3150a653b623c920c539b`, the frozen NASA MHTML archive (SHA-256 `ca63703f97b63439d1969d7425e4e9f07c611566b6c7089e47b1b0d058739735`) replayed through 13 browser, OfficeIMO and PeachPDF operations without a conversion failure. The source archive itself is unchanged from the preceding clean replay.

Bootstrap gives NASA card descriptions `overflow-wrap: break-word`. In the final Magnetospheres card, the description has a whitespace break before long filenames. OfficeIMO previously consumed the remaining line width after `||` by emergency-splitting the next filename. The renderer now takes the existing whitespace break first, then splits an oversized token on its fresh line. The same rule applies to float-wrapped text and to tokens whose first preferred-break chunk is itself too wide. `word-break: break-all` retains its distinct fill behavior. Focused regressions failed before correction and pass after it; an independent read-only review found and then confirmed closure of the preferred-break sibling path.

The new OfficeIMO zero-margin print and current Chromium print both have four pages. Their extracted Jupiter description uses the same line-break sequence for the two visible filenames. Against the preceding OfficeIMO zero-margin PDF, pages 1–3 are pixel-identical at 144 dpi. On page 4, only the final card text band changes (bounding box `x=422..1178, y=704..835` in the 1191×1684 OfficeIMO raster).
