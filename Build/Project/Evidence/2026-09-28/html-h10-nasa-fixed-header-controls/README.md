# NASA fixed-header search control in browser print

At clean OfficeIMO source `0c5c5b7730c1b7896f7a46ced3851e1fcb8b9f7e`, the frozen NASA archive (`ca63703f97b63439d1969d7425e4e9f07c611566b6c7089e47b1b0d058739735`) was inspected against the retained Chromium 151.0.7922.34 print PDF. Its fixed navbar and link labels repeat on all four pages, but the search input and placeholder appear only on page 1. OfficeIMO repeats that input on all four pages. The existing all-page rasters and PDFs are under `Ignore/HtmlUnknownPageQualification/h10-nasa-whitespace-wrap-clean-cb18906c2/` and `h10-nasa-header-analysis-649ce7f0b/`.

An offline Chromium probe of the same archive at the recorded 816×900 viewport reports `#navbar_search_form` as `display:block`, `visibility:visible`, with a 281×40 CSS-pixel box. Direct tagged Chromium printing still extracts `Search...` from page 1 only. A normal-flow input control prints its placeholder. A separate four-page fixed-header control paints its form only on page 1 while the four body pages remain. These checks rule out a missing captured `@media print` selector as the explanation for the NASA difference. They do not establish a portable rule that every fixed form must be omitted on continuation pages; the surrounding fixed navbar text repeats in NASA.

The opt-in probe source and its small normal-flow and fixed controls remain under `Ignore/HtmlUnknownPageQualification/h10-nasa-header-search-probe-0c5c5b773/`. The duplicate 19 MiB NASA PDFs and generated probe binaries were removed after comparison. No product code or support claim changed. The search control remains an explicit visual difference between the browser print intent and OfficeIMO's print intent; suppressing it globally would need a separate browser-contract decision and adjacent fixed-content checks.
