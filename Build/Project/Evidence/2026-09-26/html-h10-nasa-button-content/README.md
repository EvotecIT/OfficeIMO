## Native system UI metrics prerequisite

At source `36ebe9646e043a92a8e0023bf72388215d20cb3b`, the new generic-name regressions fail in all three Drawing and all three PDF cases on macOS. They are retained with the probe outside the normal test build until the implementation is ready. The browser and a native CoreText UI-font probe both measure `Animation` at size 16 as 72.5625. CoreText identifies the same `/System/Library/Fonts/SFNS.ttf` program and selects optical size 17; the font file defaults to optical size 28. OfficeIMO measures the default instance at 67.8125 and its explicit optical-size-17 instance at 75.375.

Every glyph in that explicit instance advances 0.3125 farther than the native UI font. The SFNS normal tracking record has a value of -40 font units at size 16; scaling by 16/2048 gives -0.3125 per glyph and reproduces the native total exactly. Apple’s [tracking-table contract](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6trak.html) describes size-dependent adjustment to each glyph advance. This is evidence for an owned tracking and optical-size prerequisite, rather than a reason to apply a scene-width correction or switch the CSS family immediately. Measurement and paint must use the same instance and advances before the shared generic-family mapping is enabled.

The [native metrics record](system-ui-native-metrics.json) pins the font hash, per-glyph observations, table values and next requirements. Sources, native and browser reports, managed axis measurements, table metadata and the pending regression fixtures remain under `Ignore/HtmlUnknownPageQualification/h10-systemui-probe-36ebe9646/`. Product behavior is unchanged by this investigation; NASA font and layout qualification remains open.
