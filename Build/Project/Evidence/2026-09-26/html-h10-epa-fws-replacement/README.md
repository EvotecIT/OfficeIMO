## FWS: CSS scope and lossy WebP gaps

The FWS archive captured 46 resources and all 27 page images without a pending image. Offline Chromium prints seven pages and screen-media prints eight; PeachPDF prints seven. All OfficeIMO PDF intents stop at the default CSS rule limit (`actual=10001`, `limit=10000`). An exploratory replay with a 20,000-rule limit also stops at `actual=20001`; it was not adopted as a new untrusted-input policy. No OfficeIMO FWS PDF or six-target editable acceptance is claimed. The default bound remains unchanged.

At clean code head `52260adbb9bcb871db1988fb9d2755d70914a654` (unchanged renderer code through documentation head `d790d1f377556fcb3e1dfeaff30a705c1ef4a520`), an offline CSSOM probe found 12 readable stylesheets containing 24,007 style rules: 21,526 active in screen media and 21,521 active in print media. A simple comma-split selector count found 28,518 active print selectors; that count can overcount commas inside functional selectors and is not a parser acceptance metric. The 20,000-rule rejection therefore cannot be dismissed as a false cap merely from the page's visible size.

An explicit exploratory `MaxCssRules=40000` allows default print conversion without changing the untrusted profile. Two initial runs took 7.4–7.8 seconds inside the probe and allocated about 4.76 GB cumulatively; `/usr/bin/time -l` recorded maximum resident memory of 442,286,080 bytes on this Mac. A further diagnostic replay took 11.5 seconds and produced the same 1,847,721-byte PDF, SHA-256 `47bb5f6e1e671085bd67422f66719391a0afae372944be903bf451d016940d18`. These are exploratory single-machine observations, not a platform budget qualification.

OfficeIMO prints five pages against Chromium's seven. All five OfficeIMO and seven Chromium pages were inspected: the Florida salt marsh vole, alligator, bog turtle, brown pelican and bald eagle photographs are absent from OfficeIMO, while the later story-card photographs paint. Every missing photograph is present in the frozen archive as a 992-pixel responsive WebP resource. RIFF inspection identifies a lossy `VP8 ` chunk in each; none is lossless VP8L. At that initial replay, the shared managed decoder supported lossless VP8L only. The PDF report contains exactly five `HtmlPdfImagePayloadOmitted` warnings for these images, with omission loss, but its generic preparation message does not identify the codec limitation.

OfficeIMO.Core now owns the bounded opaque VP8 keyframe decoder. It is adapted from CodeGlyphX source `fc25e2fcf795d9c9a09b88708c47bdfeed5c446d`, with Apache-2.0 attribution and the relevant WebM license/patent notices included in the Core package. The port uses Core's portable byte view and reusable prediction buffers, enforces cancellation and aggregate decoded-buffer limits, and introduces no CodeGlyphX, ChartForgeX, libwebp or libvpx runtime dependency. The optional CodeGlyphX bridge remains for QR/barcode placement. Lossy WebP with separate alpha and animated WebP remain outside this owned decoder's supported subset.

The shared raster/PDF wiring applies container validation, resource limits, source dimensions and cancellation to built-in and caller codecs. Static-frame selection reports animation/page loss, including direct APNG and flattened drawing effects; missing-image placeholders remain outside source-pixel validation. No captured photographs were replaced with JPEG derivatives.

Independent Pillow/libwebp-produced solid-color, directional and odd-size fixtures validate reconstruction with mean channel error at most 1 and maximum error at most 3. The five archived photographs have native/managed mean RGBA errors of 0.0174–0.0391 and maximum error 1. The original repaired CodeGlyphX decoder and OfficeIMO's portable port produce identical decoded image hashes and byte-identical PDFs for all three archive intents. Print produces five pages, screen-media six, and snapshot six, with zero image-payload omissions. All-page contact sheets against the retained seven-page Chromium print reference show restored photographs but different image widths and section/page grouping. This is image restoration evidence, not unfamiliar-page fidelity acceptance.

A read-only review of the port found that exhausted arithmetic partitions could manufacture unlimited zero bits. Both owners now bound termination lookahead and reject further reads. Regression inputs cover a correctly sized container with an exhausted control partition and an independently produced image with intact control data but an exhausted coefficient partition. Native libwebp rejects both inputs. Core tests exercise direct decoding, shared decoding and content validation; targeted review confirms propagation across control, mode, coefficient, sign and extra-bit reads. [CodeGlyphX PR #248](https://github.com/EvotecIT/CodeGlyphX/pull/248) independently repairs that library's managed codec.

Operation-scoped selector projections reuse wrappers and attributes during one computed-style operation. A second operation creates a new cache and observes DOM attribute/order changes. A further provider-query optimization uses declaration metadata to avoid lookups that cannot produce a value and serializes each rule's CSS text once. The [qualification record](css-provider-query-qualification.json) pins functional source `8593e6acb696e1bbf6b93a9f473209194bcd6295`: conversion allocations fall from 4,576,477,744 to 3,261,235,688 bytes for print, from 4,823,793,496 to 3,506,488,288 for screen-media, and from 4,493,697,784 to 3,175,549,880 for snapshot. All three PDFs remain byte-identical, with no image omissions. HTML passes 3,553/3,553 on both .NET 8 and .NET 10, the portable build is clean, and exact-source H4 passes eight cases with all 13 print rasters byte-identical to the previously inspected baseline. These are allocation totals, not resident-memory measurements or accepted platform budgets.

A separate print probe records 30,506,448 allocated bytes for archive loading, 4,986,419,088 through PDF serialization including loading, and another 409,341,128 for readback and pixel-hash validation. Wall-clock measurements ran alongside builds and are unsuitable as acceptance timings. `PeakWorkingSet64` reports zero on this host, so peak resident memory is unavailable in this probe. The explicit 40,000-rule CSS cap remains exploratory. A default-resource qualification requires a measured CSS-scope decision, conversion-only budgets, and supported-platform resident-memory sampling.

## Archived fonts and variable instances

The [font audit](font-audit-qualification.json) pins functional source `33e30068863d1b457576c67b4575cef612cc3d9e`. All 12 archived WOFF2 payloads decode, and the print renderer registers 16 faces, including Source Sans Pro, Manrope, Merriweather and icon fonts. The PDF document-font policy controls installed-font lookup; it does not prevent these archived faces from loading. Unavailable-font warnings also include uncaptured sources and alternatives, so their count does not establish that the active text lacks an archived face.

The audit reproduces a variable-weight gap: registered Manrope weights use the font's default `wght=200`, and Merriweather uses `wght=300`. Explicit weight coordinates change measurements. At 44 CSS pixels, the probe text measures 539.528 pixels with default Manrope and 560.692 pixels at weight 400; Merriweather measures 583.198 pixels at its default and 610.060 pixels at weight 700 after the correction below. Mapping CSS weight to the selected variable instance remains open. These measurements identify a font-selection defect; they do not establish the contribution of that defect to every page difference.

The same probe exposed a shared variation-store failure. OpenType's complete `FFFF/FFFF` delta-set index means no variation data, but measurement rejected it as an invalid index. The evaluator now returns zero for that sentinel, including validation through GPOS, HVAR and MVAR consumers; partial sentinel pairs and invalid indexes still fail. The regression fails before the correction and passes afterward. Focused variable-font/kerning tests pass 50/50 and full Drawing tests pass 2,636/2,636 on .NET 8 and .NET 10; Core's netstandard2.0 build has no warnings or errors. Real archived Merriweather measurement now succeeds. The 79 rendered print text runs retain identical geometry, and exact-source H4 passes eight cases with all 13 PDF print and 13 display-list print rasters unchanged. This checkpoint does not close unfamiliar-page fidelity or resource budgets.
