## Flex pagination follow-up

The NASA print defect was partly caused by treating a tall flex row as an unbreakable block and by dropping the paged `body` flex layout. The renderer now derives row break opportunities from child blocks while respecting their line break constraints. It retains a simple paged flex-column body when no descendant requests a page transition and the first/left/right page geometry agrees. Bodies with authored breaks or named pages still take the existing child-block path; regressions cover direct and nested named pages, changed page geometry, a row gap adjacent to a forced break, and nested widows/orphans. The full .NET 10 HTML suite passed 3,254/3,254 and the H4 advanced held-out gate passed 8/8 on the candidate.

On the same frozen NASA archive, OfficeIMO print, screen-media pagination and screen-snapshot pagination each produced two pages; the pinned PeachPDF print lane produced three. First-page raster inspection shows the OfficeIMO title, overview and sidebar again, but the header still clips and the gallery cards and imagery remain absent or mispainted. The page-count change therefore does not establish visual equivalence with Chromium print (four pages) or general superiority to PeachPDF. This archive is a development case; a new predeclared held-out page, complete resource/loss accounting, whole-document visual checks and the editable targets are still required for H10 acceptance.

## TodoMVC text paint and line-height follow-up

The frozen TodoMVC print CSS uses `font-size: 100px` on the heading and inherits the body's `line-height: 1.4em`. Offline Chromium computes the heading line box at 19.6 CSS pixels, keeps its text above the input, and paints it with `rgba(175, 47, 47, .15)`. OfficeIMO had recalculated the inherited `em` value against the heading's 100-pixel font, painted the oversized glyph at the line-box origin, and discarded foreground alpha on the PDF text path. The static renderer now inherits the parent's computed length-based line height, keeps unitless multipliers relative to each child font, and centers oversized glyph paint around a short line box. The HTML-to-PDF adapter and shared PDF drawing writer retain foreground alpha.

On the unchanged archive, the zero-margin OfficeIMO print output now separates the heading from the input and retains both text markers. It still differs from Chromium in heading glyph metrics and placement; the placeholder remains dark and upright because its vendor placeholder pseudo style is not applied. The print, screen-media and snapshot routes each produce one page, as do Chromium and the pinned PeachPDF print routes. This is a fixed layout defect with a remaining typography/pseudo-style gap, not a claim of visual parity.

Independent review exposed two adjacent regressions before the checkpoint: expanded glyph paint could make short line boxes lose text at a page break, and an outlined font could apply foreground alpha twice. Fragmentation now uses the line's layout height separately from its paint height, and the PDF adapter applies an outer opacity group only to non-outlined text. Focused tests cover a four-line, two-page oversized heading and a translucent variable-font outline. The .NET 10 HTML suite passes 3,267/3,267, the focused PDF drawing tests pass 5/5, and the H4 advanced held-out gate passes 8/8. The final exact-head report is retained under `Ignore/HtmlUnknownPageQualification/h10-playwright-todomvc-leading-clean/`.

## NASA flex cascade and all-page replay

At source `4f6acdf9e`, the stylesheet fallback no longer lets a synthesized `flex` shorthand displace an authored inline `flex: none` when a rule declares only `flex-shrink: 0 !important`. The renderer also compares shorthand and longhand cascade priority and retains their authored order. Focused tests cover both important-declaration directions and both source orders. The full .NET 10 HTML suite passed 3,274/3,274; the H4 advanced held-out acceptance gate passed 8/8. A targeted independent review found no remaining actionable issue in this flex-priority slice.

The unchanged offline NASA archive completed every replay operation at this exact head with no execution failures. Chromium print has four pages; OfficeIMO print has twelve, screen-media pagination ten, and screen-snapshot pagination twelve. PeachPDF print has three. Every printed page was inspected from page rasters. OfficeIMO now flows the gallery cards in order instead of overlapping them, but keeps one card per row, carries the gallery across pages 2-11, and leaves page 12 nearly empty. Chromium print fits two gallery cards per row on its first page. The top navigation and logo remain clipped or incomplete in OfficeIMO. This is a material flow fix, not page-level visual equivalence.

The archive contains 24 MIME parts: one HTML page, three stylesheets, fifteen JPEGs, three PNGs and two SVGs. The OfficeIMO print report records 50 unavailable resource references: 39 gallery/media URLs, nine favicons and two icon-font URLs. The archived `HelioAware_Ep1_Thumb_v2.png` is truncated and cannot be decoded even though it is present; its omission is reported separately. Valid captured thumbnails appear in the output, while many later missing images are absent from the offline Chromium reference too. The report also contains five SVG-content warnings. A direct reader probe accepts the saved USA.gov logo, but rejects the saved NASA logo because its XML declares a DTD, which the bounded SVG reader prohibits. The resource warnings therefore mix capture omissions, one malformed saved image and renderer limits; their raw count is not a visible-content loss count.

Print layout needs a separate fit-width investigation. In the offline Chromium DOM with print media emulated, the gallery list is 520 CSS pixels wide at an 816-pixel viewport, so its 310-pixel cards form one column. At a 1,024-pixel viewport the list is 744 pixels wide and forms two columns. Chromium's A4 PDF nevertheless shows two columns. Separate PDF captures at browser viewport widths 600, 816, 1,024 and 1,200 all produced four pages with the same inspected first-page text coordinates. The PDF print layout in this runner is therefore independent of the browser viewport setting. Its observed card spacing is 160 PDF points for cards separated by 320 CSS pixels in the wide DOM, consistent with roughly two-thirds of the usual CSS-pixel-to-point scale; this does not establish the browser's exact fitting algorithm. The next renderer change must keep print layout width, physical page size and scale explicit, then compare every page again. The exact-head report and all-page contact sheets are under `Ignore/HtmlUnknownPageQualification/h10-nasa-flex-priority-4f6acdf9e/`.
